# 页面 PRD：两融交易咨询服务

**页面类型**：GWork 串联后的 PC Web 单客户服务工作台  
**页面目标**：在同一纵向服务清单内查看客户资料、信用账户资产、待处理任务和逐笔诊断方案，并完成服务记录上报。

## 1. 页面结构

1. 顶部：页面名称和本次咨询时间；不展示咨询来源选择、来源按钮或任务码状态。
2. 客户资料：不展示“客户信息”区块标题；直接展示客户姓名、姓名右侧“客户视图 >”跳转入口、脱敏资金账号、风险等级、掩码电话、电话外呼和服务状态。客户视图由正式宿主承接，静态原型点击后仅展示本地演示反馈。
3. 信用账户资产：信用账户总资产、净资产、总负债及数据时点。
4. 待处理任务：默认收起；展开后显示任务描述、必做/选做和截止时间。
5. 交易诊断：按操作时间倒序展示明细；每笔显示交易形式、委托代码、标的名称、诊断生成时间、个股诊断素材链接和复制入口，以及独立的五段诊断结果。
6. 底部固定区：本次服务记录文本框和完成服务按钮。

页面采用服务清单式纵向单列，不展示左侧客户列表或诊断侧栏，不提供企微单聊、企微群发或刷新按钮。保持白底、浅灰页面底色、蓝色强调和附件中客户资料横向分组的视觉语言。

## 2. 交互状态

| 状态 | 进入方式 | 页面表现 |
|---|---|---|
| 上游承接完成 | 专用账号/任务码页面和串联流程处理完成 | 服务页仅接收客户、任务、交易明细和诊断结果，不展示资金账号录入或任务码状态 |
| 明细切换 | 点击交易明细 | 同步切换该笔交易信息、个股诊断入口和五段诊断内容 |
| 暂未识别 | 上游返回未得出诊断的明细 | 展示“暂未识别原因，请通过人工渠道核实”，不在本页发起重查、截图上传或人工补录 |
| 完成服务 | 点击完成服务并确认 | 沿用现有投顾线服务上报逻辑；无诊断结果也允许完成 |

## 3. 五段服务方案

原子 Skill 返回并按业务已整理内容展示：原因定位、数据说明、解决路径、风险提示、服务建议。每笔明细分别展示五个模块，每个模块支持单独复制，完整方案支持整体复制；数据说明中的账户数值、委托数量等字段由系统自动填充，缺失时显示“数据暂不可用”，不得由员工或模型臆造。

### 首期标准服务方案示例

以下为“可用保证金不足”错误场景的已确认展示内容。生产环境由原子 Skill 按错误场景返回对应内容；`XX` 位置由接口数据自动填充。

原型为便于演示，将上述两个数据变量显示为示例值“426,000元”和“568,000元”；生产环境不得使用该固定示例值。

**原因定位**

您好，您当前无法融资买入更多数量标的证券，原因是信用账户“可用保证金不足”。融资买入的核心机制是：您需要以账户中的现金和证券经折算后作为保证金，向券商借入资金买入证券。可用保证金 = 您账户的总保证金 − 已被占用的保证金。只有可用保证金 ≥ 本次委托所需保证金时，才能成功进行委托。可用保证金 =（现金 × 100%）+（担保证券市值 × 各证券折算率）− 已占用保证金，其中，现金折算率最高（通常为100%），股票和ETF按我司核定的折算率计算，不同证券差异较大。

**数据说明**

您当前信用账户可用保证金是XX元，而本次委托所需要的保证金是XX元，不足以覆盖本次委托所需，因此系统拒绝了该笔融资买入。

**解决路径**

如果您想增加可用保证金，主要有以下方式：
①银证转账：转入现金，现金折算率通常为100%，是提升可用保证金最快的方式。
② 担保品划转：从普通账户划入高折算率证券（如ETF折算率最高可达90%）至信用账户。
③ 优化担保品结构：将当前持仓中折算率较低的证券替换为折算率更高的证券，同等市值释放更多保证金。
④ 归还部分负债：还款还券可释放已占用的保证金，同时降低负债压力。
如您不计划增加可用保证金，也可以适当降低委托金额，将本次融资买入金额降至可用保证金可覆盖的范围，分批建仓。

**风险提示**

持仓证券的折算率会动态调整，若被调低，可用保证金将被动收缩，极端情况下可能无法继续融资融券，请密切关注持仓证券的折算率变化。

**服务建议**

融资买入涉及保证金折算、维保比例、集中度等多重约束，账户操作逻辑比普通账户复杂得多。如果您希望我帮您做一次全面的账户诊断——包括保证金计算分析、担保品结构优化建议等，我可以帮您梳理，后续我们再详细沟通。

## 4. 验收标准

- 页面标题、原型文件名和交付中心入口统一为“两融交易咨询服务”。
- 页面没有左侧客户列表或诊断侧栏，客户资料、资产、任务、逐笔诊断按纵向单列布局展示；客户卡片不展示“客户信息”标题，客户姓名右侧展示“客户视图 >”入口。
- 页面不展示、检测或处理任务码有效性、过期状态和重新查询；该职责由专门页面承担。
- 页面不模拟浏览器与 GWork 的跳转或消息交互；客户视图、电话外呼与完成服务由正式宿主能力接入，静态原型只展示“演示已触发、正式动作由宿主承接”的本地反馈。
- 资产包含信用账户总资产、净资产、总负债；任务默认收起，展开可见任务描述、必做/选做与截止时间。
- 多笔明细按操作时间倒序展示，可切换查看，诊断方案不合并。
- 个股诊断入口可打开并支持复制链接；五个服务方案模块分别支持复制。
- 底部服务记录输入框固定展示，未得出诊断结果仍可完成服务；回流逻辑不变。
