## 1. 页面定位

### 1.1 核心目标

为客户经理提供一张已生成完成的高净值客户资产降级服务清单。员工按当前降级后的资产档位筛选客户，在右侧查看 AI+服务清单同款客户基础信息，以及降级场景专属客户画像、原因判断、沟通思路和服务话术，完成回访、诊断、资金转出原因了解与服务记录。

### 1.2 入口来源

- 员工消息盒子中的每日 15:30 自动任务入口。
- WorkBuddy 自由圈客入口。
- WorkBuddy 直接生成“高净值客户资产降级服务清单”入口。

### 1.3 页面边界

- 复用 AI+服务清单的视觉、客户基础信息、ISMP 待处理任务、姓名/资金账号搜索、电话外呼、企微群发和完成服务交互。
- 本页不展示信件、权益清单、资产配置一页通等升级场景沟通素材。
- 本页不展示资产升级场景的信件、权益清单和配置一页通；大 C 方案素材只在主动资产配置引导中由投顾手动选择。

### 模块 M6：降级客户画像

#### M6-A 资产概览

- 近20日日均净资产。
- 当前资产等级：由 `{降级前档位}` 降至 `{当前档位}`。
- 跃迁判断：近20日日均净资产对比昨日数据。
- 原因判断：由近1月、近3月、近6月三个周期的账户盈亏和净资金转出数据实时计算，展示亏损主导 / 资金转出主导 / 混合原因 / 原因不明及逐周期判断依据。
- 判断说明：账户盈亏为负数时取绝对值作为亏损额，盈亏为0或正数时亏损额按0；净资金转出为正向金额，净流入或无转出时按0。不得把缺失或接口失败值当作0。

#### M6-A1 原因判断算法（研发口径）

| 步骤 | 规则 |
| --- | --- |
| 周期取值 | 分别处理近1个月、近3个月、近6个月；同一周期账户盈亏或净资金转出任一缺失、不可解析或取数失败，该周期无效，不参与投票。 |
| 金额归一 | `loss = max(0, -accountProfitLoss)`；`outflow = max(0, netCashFlowOut)`。净流入须按资金数据源的正负方向识别后归一为0。 |
| 单周期投票 | 若 `loss > 0` 或 `outflow > 0` 且 `loss >= outflow * 1.5`，投“亏损主导”一票；否则若 `outflow > 0` 或 `loss > 0` 且 `outflow >= loss * 1.5`，投“资金转出主导”一票；两项均为0或均未达到对方1.5倍时不投主导票。边界值1.5倍计入主导。 |
| 跨周期归类 | 有效周期数少于2，归“原因不明”；否则亏损票数≥2归“亏损主导”，资金转出票数≥2归“资金转出主导”；有效周期数≥2但两类均不足2票，归“混合原因”。 |
| 展示依据 | 逐周期展示“亏损主导”“资金转出主导”“未达阈值，无主导票”或“数据不足”；同时展示有效周期数和两类票数，供员工理解最终标签。 |

实现应以未舍入的原始金额判断，只在界面展示时格式化金额。金额为0是有效数值，不等同于缺失值；单周期双方均为0不投票。

#### M6-B 账户盈亏与净资金转出

独立展示三行周期数据，避免汇总为一句话：

| 周期 | 账户盈亏 | 净资金转出 |
| --- | --- | --- |
| 近1个月 | 金额及正负状态 | 金额及正负状态 |
| 近3个月 | 金额及正负状态 | 金额及正负状态 |
| 近6个月 | 金额及正负状态 | 金额及正负状态 |

账户盈亏数据沿用 AI+助手口径；净资金转出按照本场景资金数据口径展示。

#### M6-C 持仓结构与行业集中度

标题下方展示“数据口径与 AI+助手保持一致”。采用“行业汇总 + 可展开标的明细”的分层表格：

- 行业汇总：行业名称、持仓、市值占比、收益额。
- 行业明细：标的名称、市值&仓位、收益额、持有天数。
- 展示前三大行业占比合计及“是否超过60%”提示，用于支持板块集中度筛查。

#### M6-D 历史触达记录

- 最近有效沟通日期。
- 近6月有效沟通次数：直接取数仓已有字段并展示。
- 近6月有效交互天数：直接取数仓已有字段并展示。
- 三项指标分别取数、分别展示；数据缺失时显示“--”，不由页面或大模型推算。该展示不改变近 90 天排序和防重规则。

### 模块 M7：沟通思路

- 按当前客户降级路径展示对应的一整套业务示例，固定包含【亏损场景】【资金转出场景】【混合原因】【主动资产配置引导】四部分；不因系统原因判断隐藏任一部分。
- `1000万以上 → 500–1000万`：展示业务提供的千万级客户亏损、资金转出（含“转去别家 / 企业经营周转”应答）和大C方案 / 目标权重再平衡示例。
- `500–1000万 → 300–500万`：展示业务提供的亏损、资金转出（含“转去银行 / 买房 / 还贷”“更好的产品”应答）和大C方案 / 资配建议书示例。
- 前两条路径均展示与该降级路径对应的【混合原因】完整原文；其中千万级示例包含持仓风险梳理和资金安排了解，中间档示例包含行业集中度筛查、资金规划了解。
- `300–500万 → 300万以下`：展示业务提供的亏损（含客户沉默 / 敷衍应答）、资金转出（含“转走了”“生活开支”应答）、混合原因和轻量资产配置引导示例；亏损场景正文使用最新提供的“持仓赛道与概念、产业逻辑梳理”版本，不再使用旧“账户清扫 / 退市风险”版本。
- 三条降级路径均展示业务提供的【混合原因】完整原文，分别使用对应层级的示例，不跨层级复用或由模型补写。
- 示例内容逐段按业务提供的完整原文展示，不由大模型总结、改写、补充或删减；思路正文仅供投顾准备沟通，不进入企微群发或一键复制内容。大 C 方案素材是独立客户素材，不属于沟通思路正文。
- 每条路径四个场景均为独立折叠段，顺序为【亏损场景】、【资金转出场景】、【混合原因】、【主动资产配置引导】；默认仅展开【亏损场景】，支持“全部展开 / 全部收起”和单独展开或收起。
- 在包含“基于客户 KYC 情况匹配不同大 C 方案沟通”的主动配置引导中显示素材入口；档位匹配由投顾基于实际沟通判断，不由系统读取 KYC 自动选择。
- 五档方案为低波动、中低波动、中波动、中高波动、高波动；方案图文暂用 PNG 占位，不生成、不改写方案正文。
- 素材面板以右侧抽屉展示，入口不直接展开五档内容，避免沟通思路步骤过长。各档支持多选、预览长图和下载；预览长图单独打开预览弹窗，不在方案列表下方展开。首次打开全部不选，取消不保存，确认后保留当前客户选择。
- 确认的素材摘要展示在服务话术上方，随本客户服务话术进入触达；未选素材时仍可只发送话术。

### 模块 M8：服务话术

- 按降级路径、原因判断和客户画像生成摘要式对客话术：亏损主导使用对应路径【亏损场景】示例；资金转出主导使用【资金转出场景】示例；混合原因使用该路径专属【混合原因】示例；原因不明使用中性服务回访话术，不猜测原因。
- 混合原因话术需同时覆盖持仓波动/结构梳理与资金安排/服务衔接的了解方向，但不得向客户透露系统判定为“混合原因”。客户应答分支仅供员工在客户实际表达相应情况后参考，不得预先假设客户应答并写入首次触达话术。
- 主动资产配置引导仅在客户表达意愿后作为后续沟通参照，不默认进入首次生成话术。
- 个性化话术默认引用 1 个、最多引用 2 个有效画像切入点。有效画像切入点须同时满足：与当前降级原因或服务动作直接相关；数据完整、可信且为本次清单有效期内的结果；能够自然引出回访、账户诊断、资金转出原因了解或服务引入；对客表达可转换为“当前持仓结构”“账户情况”“资金安排”等中性表述。
- 优先选择规则：亏损主导优先选择账户盈亏变化、行业/产品集中度或风险承受与操作风格；资金转出主导优先选择净资金转出趋势、留存持仓结构或待处理的资金安排任务；混合原因优先选择账户盈亏与净资金转出中数据更完整的一个方向，再搭配持仓结构或服务记录；原因不明仅使用持仓结构、服务记录或待处理任务，不引用缺失的原因数据。
- 有效画像切入点示例：账户盈亏变化 + 行业集中度，用于引出账户诊断；资金安排趋势 + 留存持仓结构，用于了解转出原因并做好服务衔接；风险承受与操作风格 + 持仓结构，用于引出风险匹配复盘。
- 不得把多个字段逐项罗列成客户画像摘要，不得提及具体资产金额、资产降级、系统判断、内部模型或缺失数据；当没有满足条件的有效切入点时，使用不引用画像数据的通用回访话术。

#### M8-A 话术生成约束细则（研发实现依据）

| 规则项 | 实现要求 |
| --- | --- |
| 选取数量 | 默认选取 1 个有效画像切入点；仅在两个切入点均与本次服务动作直接相关且不会造成内容堆砌时，最多选取 2 个。禁止选取 3 个及以上。 |
| 有效判定 | 字段必须有值、数据源返回成功、处于本次清单有效期内；同时须与当前原因判断或拟执行服务动作相关，并可转换为不暴露具体金额和内部判断的中性对客表达。 |
| 原因与字段映射 | 亏损主导：账户盈亏、行业/产品集中度、风险承受与操作风格；资金转出主导：净资金转出趋势、留存持仓结构、资金安排待办；混合原因：以对应路径【混合原因】沟通思路为话术结构参照，优先使用数据更完整且与回访相关的账户盈亏或资金安排切入点，再辅以持仓结构或服务记录；原因不明：只可使用持仓结构、服务记录、待处理任务，禁止使用缺失的盈亏/资金字段。 |
| 无可用切入点 | 生成不引用画像数据的通用服务回访话术；不得因画像缺失而补写或猜测客户情况。 |
| 输出限制 | 禁止逐项罗列画像字段、具体资产金额、资产降级、系统判断、内部模型和缺失数据；输出应服务于本次回访、诊断、资金转出原因了解或服务引入。 |
- 展示“合规审核通过”和“人工未编辑/人工已编辑”状态。
- 话术文本直接可编辑，失焦保存，不新增独立编辑按钮，不触发二次合规审核。
- 一键复制只复制对客话术，不复制内部沟通思路。
- 方案素材不拼接到话术文本或复制到剪贴板；通过单聊/群发的素材附件形式发送。

### 模块 M9：服务操作

- 服务内容记录输入框；点击“完成服务”即写入当前场景已联系记录。
- 电话外呼、企微单聊、企微群发沿用 AI+服务清单交互。
- 完成服务后记录场景 ID、客户 ID、降级路径、原因判断、触达渠道、服务内容和完成时间；客户置灰并移至列表底部。

## 4. 交互逻辑

1. 进入清单即视为清单生成完成，不展示生成进度；一次跨越两个及以上档位的客户同样纳入清单，其沟通思路、服务话术和群发分组按降级后的当前资产层级对应路径服务。
2. 左侧资产筛选只展示当前降级后的资产档位：500–1000万、300–500万、300万以下；其下方以收起式单行入口展示资产降级原因判断筛选，点击下拉展开全部、亏损主导、资金转出主导、混合原因、原因不明。资产降级原因判断标题旁的说明图标点击后以气泡展示 1.5 倍阈值、三周期多数归类、混合原因和原因不明的判断逻辑；点击气泡外区域收起。两组筛选默认均选择“全部”，与姓名/资金账号搜索叠加取交集。
3. 选中客户后，右侧所有数据均切换为该客户的降级画像；不保留升级场景的交易次数、权益素材等模块。
4. 企微群发弹框与客户详情已确认素材及右侧服务话术保持同源：千人一面按相同降级路径、相同资产降级原因判断、相同素材组合分组，使用组级摘要话术且不得混入单个客户画像；千人千面逐客户展示话术并允许调整各自五档素材组合；无素材时允许仅发送话术。企微返回“发送客户成功”回执后，记录客户、素材 ID 列表、渠道、时间及发送结果并写入防重标记。
5. 原因判断采用已确认的单周期1.5倍阈值、至少2个有效周期和“三周期中同一方向至少2票”的归类规则；单周期不满足阈值不投票，有效周期不足2个归原因不明。
