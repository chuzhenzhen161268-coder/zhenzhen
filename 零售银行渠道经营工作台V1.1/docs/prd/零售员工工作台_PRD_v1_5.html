第 2 章：项目背景与目标

2.1 背景

为解决银行渠道精耕过程中，员工经营渠道相关数据和功能入口分散的问题，规划建设「零售员工端渠道经营视图」，作为年度零售渠道数字化经营建设的重点方向。经过多轮迭代，当前版本（HTML v8）已在首版 PRD 基础上扩展了多项核心能力，本文档作为现阶段实现状态的完整归档与迭代依据。

2.2 核心目标

  • 聚合化：实现渠道经营数据与过程数据的统一呈现，5 大模块单页直达，减少跨系统操作切换耗时 60% 以上。
  • 标准化：规范渠道拜访、需求采集与跟进的标准化作业流程（GPS 打卡 + 选择题表单），拜访记录完成率提升至 90%。
  • 赋能化：集成知识库（展业资料 + 优秀案例）与工具库，员工获取展业参考资料的平均时长压缩至 30 秒内。
  • 闭环化：异动提醒 → 拜访行动 → 需求跟进 → 上报协同，形成完整业务闭环，紧急需求当日响应率达 95%。

2.3 非目标（本版本不解决）

  • 团队长汇总视图（团队维度数据汇总）
  • 渠道星级自动评级算法（本版展示数仓同步结果）
  • 知识库后台内容管理（后台 CMS 另立项）
  • 离线模式（弱网兜底）

2026-06-30（H5 移动端）

核心使用场景

场景 1：外勤拜访打卡 背景：员工到达银行网点后需完成打卡并记录拜访内容。 操作路径：首页「渠道拜访」模块 → 点击「我要拜访·立即打卡」→ 在打卡页内联的网点选择区（输入框 + 「附近网点」/「搜索结果」）点选网点，或输入未录入网点名称（点「立即打卡」后二次确认）→ 点击打卡并同步采集经纬度信息（采集失败不阻断）→ 选择「立即填写」或「稍后补充」→ 完成拜访表单提交。 期望结果：拜访记录保存，记录打卡地点、打卡时间、经纬度采集结果和采集状态，日历打点更新，需求自动流入需求跟进表。

场景 2：查看渠道异动 背景：员工上班首先查看当日有无需要重点关注的渠道异动。 操作路径：首页「重点关注」模块 → 查看重点关注摘要 → 点击「查看全部」进入全部异动列表 → 点击网点降级/未拜访/生日提醒进入 H5 消息详情页，点击需求未满足进入 H5 需求详情页。 期望结果：员工快速了解渠道风险点和待跟进需求；消息盒子下发类消息查看详情后从当前列表消失，需求未满足事项按需求状态持续展示或停止展示。

场景 3：渠道建联信息管理 背景：员工需要查阅或更新某网点的关键人信息。 操作路径：「我的渠道」→ 网点模糊搜索选择具体网点 → 查看建码卡片（关键人、生日、联系方式）→ 点击「编辑」→ Bottom Sheet 中增删改关键人信息（含生日）→ 保存。 期望结果：建联信息实时更新，关键人生日提醒自动展示。

场景 4：需求跟进与上报 背景：员工在拜访后收到紧急需求，需要录入并跟进。 操作路径：拜访表单填写银行需求挖掘 → 需求是否满足选择“未满足”或“无法满足” → 按页面条件填写紧急程度与解决方案 → 提交 → 符合上报条件时系统自动推送企微消息至团队长 → 后续在「需求跟进表」中编辑解决方案并更新状态。 期望结果：紧急需求自动触达团队长，需求全生命周期可追踪。

场景 5：知识库检索 背景：员工在拜访中遇到银行方的具体需求，需要快速匹配解决方案。 操作路径：拜访表单“银行需求挖掘”模块点击「AI问案例」→ 输入关键词 → 匹配知识库案例/SOP → 引用到解决方案备注。 期望结果：快速获得可操作的解决方案参考，降低员工思考成本。

第 5 章：页面详细说明

5.1 主页面（首页）

1. 页面定位

工作台核心承载页，汇聚5大功能模块于单一滚动视图，通过固定顶部 Tab 锚点导航实现快速定位。

2. 页面入口

  • 应用启动默认进入（唯一主入口）

3. 页面目标

  • 让员工在一个页面内完成日常经营所需的信息查阅与核心操作触达，无需跳出工作台框架。

4. 页面模块说明

4.1 顶部 Header 模块作用：展示工作台名称。 展示内容：页面标题“零售银行渠道经营工作台”。员工版不展示员工头像、姓名及右侧角色切换按钮，不提供员工版/团队长版切换入口。 交互说明：无。

4.2 顶部 Tab 导航（qnav） 模块作用：5大模块的快捷锚点导航 展示内容：重点关注 / 我的渠道 / 渠道拜访 / 知识库 / 工具库 交互说明：点击 Tab 平滑滚动至对应模块，当前 Tab 高亮（蓝色下划线）；页面滚动时联动高亮（含滚动锁机制：点击后 1.5s 内禁止滚动触发高亮变化）；滚动到底部时固定高亮最后一个 Tab。支持鼠标横向拖拽和移动端横向滑动，右侧使用渐隐遮罩提示仍有内容；拖动结束不得误触导航项。 备注：Tab 可横向滚动，超出宽度时隐藏滚动条。

4.3 【重点关注】模块

模块作用：聚合展示当前员工需要优先查看的渠道经营事项，帮助员工识别风险、查看消息详情或进入需求详情继续跟进。 展示内容：模块标题 + 「查看全部 ›」入口；重点关注摘要列表（折叠态默认显示前3条）；展开/收起切换按钮。本期展示 4 类事项：网点降级、未拜访提醒、生日提醒、需求未满足。

5.4 二级页面：我要拜访（MVP打卡 + 经纬度采集 + 拜访表单）

1. 页面定位

外勤打卡与拜访记录的核心操作页，MVP 阶段保留现有前端交互和功能流程，点击打卡时尽量采集经纬度、定位精度和采集状态；定位失败不阻断员工继续选择拜访网点。

2. 页面入口

  • 首页「我要拜访·立即打卡」按钮
  • 待补充横幅「去补充」按钮（直接跳至表单）

3. 页面目标

  • 让员工在2分钟内完成打卡+拜访记录全流程。
  • MVP 阶段解决“可记录、可追溯、不中断”的问题：记录员工主动打卡时间、选择的拜访网点、可采集到的经纬度信息和采集状态；定位失败或授权失败不阻断打卡。

4. 页面模块说明

4.1 打卡位置区（MVP 方案）

状态 触发时机 展示内容 用户操作
默认态 进入我要拜访页 当前GPS定位卡片、网点选择区（输入框 + 「附近网点」按 GPS 距离升序取前 4，行带归属标签与 ≈xxm） 直接点选附近网点，或输入关键字搜索全部已录入网点
经纬度采集成功 浏览器/企微容器返回坐标 地图、经纬度、定位精度、采集时间、附近网点列表 可复制坐标，可继续打卡；
经纬度采集失败 权限拒绝、容器限制、超时或环境不支持 展示「暂未获取GPS定位」和采集失败状态 选择拜访网点后继续打卡
网点搜索与未匹配 在网点选择区输入关键字 标题切为「搜索结果」：全部已录入网点、本人名下优先、行带归属标签（有距离数据时含距离）；无命中时仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」、不展示网点行 点选任一结果行即选中并收起；无命中时点「立即打卡」弹出「确认拜访该网点？」二次确认；

MVP 打卡判定：员工选择拜访网点后，点击「立即打卡」即生成打卡记录。若可获取经纬度，则随记录提交；若无法获取，则记录 gpsStatus = failed / denied / unsupported / timeout，不阻断提交。

打卡网点选择：打卡地点在打卡页页内选择、不使用弹层——「选择拜访网点」处即为输入框，未输入时其下方直接按 GPS 距离升序列出「附近网点」（网点名 + 归属标签 + ≈xxm）；输入关键字后列表标题切为「搜索结果」（命中全部已录入网点、本人名下优先、行带归属标签与距离）；关键字未匹配到任何已录入网点时结果区仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」。点选任一结果行 → 区域收起为已选态（网点名 + 归属标签 + 清除），点击已选区域可再次展开改选；点「清除」回到未选态。点「立即打卡」：列表已选网点直接生成凭证；未录入网点（手输未匹配）弹出居中二次确认「确认拜访该网点？」（含所输名称、「确认打卡／取消」；取消后关闭弹窗、停留打卡页并保留输入）；未选且输入为空时 Toast「请先选择拜访网点」，不生成凭证。不再有"名称比对系统网点"式校验，可拜访非本人名下网点（行内以灰色「非本人名下」标签标识）。

4.2 打卡确认区 展示内容：地图、定位精度圆、当前经纬度、定位精度、采集时间和附近网点列表。员工在打卡页内联网点选择区点选网点（默认「附近网点」按距离升序、输入关键字切「搜索结果」，行带「本人名下 / 非本人名下」标签与距离，本人名下优先）；关键字无匹配时以所输名称作为未录入网点。 交互：点选任一网点行后区域收起为已选态，点击「立即打卡」直接进入成功确认区；未录入网点（手输未匹配）点「立即打卡」时弹出居中二次确认「确认拜访该网点？」，点「确认打卡」后以所输名称（无归属标签）进入成功确认区；未选且输入为空时 Toast「请先选择拜访网点」，不得生成打卡凭证。

4.3 打卡成功确认区 蓝色信息卡展示“打卡成功”、地点和完整时间，并列展示两个操作卡： “立即填写 / 趁热打铁，一次完成”→ 页面平滑滚动至拜访表单区域 “稍后填写 / 生成待补充记录”→ 生成待补充记录，关闭二级页面，首页显示横幅。

4.4 拜访表单（6个模块）

题号 题目 题型 选项
Q1 拜访对象 多选 / 手输 该打卡网点的关键人多选，选项呈现为「职位 + 姓名」（如「理财经理 王芳」）；已录入网点（不论本人名下 / 非本人名下）只可勾选、不可在表单内新增关键人；网点无关键人时展示空态提示（本人名下指向「我的渠道」维护 / 非本人名下仅提示）、不展示「其他」按钮、直接展示拜访对象输入框、该模块为必填（自由文本，为空则拦截提交并在该模块描红提示「必填未完成」）；当打卡网点为未录入网点（手输未匹配）时，改为展示空态说明 + 自由文本输入（就地手输拜访对象，输入非空即满足必填），同样不展示任何补录入入口；已录入网点在有关键人时于关键人选项外附「其他」按钮（点选展开文本框输入拜访对象自由文本，仅记为本次记录、不写入关键人档案），无关键人时不展示该按钮

Q3 达成合作内容 多选（选填） 客户线索/资源互换/活动开展/晨夕会宣导/关键人开户/其他；

自动触发规则：需求结果为未满足或无法满足时显示紧急程度和解决方案；满足条件的未满足需求提交后生成 Demand 记录并进入需求跟进，可在重点关注“需求未满足”中展示。隐藏字段不参与必填校验。

Q1 拜访对象·关键人来源：Q1 对象来源由静态角色枚举改为该打卡网点已录入的关键人（职位 + 姓名，多选）。已录入网点（不论本人名下 / 非本人名下）一律不可在拜访表单内新增关键人——Q1 只可勾选该网点已录关键人，关键人的增 / 改 / 删统一由「我的渠道 → 编辑建码信息」维护（仅本人名下网点开放，按「职位 + 姓名」去重）。Q1「其他」按钮：该网点有关键人时，已录入网点的 Q1 在关键人选项外附「其他」按钮，点选后展开文本框，员工可输入拜访对象信息（提示「请输入拜访对象信息（职位+姓名，多人可用顿号分隔）」）；该文本仅写入本次拜访记录快照、不产生关键人档案新增 / 变更，与勾选关键人并存时按顿号合并展示；该网点无关键人时不展示该按钮、直接展示拜访对象输入框；未录入（手输）网点不展示该按钮。网点无关键人时，Q1 展示空态提示「该网点暂无关键人，可前往『我的渠道』编辑建码信息补充」（非本人名下网点仅提示「该网点暂无关键人」），不展示「其他」按钮、直接展示拜访对象输入框（自由文本），因无可勾选项，该模块为必填（自由文本，为空则拦截提交并在该模块描红提示「必填未完成」）。提交时以快照固化本次拜访对象，关键人后续被删除 / 更名不影响已提交记录；存量历史记录保持原文本展示。当打卡网点为未录入网点（手输未匹配、无关键人档案）时：Q1 不展示关键人多选，改为展示空态说明「该网点未录入系统，请直接填写拜访对象」+ 自由文本输入框，输入非空即满足 Q1 必填。标题提示文案统一：Q1 标题「拜访对象」后的提示统一为「（可拜访多个对象）」，有关键人 / 无关键人 / 未录入手输三种状态一致；该文案同时适用于关键人多选与自由文本输入（文本态多人以顿号分隔）。

Q2 银行需求挖掘·两级分类选择器：「银行需求挖掘」由 10 项平铺 chip 改为两级分类选择——一级为需求维度（职业需求 / 社会需求 / 个人需求），三个大类直接常驻平铺在表单卡片内作为分组容器（非互斥；点击任一大类标题即拉起该类选择弹层，已选需求按所属大类归位展示在对应分组块下，不设「＋ 添加需求」按钮）；二级为该维度下的需求指标（源自《渠道信任经营 · 需求库速查（三维度）》46 项，按展示分组铺开、★常用项置前）。选择器为半屏、只显示所点大类：顶部搜索框在当前大类内匹配（不跨大类），底部为「已选摘要 + 确定（已选 N 项）」（空选置灰）；勾选某项后该项下方即时出现「描述（选填）」输入框；库中无对应项时走「＋ 手工补充」，自动挂靠当前大类、grp 记为"自定义"、打「自定义」标识（同大类重名或输入为空分别给 Toast）。表单卡片内，三个大类各为一块浅灰底圆角分组卡片（组头＝维度色圆点 + 大类名 + 「N 项」计数胶囊 + 右侧「＋ 添加」小按钮，未选时隐藏计数胶囊、按钮降级为灰色描边；组间留白分隔），已选需求按大类归入对应卡片（标签带维度色与「自定义」标识、可单个删除）；每个标签下方的描述：有内容时直接显示带内容的描边输入框，为空时收起为浅色「＋ 描述（选填）」入口、点击展开为输入框，可就地在卡片内填写 / 修改该需求的描述，与弹层内同项描述为同一份数据、双向同步。维度三色规范：职业需求 #2B73FF（蓝）/ 社会需求 #8257E6（浅紫）/ 个人需求 #12A870（浅绿）。弹层内选项的选中态（边框 + 文字 + 底色）按当前大类取对应色。必填规则：仅要求至少选 1 项需求；「需求描述」为每个已选需求标签各自的选填描述（校验未通过时模块卡片描红、聚焦并 Toast，选择需求后自动清除错误态）。修改态（拜访记录编辑）复用同一控件，已选需求及其描述按快照回显。存量历史记录保持原文本展示、不追溯改写，统计端归入「未分类」。

4.5 编辑态：修改拜访记录 由「拜访详情」页点「修改」进入，复用同一套拜访表单：标题由「我要拜访」改为「修改拜访记录」；打卡凭证区（打卡网点 / 地点、打卡时间）只读展示、不可修改；6 个模块字段全部预填原记录值且可修改，条件必填与校验口径与新建一致，Q1 呈现复用同一套关键人多选规则（历史已固化的对象按快照回显）；底部操作由「放弃 / 提交完整记录」变为「取消 / 保存修改」；校验通过后覆盖原记录并返回详情页展示更新后内容，历史列表该行同步刷新。

5. 页面交互流程

流程 1：MVP 打卡并立即填写 进入页面 → 选择拜访网点 → H5 尝试采集定位结果 → 点击「立即打卡」→ 打卡成功 → 选择「立即填写」→ 完成6模块条件表单 → 点击「提交完整记录」→ Toast 反馈 → 关闭二级页面。

流程 2：经纬度采集失败仍打卡 进入页面 → 经纬度采集失败或未授权 → 选择拜访网点 → 点击「立即打卡」→ 生成无GPS坐标打卡记录，记录 gpsStatus → 继续填写或稍后补充。

流程 3：稍后补充 打卡成功 → 点击「稍后填写」→ 首页展示待补充横幅 → 点击「去补充」→ 恢复打卡记录并展示拜访表单。

流程 4：修改拜访记录 历史拜访记录 → 打开一条拜访记录详情 → 点右上「修改」→ 编辑态（字段预填、打卡凭证只读）→ 修改 / 补齐字段 → 点「保存修改」→ 校验通过后覆盖原记录 → 返回详情页展示更新后内容，历史列表该行同步刷新。

10. 最终补充规则：全局待补充记录与提交校验

  1. 打卡成功后仅生成“打卡凭证 / 待补充记录”，不生成正式拜访记录；该记录只表示员工已到访或已发起拜访动作，仍需补全表单。
  2. 只有员工完成并提交完整拜访表单后，系统才生成正式拜访记录；正式拜访记录才进入历史拜访记录列表、日历记录、拜访详情页和后续统计。
  3. 仅打卡但未填表单的记录不得出现在历史拜访记录列表中，也不得计入“已完成拜访记录”统计；只能出现在【渠道拜访】模块顶部的待补充队列中。
  4. 待补充记录为全局队列，不按日历选中日期过滤；只要员工存在未补完整表单的打卡凭证，即在【渠道拜访】模块顶部展示。
  5. 待补充记录按打卡日期时间倒序排列，最新一条默认展示在顶部；时间展示格式为 YYYY/MM/DD 与 HH:mm:ss。
  6. 收起态只展示最新一条待补充记录；当存在 2 条及以上时，卡片底边中间展示向下小三角，点击后展开全部待补充记录。
  7. 展开态展示全部待补充记录，每条记录样式一致：第一行 YYYY/MM/DD 拜访记录待补充，第二行 银行名称 · HH:mm:ss，右侧为 去补充 按钮。
  8. 展开态底边中间展示向上小三角，点击后收起；小三角为浮层控件，不占用独立内容行。
  9. 点击任一待补充记录的 去补充，进入该打卡凭证对应的拜访表单；提交完成后从全局待补充队列移除该条记录，并生成正式拜访记录。
  10. 拜访记录表单包含 6 个模块：拜访对象、银行需求挖掘、达成合作内容、需求是否满足、需求是否紧急、其他拜访信息。拜访对象、银行需求挖掘、需求是否满足必填（其中「银行需求挖掘」需至少选 1 项需求、「需求描述」为每个已选需求标签各自的选填描述）；达成合作内容和其他拜访信息选填；需求是否紧急及解决方案按满足状态条件展示并在显示时必填。
  11. 若任一当前可见的必填模块未完成，点击 提交完整记录 时阻止提交；未完成模块显示红色描边与“必填未完成”，同时 Toast 请完善相关信息。隐藏字段不参与校验。
  12. 若第 1、2、3 项选择 其他，对应备注输入框也必须填写，否则视为该必填项未完成。
  13. 校验通过后才允许保存正式拜访记录、关闭表单，并同步刷新待补充记录队列和历史拜访记录列表。

  • 「我的渠道」全部网点态（网点选「全部网点」）下，4 张经营结果卡片（新增资产 / 新增有效户 / 新增开户数 / 渠道经营积分）可点击进入，并带入对应指标维度。
  • 单网点态不可进入（选中具体网点时结果卡不可点击）。
  • 「名下渠道数」卡始终无此入口（员工级结构性指标，无网点排名含义）。

3. 页面目标

  • 让员工在单一指标维度下查看本人名下网点的排名分布，并可直接查看网点渠道详情。

4. 页面模块说明

顶部控制区：标题＝所点击指标名 + 「名下渠道排名」标识；周期下拉（昨日/本周/自然月/本年/考核月；选「考核月」展示期次列表）。无维度切换控件（维度固定为「按网点」）。

指标切换区（页内）：排名列表上方保留 4 张指标卡（新增资产 / 新增有效户 / 新增开户数 / 渠道经营积分），4 选 1、默认选中入口带入的指标，当前指标卡高亮；点击某张卡 → 排名列表与各行数值按该指标刷新（卡选中态同步切换）。

排序切换：列表支持排序切换——默认按名次，可切换为按数值升序 / 降序。

排名列表：按该指标排列本人名下网点，每行展示——排名序号 / 网点名 / 该指标数值 / （可选）占比或进度条。网点行不展示所属员工副信息（已限定为本人名下）。网点名最多展示 2 行，1～2 行完整可见，超过 2 行时第 2 行末尾以省略号收尾，并与右侧指标数值顶部对齐；超过 2 行的完整名称在该行展开的渠道详情卡片内完整展示（依据「渠道名称完整显示」规格）。

网点行点击：整行点击在该行下方原地展开 / 收起渠道详情卡片（同一列表同时仅展开一行；展开交互沿用「渠道详情卡片」规格）。

渠道详情卡片（网点行展开）：自上而下展示——①完整渠道名称（不发生省略号隐藏）；②渠道建档信息：建码日期 · 已建码天数、关键人列表（职位 + 姓名 + 生日，全部展示、不设条数上限）、网点星级 + 星级变化（网点星级仅用星形图标展示，不附「一星／二星」等文字档位）。卡片不展示经营指标 4 项与过程指标 4 项；卡片只读，不提供「编辑建码信息」入口；仅星级变化随页内「时间周期」切换刷新，建码日期 · 天数与关键人列表为静态档案、不随周期变化；无建档数据的网点展开后仍展示完整渠道名称，其余区域展示「暂无建档信息」占位。关键人区排布：关键人标签默认每行两个（各占半宽），当单个标签的「职位 + 姓名 + 生日」在半宽内放不下时，标签内文字自然换行，完整展示、不截断、不溢出；标签较多时逐行自然折行，不设条数上限。

周期口径：继承上游「我的渠道」当前周期（含所选考核期次）进入；进入后页内独立切换（仅影响本页）；返回「我的渠道」时其周期保持进入前原状态（页内切换不回写）；再次进入重新继承。

5. 页面交互流程

流程 1：进入排名页：「我的渠道」全部网点态 → 点某张经营结果卡片 → 进入本页并继承该指标与当前周期 → 展示本人名下网点排名。

流程 3：查看渠道详情：点网点行 → 展开渠道详情卡片。

流程 4：切换指标：进入排名页 → 点其余 3 张指标卡之一 → 排名列表与各行数值按该指标刷新 → 顶部标题与卡选中态同步更新。

第 6 章：通用能力说明

6.1 二级页面（Sub-Page）

能力定位：全屏覆盖的二级页面，承载不适合弹框承载的复杂内容，提供原生 App 级别的页面切换体验。

适用页面：全部异动、拜访历史、拜访详情、我要拜访、需求跟进表、需求详情、知识库、渠道星级详情页、名下渠道排名

技术实现：position:fixed，z-index:100；初始 opacity:0; visibility:hidden（不占位）；打开添加 open class → opacity:1; visibility:visible；入场动画：从右侧 translateX(100%) 滑入，300ms cubic-bezier(0.4,0,0.2,1)

标题栏（sub-hd）：深蓝色顶栏，左侧「← 返回」，中间页面标题，右侧操作（可选）

交互规则：点击返回按钮 → 关闭当前子页；不支持手势右滑关闭（首版）

首版必做：动画 + 所有子页面接入 首版可弱化：手势右滑关闭（P1）

状态同步要求：子页面操作保存后（如需求状态更新），关闭时触发父页面列表数据刷新

6.2 Bottom Sheet（底部弹框）

能力定位：适用于表单编辑、选项选择等需要更多空间的操作场景，不触发全屏跳转。

适用场景：建联信息编辑、AI问案例

技术实现：挂载于 body 层（非 #app 内），避免 overflow:hidden 截断；position:fixed; bottom:0; left:50%; transform:translateX(-50%) translateY(100%)；打开添加 open class → translateY(0)，配合蒙层

交互规则：点击蒙层关闭；顶部有拖动把手（视觉提示，首版不支持手势拖动）；最大高度 88vh，内容超出时内部滚动

状态同步要求：Sheet 保存成功后，触发页面对应数据区域的刷新

6.3 Toast 通知

能力定位：操作结果的轻量级反馈，不阻塞用户操作。

适用场景：所有操作反馈（保存成功、复制成功、定位状态变化等）

规格：出现在底部距底 80px 处，深色圆角胶囊，2.5s 后自动消失，淡入淡出动画

挂载层级：body 级别，z-index:10000

6.4 筛选标签（Filter Tag）

能力定位：多处复用的横向滚动筛选组，单选。

适用场景：重点关注、历史拜访、需求跟进、知识库

交互规则：同一组内互斥单选，选中态蓝底白字；横向超出自动滚动，隐藏滚动条；默认选中「全部」

第 8 章：状态与规则说明

8.1 MVP 打卡与经纬度采集规则

  • 打卡判定口径：员工选择拜访网点后点击“立即打卡”，即可生成打卡记录；定位失败不阻断打卡。
  • 经纬度采集：点击打卡前后，H5 尝试采集经纬度、定位精度和采集时间；采集成功则随拜访记录保存。
  • 采集失败处理：因权限拒绝、企微/H5 容器限制、系统超时或设备能力不支持导致采集失败时，不阻断打卡；记录 gpsStatus，并允许员工继续选择拜访网点。
  • 前端交互保持：保留当前“我要拜访 · 立即打卡”“立即填写”“稍后填写”“待补充记录”等交互。

8.1.1 非MVP定位增强说明

8.2 需求上报规则

  • 自动上报条件：拜访表单“需求是否紧急”=紧急 AND “需求是否满足”=未满足 → 保存时自动触发企微应用消息推送至员工所属团队长。
  • 手动上报：需求详情页选择「无法满足」→ 保存时触发上报，同时记录上报状态
  • 推送内容：包含需求描述、网点名称、紧急程度、员工姓名

8.3 生日提醒规则

  • 计算：以当年对应月日计算距今天数，若当年日期已过则计算明年
  • 今天生日（d=0）：闪烁橙色徽章「🎂 今天生日」
  • 1-7天（d=1-7）：橙色徽章「🎂 N天后生日」
  • 8-30天（d=8-30）：绿色徽章「🎂 N天后」
  • >30天：灰色徽章「🎂 M月D日」
  • 无生日数据：不显示徽章

8.4 待补充记录规则

支持多条待补充记录并存，新打卡不覆盖旧记录；完成一条仅移除对应记录。列表按打卡时间倒序。

  • 员工打卡后选「稍后填写」→ 在 localStorage 写入 _pendingRecord（打卡地点 + 时间）
  • 首页「渠道拜访」模块顶部显示黄色横幅提醒
  • 点击「去补充」→ 恢复打卡状态并显示表单
  • 完整提交后 → 横幅消失，_pendingRecord 清空
  • 每次只能有一条待补充记录（新打卡会覆盖旧的）

8.5 数据权限规则

需求详情操作区依据当前角色与被查看员工 ID 渲染；团队长穿透员工时不得出现员工写操作。定位页可按设计展示并复制经纬度，埋点不得上传经纬度原值。

  • 员工仅可见名下渠道数据（networkId 列表由登录态决定）
  • 团队长可见辖内汇总数据（后续版本）
  • 关键人电话字段脱敏展示（中间4位替换为 ****）

8.6 Tab 导航滚动联动规则

  • 点击 Tab 平滑滚动至锚点，同时设置 _tabScrollLock=true，1.5 秒后解除
  • 锁定期间禁止滚动事件触发 Tab 高亮变更
  • 非锁定期间：模块顶部进入视口上方 120px 内即高亮对应 Tab
  • 滚动到底部：强制高亮最后一个 Tab

8.7 重点关注事项链路规则

消息盒子直达 H5 类（网点降级、未拜访提醒、生日提醒）： 1. 上游规则命中； 2. 消息盒子生成消息并直接下发至 H5； 3. H5 在首页和全部异动页展示消息摘要； 4. 员工点击消息； 5. H5 打开消息详情页； 6. 消息详情页打开成功后，该消息从 H5 当前列表消失。

H5 需求记录类（需求未满足）： 1. 员工在拜访表单或需求跟进中提交未满足需求； 2. H5 生成或更新 Demand 记录； 3. 符合未满足展示条件的 Demand 进入重点关注； 4. 员工点击需求未满足事项； 5. H5 打开需求详情页； 6. 若需求仍未满足，返回后继续展示；若状态变为已满足、已关闭或已失效，则停止展示。

补充规则： - H5 不负责生成前三类消息； - 需求未满足不走消息盒子消费链路； - 消息盒子类以 messageId 做去重和当前列表移除； - 需求未满足以 demandId 和需求状态控制展示； - 不再引入企微消息中心作为本模块链路说明。
