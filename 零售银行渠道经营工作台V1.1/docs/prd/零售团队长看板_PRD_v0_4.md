## 2. 项目背景与目标

### 2.1 背景

零售员工版渠道经营工作台已沉淀个人渠道经营能力，员工可以完成重点关注查看、渠道建码维护、拜访打卡、拜访记录补充、需求状态维护、知识库和工具库使用。团队长日常管理中需要从团队维度查看员工经营进展，识别无法闭环的上报需求、超过阈值仍未处理的超时关注，并通过提醒、跟进、归档动作推动团队经营闭环。

团队长本人也可能承担个人渠道经营任务。团队管理视角只看团队聚合数据和员工明细，不代员工编辑业务数据；团队长通过顶部角色切换图标回到本人员工视角，按本人身份完成打卡、建码、拜访和需求维护。

### 2.2 核心目标

- **团队看盘**：团队长可在一个 H5 页面查看团队重点关注、团队总览、星级渠道、过程跟进、拜访记录五类核心模块。
- **事项闭环**：团队长可处理员工上报需求，完成标记跟进、归档，并可对超时关注事项进行一键提醒。
- **员工穿透**：团队长可从排名、重点关注、过程记录、拜访记录进入员工详情，查看员工重点关注、渠道、拜访和需求上下文。
- **边界清晰**：团队长团队视角只读员工业务数据，不代员工打卡、编辑建码、提交拜访记录、保存需求状态；团队长本人的业务操作通过顶部角色切换图标回到员工版流程。
- **数据安全**：团队长查看员工敏感字段时按权限脱敏，埋点不上传手机号、GPS 原始经纬度、需求描述原文、拜访备注原文、解决方案原文。

### 2.3 非目标

- 不重写员工版已评审通过的页面结构、字段口径和业务状态。
- 不在团队长团队视角提供代员工打卡、代员工编辑建码、代员工提交拜访记录、代员工保存需求状态。
- 不由团队长版判断员工重点关注消息是否完成，员工消息盒子生命周期由消息盒子后台负责。
- 不提供 PC 端页面适配。

### 2.4 上线时间

PRD 确认后 2-3 周内完成 H5 开发、联调和试运行。上线范围包含团队看板、团队重点关注、上报需求处理、超时提醒、团队总览、完整排名、星级渠道、过程跟进、团队拜访记录、员工穿透和角色切换。

## 3. 用户角色与使用场景

### 3.1 用户角色

| 角色 | 岗位/职责 | 核心诉求 | 使用频率 |
|------|-----------|----------|----------|
| 零售团队长 | 管理辖内零售客户经理，关注团队渠道经营表现和员工过程执行 | 查看团队指标、处理上报需求、提醒员工处理超时关注、穿透查看员工经营详情 | 每日 |
| 零售客户经理 | 团队长辖内员工，负责个人渠道经营执行 | 通过员工版完成打卡、拜访记录、需求维护，必要时触发团队长关注 | 每工作日 |

### 3.2 核心使用场景

#### 场景 1：团队长进入团队看板查看团队表现
**背景**：团队长需要快速掌握本周期团队经营结果和过程执行情况。  
**操作路径**：团队长从统一工作台团队版入口进入 → 查看团队重点关注 → 查看团队总览 → 查看当前排名分析 → 打开完整排名。员工版不展示团队版切换入口。  
**期望结果**：团队长可看到上报需求、超时关注、团队业务指标、员工/网点排名，并可从「按员工」排名穿透员工详情（「按网点」排名行就地展开渠道详情卡片）。

#### 场景 2：团队长处理员工上报需求
**背景**：员工侧产生紧急且未满足、无法满足或主动上报的需求，需要团队长介入跟进。  
**操作路径**：团队版重点关注 → 上报需求 → 查看全部 → 切换新上报/跟进中/已归档 → 打开需求详情 → 标记跟进或归档。  
**期望结果**：团队长可查看需求上下文并完成团队侧处理动作；标记跟进和归档只更新团队侧处理状态，不反向修改员工拜访记录和员工需求原始内容。

#### 场景 3：团队长提醒员工处理超时关注
**背景**：团队内出现生日当天、长期未拜访、需求未满足且未上报等需要团队长督促员工处理的事项。  
**操作路径**：团队版重点关注 → 超时关注 → 查看全部 → 筛选待提醒 → 勾选事项 → 一键提醒 → Toast“已发送提醒”。  
**期望结果**：系统按员工聚合发送管理提醒，列表刷新提醒状态；团队长不进入员工消息详情页、不消费员工消息；今日已提醒及冷却期内事项不可再次勾选提醒。

#### 场景 4：团队长从排名穿透员工详情
**背景**：团队长发现某员工指标异常或排名靠后，需要查看员工经营明细。  
**操作路径**：团队总览 → 完整排名 → 点击员工 → 员工详情 → 查看员工重点关注、我的渠道、渠道拜访及其中的需求跟进。  
**期望结果**：团队长可查看员工经营上下文；员工详情页只读，不展示代员工写操作入口。

#### 场景 5：团队长处理本人业务
**背景**：团队长本人也承担渠道经营任务，需要像普通员工一样完成拜访和需求维护。  
**操作路径**：团队版 → 点击顶部角色切换图标 → 回到员工版 → 按本人身份完成员工版流程。  
**期望结果**：团队长本人业务操作使用团队长本人的员工 ID，不携带被查看员工 ID，不影响团队内其他员工数据。

### 4.1 整体架构说明

## 5. 页面详细说明

### 5.1 团队版主看板


#### 1. 页面定位

团队长查看团队渠道经营表现和待处理事项的主页面。

#### 2. 页面入口

- 员工版不展示角色切换入口；团队长从统一工作台团队版入口进入。

#### 3. 页面目标

- 聚合展示团队重点关注、团队总览、星级渠道、过程跟进、拜访记录。
- 支持团队长快速进入上报需求处理、超时提醒、完整排名、星级渠道详情、过程详情、员工详情。
- 顶部右侧提供角色切换图标，用于返回本人员工视角。

#### 4. 页面模块说明

顶部五项导航支持鼠标横向拖拽和移动端横向滑动，右侧显示渐隐遮罩，拖动结束不得误触导航项；超时关注页签显示团队侧未读红点，点击查看后消失，且不得消费员工侧消息。

##### 顶部标题与返回员工版
**模块作用**：标识当前处于团队长视角，并提供返回员工版的固定入口。

### 5.2 团队重点关注页


#### 1. 页面定位

团队长处理团队风险和待协同事项的核心模块，包括上报需求和超时关注。

#### 2. 页面入口

- 团队版首页“重点关注”模块。
- 团队版首页重点关注卡片点击“查看全部{num}条”。
- 团队版首页重点关注预览卡片点击进入详情或列表。

#### 3. 页面目标

- 让团队长优先看到需要管理介入的事项。
- 支持上报需求跟进、归档。
- 支持超时关注筛选、勾选、一键提醒。

#### 4. 页面模块说明

排序按钮支持默认、升序、降序三态，当前方向标蓝。超时关注与员工版重点关注类型对齐，覆盖网点降级、未拜访、生日提醒、需求未满足四类事项。

##### 重点关注首页卡片
**模块作用**：在团队版首页预览团队长需要处理的上报需求和超时关注。  
**展示内容**：上报需求页签、超时关注页签、各页签数量、当前页签预览卡片列表、查看全部入口。  
**交互说明**：点击页签后切换预览列表；点击上报需求预览卡片进入上报需求详情页；点击超时关注预览卡片进入超时关注列表页；点击查看全部进入当前页签的完整列表页；从列表页返回时仍在当前页签。  
**备注**：首页仅展示预览数据，筛选、排序、批量操作在列表页完成；预览列表为空时展示当前页签空态；数量加载失败时展示短横线并允许点击查看全部重试。

##### 上报需求列表
**模块作用**：集中展示员工上报给团队长的需求，并支持按处理状态查看和进入详情处理。  
**展示内容**：状态页签“全部”“新上报”“跟进中”“已归档”、排序按钮、需求卡片列表、网点名称、需求描述摘要、紧急程度、上报员工、记录日期、处理状态。  
**展示逻辑**：承接员工版需求详情「无法满足」触发逻辑：员工端点击「无法满足」并保存 → 自动触发企微消息推送至团队长。按照时间降序排列。
**交互说明**：点击状态页签刷新列表；点击排序按钮在记录日期升序和降序之间切换；点击需求卡片进入上报需求详情页；从详情页返回时保留状态页签、排序方式和滚动位置。  
**备注**：“全部”页签默认隐藏处理状态为“已归档”的记录（仅在“已归档”页签展示）；“全部”页签默认展示新上报和跟进中需求；“上报需求”页签（团队重点关注首页）的数量＝总上报数−已归档数，随归档状态动态计算；无数据时按页签展示“暂无上报需求”“暂无新上报需求”“暂无跟进中需求”“暂无已归档需求”；列表加载失败时提供重试刷新。

##### 上报需求详情
**模块作用**：展示上报需求的完整上下文，并支持团队长进行跟进标记和归档管理。  
**展示内容**：所属网点、上报员工、记录时间、需求描述、紧急程度、需求状态、员工侧解决方案、“AI问案例”入口、团队长处理状态、更新时间、标记跟进按钮、归档按钮。
**交互说明**：新上报状态仅可点击“标记跟进”，状态更新为跟进中；跟进中可直接点击“归档”更新为已归档，无归档原因面板和二次确认。团队长处理状态（跟进中/已归档）按需求 ID 后写覆盖，处理成功后详情页状态徽章与外部列表（上报需求列表、团队重点关注）徽章联动刷新。解决方案框内容不可点；点击“AI问案例”进入知识库检索，并动态展示“AI 推荐”。由上报需求列表进入详情时，内容区左下/右下角展示「上一条/下一条」悬浮按钮，可在进入详情时冻结的浏览序列中逐条前后浏览；已是首条/末条时对应按钮置灰、点击给 Toast（「已是第一条」/「已到最后一条」），页面不跳转；从团队重点关注首页“上报需求”预览卡片进入时不展示这两个按钮；团队长端本页只读，无未保存改动拦截。
**备注**：团队长处理动作不反向修改员工拜访记录和员工需求原始内容；「需求状态」读取与员工端共享的同一份值（已满足/未满足/无法满足），不因团队长处理状态变化而改写；新上报时归档按钮禁用，已归档需求不展示标记跟进和归档按钮。

##### 超时关注列表
**模块作用**：展示需要团队长进行管理提醒的超时/当天事项，并支持批量提醒员工处理。团队版超时关注采用团队侧内部提醒池 `TeamTimeoutAttention`，不依赖员工消息盒子定制，不进入员工消息详情页。  
**展示内容**：状态页签“全部”“待提醒”“已提醒”、排序按钮、全选复选框、已选数量、一键提醒按钮、事项类型、关注对象、事项描述、所属员工、已超时天数/当天标识、提醒状态、最后提醒日期、下次可提醒日期。  
**展示逻辑**：

| 事项类型 | 是否进入团队超时关注 | 进入条件 | 停止/排除条件 | 团队提醒冷却 |
|----------|----------------------|----------|----------------|--------------|
| 网点降级 | 是 | 数仓生成正式网点降级事项后进入团队超时关注 | 来源降级事项失效或关闭后停止展示 | 今日已提醒不可重复选择 |
| 生日当天 | 是 | 关键人生日为当天 | 当天结束后自动消失；员工侧提前 5 天提醒不影响团队当天提醒 | 当天最多提醒 1 次 |
| 未拜访 | 是 | 员工对网点未拜访满 35 天 | 员工完成有效拜访后停止展示 | 团队提醒后 7 天内不可重复提醒 |
| 需求未满足 | 是 | 需求处于“未满足”且未上报，未满足满 12 天 | 需求已上报、已满足、已失效或已关闭后停止展示 | 团队提醒后 3 天内不可重复提醒 |

**交互说明**：点击状态页签刷新列表；点击排序按钮按超时天数升序或降序切换；待提醒且 `canRemind=true` 的事项可单选、全选和取消选择；点击一键提醒后直接按员工聚合发送管理提醒，Toast“已发送提醒”，并刷新提醒状态；仅待提醒事项可选，今日已提醒项不可选；固定显示“全选”和“已选 N”。超时关注卡片/行不跳转员工消息详情页，不消费员工消息；如需查看上下文，团队长可通过员工姓名进入员工详情只读页。  
**备注**：默认仅展示 `TeamTimeoutAttention` 中达到团队侧规则的事项；未选择事项时点击一键提醒提示“请选择待提醒事项”；提醒接口失败时保留勾选状态并提示“提醒发送失败，请重试”；今日已提醒或处于冷却期的事项不可重复提醒。

### 5.3 团队总览与完整排名页


#### 1. 页面定位

团队长查看团队业务指标、过程指标和员工/网点排名的分析模块。

#### 2. 页面入口

- 团队版首页“团队总览”模块。
- 团队版首页“查看完整排名”入口。

#### 3. 页面目标

- 帮助团队长快速掌握团队本周期经营情况。
- 支持按员工和按网点查看排名。
- 支持从「按员工」排名穿透员工详情；「按网点」排名行就地展开渠道详情卡片。

#### 4. 页面模块说明

指标卡选中态联动排名；指标、按员工/按网点维度和默认/升序/降序排序共同决定结果，切换后即时刷新标题和列表。按网点排名同时展示网点与归属员工；「按员工」维度点击行进入员工详情，「按网点」维度整行点击展开渠道详情卡片、不跳员工详情。页面顶部提供「时间周期」下拉（昨日/本周/自然月/本年/考核月，考核月口径与期次规则见 §6.2）；团队总览与完整排名详情共用同一周期状态，从总览进入完整排名时继承当前周期及所选考核期次。

##### 团队业务指标
**模块作用**：展示团队在当前周期内的核心经营结果。  
**展示内容**：当前周期、银行渠道新增资产、银行渠道新增有效户、银行渠道新增开户数、团队名下渠道数、银行渠道经营积分、各指标环比趋势。  
**交互说明**：切换周期后刷新全部团队业务指标和趋势；点各个tab切换排名卡，不进入二级页；本区恒展示 5 项业务指标，项数不随排名维度变化；「团队名下渠道数」卡一卡两用（团队维度指标展示 + 排名指标选择器）。  
**备注**：新增资产单位为万元，有效户和开户数单位为户，经营积分单位为分；排名维度＝「按网点」时「团队名下渠道数」卡整卡置灰（不可选态）、但不隐藏，表示"不可作为网点维度的排名指标"，其数值本身仍是有效的团队维度汇总；切回「按员工」恢复正常外观；指标接口失败时展示“指标加载失败，请稍后重试”

##### 当前排名分析
**模块作用**：展示当前核心指标下员工或网点的排名摘要。  
**展示内容**：排名标题、当前指标名称、维度切换“按员工”“按网点”、排名序号、员工姓名或网点名称、指标值、查看完整排名入口。  
**交互说明**：切换维度后按当前指标重新获取排名列表并保留当前周期；点击业务指标卡只切换当前排名指标，不进入二级页；点击“查看完整排名”进入完整排名详情页；「按员工」维度点击员工排名行进入员工详情，「按网点」维度整行点击展开渠道详情卡片、不跳员工详情。  
**备注**：默认指标为银行渠道新增资产，默认维度为按员工；排名维度＝「按员工」时可选 5 个指标，切到「按网点」时「渠道数」退出可选范围（不可选）；当前已选中「渠道数」再切到「按网点」时，排名指标自动回落到默认「新增资产」、排名标题与列表按“新增资产 · 按网点”刷新，该回落为一次性，切回「按员工」不自动恢复；无排名数据时展示“暂无排名数据”；排名接口失败时展示重试入口。

##### 排名渠道详情卡片（「按网点」维度）
**模块作用**：作为「按网点」排名行（首页 Top4 与完整排名页）就地展开的渠道（网点）**建档**详情，兼顾长渠道名称的完整查看与渠道建档信息的就地查看。  
**展示内容**：完整渠道名称（不发生省略号隐藏）→ **渠道建档信息**三项：①建码日期 · 已建码天数；②**关键人列表**（职位 + 姓名 + 生日，全部展示、不设条数上限）；③网点星级 + 星级变化（网点星级**仅用星形图标展示**，不附「一星／二星」等文字档位）。**卡片不再展示经营指标 4 项与过程指标 4 项**；卡片不含员工级指标「名下渠道数」。  
**交互说明**：整行点击在该行下方原地展开/收起卡片；同一列表同时仅展开一行；维度切到「按员工」时卡片收起（按员工维度无卡片）；卡片**只读**，不提供「编辑建码信息」入口。  
**备注**：**仅星级变化**随页面「时间周期」下拉（昨日/本周/自然月/本年/考核月）切换刷新；建码日期 · 天数与关键人列表为静态档案、不随周期变化；无建档数据时仍展示完整渠道名称，其余区域展示「暂无建档信息」占位。**关键人区排布**：关键人标签默认**每行两个**（各占半宽），当单个标签的「职位 + 姓名 + 生日」在半宽内放不下时，**标签内文字自然换行**，完整展示、不截断、不溢出；标签较多时逐行自然折行，不设条数上限。

##### 完整排名详情
**模块作用**：提供团队范围内业务指标和过程指标的完整排名列表。  
**展示内容**：指标选择器、维度选择器、当前周期、排名摘要、排名序号、员工姓名或网点名称、所属团队、指标值、趋势标识。  
**交互说明**：切换指标后按当前维度刷新列表；切换维度后按当前指标刷新列表；「按员工」维度点击员工行进入员工详情页，「按网点」维度整行点击展开排名渠道详情卡片、不跳员工详情；下拉刷新重新拉取当前排名。点击涨跌和数据支持切换升降序排列。  
**备注**：业务指标包含新增资产、新增有效户、新增开户数、渠道数、经营积分；过程指标包含拜访次数、活动次数、需求总数、需求未满足数量；排名维度＝「按网点」时「渠道数」不可选（对应卡片置灰）、且当前选中「渠道数」时切到「按网点」自动回落到默认「新增资产」；行名称（网点名）展示规则与渠道名称一致：最多 2 行、超出第 2 行省略号，完整名称在展开的渠道详情卡片内展示；列表为空时展示“暂无排名数据”。

### 5.4 团队星级渠道页


#### 1. 页面定位

团队长按星级查看团队渠道结构和渠道明细的页面。

#### 2. 页面入口

- 团队版首页“星级渠道”模块。
- 团队星级分布点击某星级。

#### 3. 页面目标

- 展示团队一星至五星渠道分布。
- 支持团队长按星级查看网点明细。
- 支持在星级渠道明细中就地查看渠道经营/过程指标（点击网点行展开渠道详情卡片）。

#### 4. 页面模块说明

星级渠道模块标题行提供「时间周期」下拉（与同页「过程跟进」模块周期下拉同位置、同样式），切换后各星级渠道数量与占比按该周期刷新；星级渠道与星级渠道详情共用同一周期状态。各星级条目点击进入「星级渠道详情」页（不再内联展开网点列表）；无数据星级不可点。详情页使用星级标签、员工筛选与时间周期，列表展示网点、建码日期、已建码天数，不展示员工姓名列。

##### 星级分布
**模块作用**：按星级汇总团队范围内渠道数量。  
**展示内容**：标题行「时间周期」下拉、一星标签、二星标签、三星标签、四星标签、五星标签、各星级渠道数量、各星级占比、进度条。  
**交互说明**：切换「时间周期」后各星级数量与占比刷新；点击有数据的星级条目进入「星级渠道详情」页并预置所点星级（行尾为进入箭头）；无数据的星级不可点。  
**备注**：默认统计团队长辖内全部员工名下渠道；占比按当前筛选范围内渠道总数计算；渠道总数为 0 时展示空态。

##### 星级渠道详情
**模块作用**：展示某一星级下的团队渠道明细。  
**展示内容**：页面顶部「时间周期」下拉（昨日/本周/自然月/本年/考核月）、「员工」筛选（支持按姓名搜索，规则见 §5「员工筛选器」）、「星级变化」筛选下拉（全部/升星/降星/无变化，默认「全部」）、当前星级 pills（数量随变化筛选联动）、网点名称、当前星级、建码时间、跟进天数；网点行右端展示该周期相对上期的星级变化图标（升星 ↑红 / 降星 ↓绿 / 无变化灰「—」，无上期数据不展示、图标不可点）；网点行可在行下方展开渠道详情卡片。  
**交互说明**：切换「时间周期」「员工」「星级变化」筛选或星级 pills 后刷新列表；点击某网点行在该行下方原地展开/收起渠道详情卡片（内容为完整渠道名称 + 经营指标 4 项 银行渠道新增资产/银行渠道新增有效户/银行渠道新增开户数/银行渠道经营积分 + 过程指标 4 项 拜访次数/活动次数/需求总数/需求未满足，各项随页面「时间周期」刷新）；同一列表同时仅展开一行。  
**备注**：保留「员工」筛选；列表不展示员工姓名列；网点行名称最多 2 行、超出第 2 行省略号、与右侧元素顶部对齐，完整名称在展开的渠道详情卡片内展示；无该星级渠道时展示“暂无该星级渠道”，因「星级变化」筛选造成的无匹配另给带「清除筛选 / 看全部」入口的空态“当前筛选下暂无渠道”；星级变化图标数据未到位时整体不展示、其余功能不受影响；返回列表保留滚动位置，重新进入详情页时「星级变化」筛选回到默认「全部」；团队长仅查看。

### 5.5 团队过程跟进与拜访记录页


#### 1. 页面定位

团队长查看团队拜访、活动、需求三类过程动作的模块。

#### 2. 页面入口

- 团队版首页“过程跟进”模块。
- 团队版首页“拜访记录”模块。
- 团队版首页“拜访记录”模块右上「更多 ›」入口进入拜访记录二级列表页。
- 团队版首页“查看完整排名”进入当前过程指标详情；“需求管理”入口进入需求管理 Tab。

#### 3. 页面目标

- 展示团队过程执行情况。
- 支持按周期、员工、网点筛选过程记录，并通过顶部 Tab 切换记录类型。
- 支持按周期、员工、类型检索团队拜访与活动记录。
- 支持查看团队拜访和活动详情。

#### 4. 页面模块说明

二级页将“拜访次数 / 活动次数 / 需求总数 / 需求管理”设为四个并列 Tab；“查看完整排名”进入当前指标 Tab，“需求管理”入口直接进入需求管理 Tab，返回时保留 Tab、周期、员工、网点和滚动位置。首页「拜访记录」模块点击「更多 ›」进入拜访记录二级列表页；点击月历日期不跳页、仅在模块内筛选下方记录列表（默认展示今天）；点击单条外展记录直接进入对应拜访或活动详情；拜访用蓝点、活动用橙点，同日可同时显示。周期为「昨日/本周/自然月/本年/考核月」五项；过程跟进（首页过程指标）与过程跟进详情各自独立记忆周期，考核月期次同规则（见 §6.2）。

##### 过程指标
**模块作用**：展示团队在当前周期内的过程执行情况。  
**展示内容**：当前周期、拜访次数、活动次数、需求总数、需求已满足数量、需求未满足数量。  
**交互说明**：点击拜访次数、活动次数、需求总数仅在首页切换列表，不进入二级页；点击需求管理进入过程跟进二级页，锚定到全部需求，筛选为自然月、全部员工、全部网点。首页点击列表进入二级页，在哪个tab下进入之后锚定哪个tab的详细列表。
**备注**：需指标接口失败时展示“过程数据加载失败，请稍后重试”；当前周期无数据时指标展示 0。

##### 过程详情列表
**模块作用**：展示团队范围内的拜访、活动和需求过程明细。  
**展示内容**：顶部tab筛选器，周期筛选器（昨日/本周/自然月/本年/考核月）、员工筛选器（支持按姓名搜索，规则见下）、网点筛选器，详情卡片。  
**交互说明**：切换任一筛选条件后刷新列表；点击需求卡片进入需求详情；点击员工卡片进入员工详情；从详情页返回时保留筛选条件和滚动位置。渠道（网点）行名称最多 2 行、超出第 2 行省略号、与右侧元素顶部对齐，点击该行可在行下方展开渠道详情卡片（完整渠道名称 + 经营指标 4 项 新增资产/新增有效户/新增开户数/经营积分 + 过程指标 4 项 拜访次数/活动次数/需求总数/需求未满足，随页面周期刷新），同一列表同时仅展开一行。  
**备注**：列表默认按记录时间倒序；筛选无结果时展示空态（页签为0）；筛选接口失败时保留上一次列表并提示“过程记录加载失败”；由“需求管理”列表进入的需求详情为**只读**页，内容区左下/右下角展示「上一条/下一条」悬浮按钮；已是首条/末条时对应按钮置灰、点击给 Toast（「已是第一条」/「已到最后一条」）；团队长端**无二次确认**、无未保存改动拦截（与员工端可编辑版不同）；返回列表保留周期/员工/网点与状态 chips 筛选及滚动位置；渠道详情卡片中某指标缺数据显示「—」。

**网点筛选器**  
**模块作用**：在团队可见范围内数百个、跨多家银行的网点中快速定位目标网点（含"需求管理"Tab 的网点筛选）。  
**交互规格**：点击网点筛选器 → 弹出网点选择弹层（高度 90%，头部固定、列表区内部滚动，内容为团队可见范围内的全量网点），与员工端「我的渠道」网点选择为同一实现：
1. **搜索框**：对网点名称做跨银行模糊匹配；已选银行大类时仅在所选大类内匹配。
2. **银行大类 chips**：即"银行品牌"（取自网点对象的 `bankBrand`）。按固定优先级排序：国有大行 → 股份制 → 城商/农商；默认铺 3 行，超出收进末尾「更多 ∨」，展开后 chips 区内部滚动；默认选中「全部」。
3. **最近选择（置顶区）**：展示本设备最近选中的 5 个网点；无历史时不展示；数据存本机，不跨设备同步。
4. **网点列表**：保持「全部网点」置顶；点击任一网点即选中、回填筛选条件并关闭弹层。
5. **交集规则**：搜索词与银行大类为交集（AND）。
6. **空态兜底**：交集为空时展示空态 + 「清除大类，在全部大类中搜索」；点击后回到「全部」、保留搜索词重新匹配。
7. **回退规则**：点遮罩/关闭按钮关闭弹层不改变已选网点；重新打开回到默认态（全部 + 空搜索）。

**员工筛选器**  
**模块作用**：在团队全部员工中快速定位目标员工；团队长端「星级渠道详情」「过程详情列表（含需求管理 Tab）」「拜访记录日历」及其日历详情二级页共 4 处共用同一实现。  
**交互规格**：点击员工筛选器 → 弹出员工选择弹层（头部固定、列表区内部滚动）：
1. **搜索框**：标题下方固定搜索框，对员工姓名做包含匹配、输入即时过滤（无需点击提交）；清空搜索词恢复全量列表。
2. **全部员工置顶**：「全部员工」常驻列表首项、不参与姓名过滤；点击任一员工（含「全部员工」）即选中、回填筛选条件并关闭弹层。
3. **空态兜底**：搜索无命中时列表区展示“没有找到匹配的员工”，搜索词保留以便修改。
4. **回退规则**：点遮罩/关闭按钮关闭弹层不改变已选员工；重新打开弹层时清空搜索词、列表回到全量，当前已选员工保持高亮选中态。
5. **范围说明**：仅按员工姓名匹配；列表项仅展示姓名，不展示工号/所属网点；不提供「最近选择」置顶。

##### 拜访记录日历
**模块作用**：以月历方式查看团队拜访和活动分布。  
**展示内容**：月份切换器、日历日期、拜访标记、活动标记、员工筛选器（支持按姓名搜索，规则见上）、选中日期、外展两条记录、「更多 ›」入口。  
**交互说明**：切换月份后刷新当月标记；切换员工筛选后刷新日历标记；点击月历任一日期不跳页、仅在模块内筛选下方记录列表（默认展示今天，该日期无记录时展示空态）；点击「更多 ›」进入拜访记录二级列表页（该页顶部带统一周期筛选器与「员工筛选器」，与主页日历共用同一弹层实现，详见本页「员工筛选器」）；点击首页外展记录直接进入对应拜访或活动详情。
**备注**：拜访和活动使用不同颜色标记；同一天同时存在拜访和活动时展示两个标记；当日无记录时展示“当日暂无团队拜访或活动记录”。同员工版一致。拜访记录二级列表页按月分组展示，并接入含「考核月」的统一周期筛选（昨日/本周/自然月/本年/考核月，选「考核月」后再选期次）。

##### 拜访记录二级列表
**模块作用**：集中查看团队范围内的拜访与活动记录，支持按周期、员工、类型检索。  
**展示内容**：统一周期筛选器（昨日/本周/自然月/本年/考核月，选「考核月」后再选期次）、员工筛选器（支持按姓名搜索，规则见上）、类型标签（全部 / 拜访 / 活动，各标签叠加次数）、记录列表（按月分组）。  
**交互说明**：页面不再展示日历，也无「X月X日记录」单日锚定标题，列表改按所选周期检索（不锚定单日）。切换周期（含考核月期次）或员工筛选后，列表与「全部 / 拜访 / 活动」次数同步按新条件重算；切换类型标签仅收窄列表、不改各标签上的次数。点击单条记录进入对应拜访或活动详情，返回时保留周期、员工、类型与滚动位置。  
**备注**：各标签次数口径为「当前周期（叠加当前员工筛选）下该类型的记录条数」，与当前选中的类型标签无关；筛选无结果时列表展示空态。

##### 拜访/活动详情
**模块作用**：展示团队成员单条拜访记录或活动记录的只读详情。  
**展示内容**：记录类型、所属员工、所属网点、日期、开始时间、结束时间、拜访对象（统一展示为「职位+姓名」，多选并列、完整换行不截断）、需求挖掘内容（**需求挖掘标签纵向列表，每个标签后跟各自选填描述**；描述为空不展示描述行；维度三色与员工端一致）、达成合作内容、活动类型、参与人数、备注。 同员工版一致
**交互说明**：页面只读展示；点击返回回到来源列表并保留原筛选条件
**备注**：团队长不在此页代员工编辑、提交、删除记录；拜访对象为提交时的关键人快照、展示口径与员工端一致；需求状态（若有）读取与员工端共享的同一份值，含「需求状态」标签；备注内容按权限脱敏；记录不存在时提示“记录不存在或已删除”。

### 5.6 团队员工详情页


#### 1. 页面定位

团队长从团队模块穿透查看员工经营上下文的只读页。该页复用员工版已评审通过的展示板块，不重写员工版业务流程，不提供代员工操作能力。

#### 2. 页面入口

- 完整排名点击员工。
- 上报需求详情点击员工。
- 过程记录点击员工。
- 拜访详情点击员工。
- 星级渠道详情经「员工」筛选定位（列表不展示员工姓名列；行点击为展开渠道详情卡片，不再穿透员工详情）。

#### 3. 页面目标

- 让团队长在一个页面内看清员工重点关注、渠道、拜访、需求四类上下文。
- 与当前 demo 闭环：沿用员工版对应板块的展示形态，团队长视角统一只读。
- 隔离员工侧行为数据：团队长浏览和点击不计入员工行为统计，不消费员工消息，不修改员工业务状态。

#### 4. 页面模块说明

##### 员工详情顶部
**模块作用**：标识团队长当前穿透查看的员工对象。  
**展示内容**：页面标题“员工详情”、被查看员工姓名、被查看员工所属团队、返回按钮；页面不展示“只读”文字标识。
**交互说明**：点击返回关闭员工详情页并回到来源页面；返回后保留来源页面筛选条件、选中状态和滚动位置。  
**备注**：被查看员工 ID 不等于当前登录人 ID 时，页面固定为只读；团队长本人业务通过顶部角色切换图标返回员工版处理。

##### 员工详情快捷导航
**模块作用**：在员工详情页内快速定位员工重点关注、渠道、拜访和需求信息。  
**展示内容**：重点关注、我的渠道、渠道拜访三个导航项；需求跟进并入渠道拜访区。页面不显示“只读”文字，通过隐藏编辑建码、打卡、提交拜访、修改需求状态等写入口体现只读。  
**交互说明**：点击“重点关注”“我的渠道”“渠道拜访”滚动至对应模块顶部；需求跟进随渠道拜访区展示；手动滚动时同步高亮当前模块。需求详情依据当前角色与被查看员工 ID 渲染操作区：团队长为“归档 / 标记跟进”，员工本人为“取消 / 保存更新”。  
**备注**：导航项顺序必须与员工详情页模块顺序一致；目标模块为空时仍滚动到空态位置。

## 6. 通用能力说明

### 6.1 角色切换能力

#### 能力定位

支持团队长在团队版和员工版之间切换，且保证团队视角与本人业务视角边界清晰。

#### 适用页面

- 员工版主工作台顶部。
- 团队版主看板顶部。
- 顶部角色切换能力。

#### 能力说明

- 员工版不展示角色切换入口。
- 团队长版右侧展示角色切换按钮，可切换至员工版/团队长版。
- 切换至员工版时使用团队长本人的员工身份。

#### 交互规则

- 从团队版回到员工版时恢复进入团队版前的员工版上下文。
- 从员工穿透页返回团队页时恢复来源页筛选和滚动位置。
- 返回本人员工视角时不得携带 viewedEmployeeId。

#### 状态同步要求

员工版和团队长版共享登录态；员工版不展示角色切换入口。团队长版查看员工数据时必须携带 viewedEmployeeId；通过团队长版右侧按钮切换至本人员工视角时必须使用 currentUserId。

### 6.2 筛选与排序能力

#### 能力定位

支持团队长在列表和排名场景中快速定位目标员工、网点、状态、指标和记录类型。

#### 适用页面

- 团队重点关注。
- 上报需求列表。
- 超时关注列表。
- 团队总览与完整排名。
- 星级渠道详情。
- 过程详情列表。
- 团队拜访记录。

#### 能力说明

- 周期筛选支持昨日、本周、自然月、本年、考核月五类，五个选项在同一控件内并列互斥单选；「考核月」为并列新增项，口径为考核账期（T-1 月 16 日 ~ T 月 15 日，含当日）。点选「考核月」后弹出「选择考核期次」列表：近 6 期（当期在最上、往期依次向下），每行左侧为日期区间、右侧为状态徽标（当期＝蓝色「进行中」、往期＝灰色「已结束」）、选中行显示勾选图标；首次进入默认高亮「当期（进行中）」。选定后控件回显「考核月」并在旁标注所选期次「区间 · 状态」（如 `10/16–11/15 · 进行中`），该标注仅呈现考核账期区间、不出现“数据截至 …”文案；切回自然历口径时标注消失。期次记忆：再次打开列表高亮上次所选期次，切走到其它周期再切回「考核月」仍保留所选期次。周期状态记忆范围：团队总览与团队总览详情（完整排名）共用、星级渠道与星级渠道详情共用、过程跟进与过程跟进详情各自独立、员工详情「我的渠道」与员工端「我的渠道」跨端共用；从上游页进入二级页时继承上游周期与所选期次（如团队总览→完整排名）。
- 状态筛选支持上报需求状态和超时提醒状态。
- 维度筛选支持按员工和按网点；网点筛选经"网点选择弹层"完成，支持在弹层内按银行大类（银行品牌）与关键字过滤（搜索 × 大类取交集）。
- 过程详情使用周期、员工、网点筛选，并通过顶部 Tab 切换记录类型；星级渠道详情使用周期、员工和星级筛选。

#### 交互规则

- 筛选条件变化后刷新当前列表。
- 从详情返回列表时保留筛选条件和滚动位置。
- 排序支持记录日期升序、记录日期降序、超时天数升序、超时天数降序、指标值降序。

#### 状态同步要求

筛选状态在当前页面内保持；切换主模块时不带入其他模块筛选条件。

### 6.3 Toast、弹层与底部面板能力

#### 能力定位

统一团队长版管理动作反馈，降低误操作。

#### 适用页面

- 上报需求详情。
- 超时关注列表。
- 团队版主看板。
- 员工详情页。

#### 能力说明

- Toast 用于保存成功、校验失败、提醒成功、加载失败四类轻量反馈。
- 一键提醒不使用 Confirm 弹层，点击后直接发送。
- 上报需求归档不使用归档原因弹层。
- Loading 和骨架屏用于页面或列表加载。

#### 交互规则

- 管理动作成功后展示成功 Toast。
- 管理动作失败后保留当前页面状态并展示失败 Toast。
- 归档和一键提醒均不二次确认。
- 弹层关闭后返回触发前上下文。

#### 状态同步要求

管理动作成功后刷新首页预览、列表和详情状态。

### 6.4 只读与权限控制能力

#### 能力定位

确保团队长能查看团队员工数据，但不会代员工修改个人业务数据。

#### 适用页面

- 员工详情页。
- 员工渠道只读详情。
- 员工拜访只读详情。
- 员工需求只读详情。

#### 能力说明

- 团队长可查看辖内员工聚合数据和明细数据。
- 团队长员工详情页复用员工版重点关注、我的渠道、渠道拜访的展示能力，需求跟进并入渠道拜访区。
- 团队长团队视角不可编辑员工建码信息、不可提交员工拜访记录、不可保存员工需求状态、不可消费员工消息。
- 团队长本人业务操作仅在通过角色切换返回的员工视角中开放。

#### 交互规则

- 只读页不展示打卡、定位、编辑建码、新增关键人、删除关键人、提交拜访、编辑需求、保存需求状态按钮。
- 管理动作如标记跟进、归档、一键提醒属于团队长权限，可在团队重点关注内操作。
- 查看敏感字段需按权限脱敏。
- 团队长查看员工详情产生的页面行为不计入员工行为数据，不更新员工侧页面统计和业务指标。

#### 状态同步要求

权限状态由登录态、团队关系和被查看对象共同决定；团队视角始终只读员工数据，点击角色切换返回本人员工视角后才开放本人写操作。

### 7.14 员工填报内容落表要求

员工在 H5 中手工填写、选择、提交的业务内容需要进入对应业务表，用于后续查看、团队汇总、重点关注规则和审计追溯。团队版只读引用员工侧业务表，不重复保存员工填写的原文内容。

| 填报场景 | 需落表内容 | 建议落表对象 | 备注 |
|----------|------------|--------------|------|
| 渠道/网点维护 | 网点名称、银行、支行、地址、建码日期、星级、归属员工等 | Network | 员工维护后用于我的渠道、团队星级渠道和排名穿透 |
| 关键人维护 | 关键人角色、姓名、电话、生日、备注等 | Contact | 电话、生日、备注为敏感字段；可入业务表，埋点不上传原文 |
| 拜访打卡 | 打卡时间、网点、经度、纬度、定位状态、提交时间等 | VisitRecord | MVP 不做强 GPS 判定，但需记录可采集到的经纬度和定位状态 |
| 拜访记录补充 | 银行需求类型、需求挖掘内容、达成合作类型、拜访备注等 | VisitRecord/Demand | 拜访中产生的需求可同步生成或关联 Demand |
| 活动记录 | 活动日期、开始时间、结束时间、活动类型、参与人数、新增开户数、活动备注等 | ActivityRecord | 活动备注为敏感字段；埋点不上传原文 |
| 需求记录 | 需求描述、紧急程度、当前状态、解决方案、所属网点、来源拜访记录等 | Demand | 需求描述和解决方案为敏感字段；团队上报只引用 Demand，不重复保存原文 |
| 需求状态更新 | 已满足、未满足、无法满足等状态及更新时间 | Demand | 需求状态是原始业务状态（与员工端共享同一份值），团队长处理状态单独保存在 ReportDemand |

落表处理要求：
- 员工点击保存/提交后，前端应调用对应业务保存接口；保存成功后再刷新列表、详情和团队侧只读数据。
- 业务表需记录创建人、创建时间、更新人、更新时间，便于追溯。
- 敏感原文可以进入业务表，但不进入埋点；团队长查看时按权限脱敏展示。
- 页面筛选条件、页签状态、排序状态、临时勾选状态不作为员工填报业务内容落表。
- 由规则计算得到的数量、排名、超时天数、是否可提醒等为计算结果，不替代员工原始填报数据。

## 8. 状态与规则说明

### 8.1 业务规则

上报需求按“新上报 → 跟进中 → 已归档”单向流转；新上报不可直接归档。超时关注与员工版重点关注统一为网点降级、未拜访、生日提醒、需求未满足四类。

- 团队长团队视角只读员工业务数据，不代员工提交打卡、拜访记录、建码信息和需求状态。
- 员工侧需求满足上报规则时进入团队长上报需求列表；上报规则由员工版 PRD 和后端规则引擎负责。
- 团队长标记跟进和归档只更新团队长处理状态，不覆盖员工需求原始状态。
- 超时关注由团队侧内部规则池 `TeamTimeoutAttention` 生成，团队长版只展示、筛选、提醒，不打开员工消息详情页。
- 今日已提醒及冷却期内事项不可重复提醒。
- 团队长本人业务通过角色切换图标进入员工版流程，使用团队长本人的员工 ID。
- 团队长查看员工详情只产生管理视角访问，不计入被查看员工的行为数据、业务状态和过程指标。

### 8.2 用户权限规则

角色切换返回团队长本人员工视角；员工穿透页隐藏所有写入口。需求详情操作区必须同时校验当前角色与被查看员工 ID。

| 角色 | 可查看 | 可操作 | 可管理 |
|------|--------|--------|--------|
| 零售团队长-团队视角 | 辖内员工聚合指标、关注事项、拜访记录、需求记录、员工详情 | 查看、筛选、排序、进入详情 | 标记上报需求跟进、归档、一键提醒员工 |
| 零售团队长-员工视角 | 通过角色切换返回的本人工作台 | 本人打卡、建码编辑、拜访提交、需求状态更新 | 不影响他人员工数据 |
| 零售客户经理 | 本人工作台、本人渠道、本人拜访、本人需求 | 本人业务操作 | 无团队管理权限 |

### 8.3 数据同步规则

- 员工提交拜访记录后，团队版过程跟进和拜访记录需同步。
- 员工需求满足上报规则后，团队版上报需求列表和团队重点关注入口需同步生成或更新。
- 团队长标记上报需求跟进后，团队重点关注首页、上报需求列表和详情需同步。
- 团队长归档上报需求后，默认首页和“全部”列表不展示该事项，已归档筛选中可查看。
- 团队长完成一键提醒后，超时关注列表中对应事项变为已提醒，并记录提醒次数和最后提醒日期。
- 员工消息盒子消息生命周期由消息盒子后台负责；团队长查看员工重点关注不消费员工消息。
- 团队超时关注由 `TeamTimeoutAttention` 独立生成和流转；团队长一键提醒不改变员工消息盒子的已读、消失或详情访问状态。
- 团队长查看员工详情不触发员工版数据同步；不更新员工消息已读、拜访次数、需求处理数、渠道维护记录。

### 8.4 团队超时关注生成与提醒规则

团队超时关注覆盖网点降级、未拜访、生日提醒、需求未满足四类；提醒无需二次确认，今日已提醒项不可重复选择。团队未读红点独立维护，不得消费员工消息。

| 规则项 | 规则说明 |
|--------|----------|
| 生成范围 | 本期生成网点降级、生日提醒、未拜访、需求未满足四类团队超时关注。 |
| 生日当天 | 关键人生日等于当前日期时生成 `birthday_today`；当天结束后自动停止展示；当天最多提醒 1 次 |
| 未拜访 | 网点未拜访满 35 天生成 `no_visit_timeout`；员工完成有效拜访后停止展示；团队长提醒后 7 天内不可重复提醒 |
| 需求未满足 | 需求状态为“未满足”、未上报且未满足满 12 天生成 `unmet_demand_timeout`；需求已上报、已满足、已失效或已关闭后停止展示；团队长提醒后 3 天内不可重复提醒 |
| 待提醒判断 | `canRemind=true` 且未处于今日已提醒/冷却期时，可勾选并一键提醒 |
| 已提醒判断 | 提醒成功后写入 `lastRemindTime`、`nextRemindTime`、`remindCount`、`remindedBy`；列表展示为已提醒或冷却中 |
| 去重规则 | 同一 `employeeId + attentionType + sourceBizId` 在同一有效周期内只保留一条有效记录 |
| 详情边界 | 团队长超时关注不进入员工消息详情页，不消费员工消息；仅作为管理提醒列表使用 |

### 8.5 提示反馈规范

一键提醒成功 Toast 为“已发送提醒”；前台不再出现归档原因必填及归档确认提示。

| 操作 | Toast 文案 |
|------|------------|
| 团队看板加载失败 | 团队看板加载失败，请稍后重试 |
| 上报需求标记跟进成功 | 已标记为跟进中 |
| 上报需求归档成功 | 已归档 |
| 未选择待提醒事项 | 请选择待提醒事项 |
| 一键提醒成功 | 已发送提醒 |
| 一键提醒失败 | 提醒发送失败，请重试 |
| 今日重复提醒 | 今日已提醒，无需重复提醒 |
| 员工详情加载失败 | 员工详情加载失败 |
| 无团队版权限 | 暂无团队版权限 |

### 8.6 空态规则

- 团队重点关注无数据：展示“暂无重点关注事项”。
- 上报需求无数据：展示“暂无上报需求”。
- 超时关注无数据：展示“暂无超时关注”。
- 团队总览无数据：展示“暂无团队数据”。
- 完整排名无数据：展示“暂无排名数据”。
- 星级渠道无数据：展示“暂无星级渠道数据”。
- 过程记录无数据：展示“暂无过程记录”。
- 员工详情无数据：各模块展示对应空态。

## 9. 埋点设计

### 9.1 命名规则

- event_name 统一使用通用事件类型：`rc_view` 表示页面浏览，`rc_click` 表示页面点击，`rc_show` 表示页面曝光或弹层曝光，`rc_result` 表示操作结果。
- page_name 使用 `rc_ + 角色 + 页面`，例如 `rc_staff_home`、`rc_team_home`、`rc_team_demand_detail`、`rc_team_timeout_attention_list`。
- module_name 使用 `rc_ + 角色 + 模块`，例如 `rc_team_attention_module`、`rc_team_rank_module`、`rc_staff_visit_form_module`。
- element_name 使用业务对象 + 动作，例如 `switch_team_click`、`demand_filter_click`、`timeout_remind_confirm_click`、`visit_submit_result`。
- 业务字段不通过埋点保存；拜访对象、需求挖掘、合作内容、备注、经纬度进入业务字段或业务表。
- 埋点只记录页面浏览、点击、曝光、操作结果，不上传手机号、生日、备注、需求描述、解决方案、GPS 经纬度原值。

### 9.2 标准字段

| 字段 | 英文字段名 | 说明 |
|------|------------|------|
| 事件类型 | event_name | rc_view/rc_click/rc_show/rc_result |
| 页面名称 | page_name | 英文页面标识 |
| 模块名称 | module_name | 所属模块 |
| 按钮名称 | element_name | 触发点击控件 |
| 按钮位置 | location | 控件位置 |
| 前向页面 | from_page | 用户来源页面 |
| 去向页面 | page_to | 跳转目标 |
| 平台 | platform | h5/wx_work |
| 用户角色 | role | manager |
| 团队 ID | team_id | 团队版使用 |
| 被查看员工 ID | viewed_employee_id | 员工穿透使用 |
| 备注 | remarks | 补充说明，不放敏感原文 |

### 9.3 隐私字段标注

以下字段不得明文进入埋点：

- 关键人完整手机号。
- 关键人生日。
- GPS 原始经纬度。
- 客户姓名、客户账号、手机号、证件号。
- 需求描述、拜访备注中的客户资源明细。
- 解决方案中的敏感经营策略原文。

### 9.4 埋点表

角色图标切换、导航拖拽结束、未读红点查看、标记跟进、归档、排序三态、超时事项选择/全选/一键提醒、排名维度切换、星级条目点击、星级渠道卡片展开、过程 Tab、日期详情及员工穿透均需沿用现有命名规则补充事件；不得上报员工填报原文或个人敏感信息。

#### 团队员工详情埋点

| 事件名称 | event_name | page_name | module_name | element_name | location | from_page | page_to | 备注 |
|----------|------------|-----------|-------------|--------------|----------|-----------|---------|------|
| 员工详情浏览 | rc_view | rc_team_employee_detail | rc_team_employee_drilldown_module | - | - | rc_team_rank_detail/rc_team_demand_detail/rc_team_process_list/rc_team_visit_detail | - | 团队长侧访问事件，上报 viewed_employee_id、from_page；不计入被查看员工行为数据；星级渠道详情不再作为来源页 |

### 9.5 埋点设计规则

1. 页面分析必须携带 view 事件。
2. 筛选类事件在选择完成后上报，不在输入过程中逐字上报。
3. 需求描述、解决方案、拜访备注只上报 ID 和状态，不上报原文。
4. 同一按钮多入口保持 element_name 一致，通过 page_name 和 from_page 区分上下文。
5. 团队长查看员工详情时，仅保留员工详情浏览事件；详情页内导航、列表点击、只读详情查看不做员工行为埋点。
6. 团队长访问审计与员工行为数据分表或分口径存储，不参与员工页面点击、拜访、需求、消息消费统计。


> **产品口径**：超时关注包含网点降级、未拜访、生日提醒、需求未满足四类；拜访需求选项统一使用“渠道关键人赋能”。

## 10. 功能实现、验收标准与里程碑

### 10.1 功能实现清单

- [ ] 员工版不展示角色切换入口；团队长版右侧按钮可切换至员工版/团队长版。

- [ ] 超时关注支持网点降级、生日提醒、未拜访、需求未满足四类事项；已上报需求不重复进入超时关注。

- [ ] 今日已提醒及冷却期内事项不可重复提醒。
- [ ] 团队总览展示新增资产、有效户、开户数、渠道数、经营积分五类指标。
- [ ] 完整排名支持按员工、按网点查看。
- [ ] 团队星级渠道支持一星至五星分布和明细查看。
- [ ] 团队过程跟进支持过程指标和明细列表。
- [ ] 团队拜访记录支持日历查看和详情查看。
- [ ] 团队长可从团队模块进入员工详情。
- [ ] 员工详情按只读模式复用重点关注、我的渠道、渠道拜访，需求跟进并入渠道拜访区。
- [ ] 员工详情内团队长浏览和点击不计入被查看员工行为数据。
- [ ] 团队长通过角色切换返回员工版，并按本人身份复用员工业务流程。

#### 核心业务闭环

员工产生符合上报规则的需求 → 团队长在团队版看到上报需求 → 团队长标记跟进或归档 → 团队重点关注、列表、详情状态同步。  
团队侧规则池生成超时关注 → 团队长筛选待提醒事项 → 勾选事项 → 一键提醒 → 今日已提醒及冷却期内事项禁用重复提醒；全流程不打开员工消息详情页、不消费员工消息。

### 10.2 验收标准

逐项验证统一标题、角色图标切换、导航拖拽防误触、上报需求状态机、团队红点隔离、四类超时关注、AI问案例、直接提醒、排名联动、星级条目点击、四 Tab 与状态保持、日期详情、员工穿透只读及角色化需求操作；未涉及能力按 v0.2 原验收标准执行。

| 功能点 | 验收标准 |
|--------|----------|
| 团队版加载 | 团队长进入 H5 后可看到团队重点关注、团队总览、星级渠道、过程跟进、拜访记录 |
| 角色切换 | 员工版无切换入口；团队长版右侧按钮可切换至员工版/团队长版。 |
| 切换至员工版 | 团队长版右侧按钮切换至员工版后，使用团队长本人的员工身份 |
| 团队重点关注 | 团队版可切换上报需求和超时关注，并展示数量和列表 |
| 上报需求处理 | 新上报必须先标记跟进，跟进中才可直接归档；不选择归档原因、不二次确认 |
| 超时关注生成 | 生日当天、未拜访满 35 天、未满足且未上报需求满 12 天可进入超时关注；网点降级、已上报需求不进入超时关注 |
| 超时一键提醒 | 勾选待提醒事项后点击一键提醒直接发送，Toast“已发送提醒”，并写入最后提醒时间和下次可提醒时间 |
| 重复提醒限制 | 今日已提醒或处于冷却期的事项不可再次勾选提醒 |
| 消息详情边界 | 团队长点击超时关注不进入员工消息详情页，不消费员工消息盒子消息 |
| 团队总览 | 周期切换后团队指标和排名同步刷新 |
| 完整排名 | 可按员工和网点切换，点击员工进入员工详情，按网点整行展开渠道详情卡片 |
| 星级渠道 | 点击星级条目进入星级渠道详情并预置星级；无数据星级不可点；详情页可切周期/员工并展开渠道详情卡片 |
| 过程跟进 | 点击过程指标可进入对应明细列表，筛选后列表刷新 |
| 拜访记录 | 点击日历日期可查看当日记录，点击记录进入只读详情 |
| 员工详情只读 | 团队长查看员工详情时不出现代员工打卡、编辑建码、提交记录、保存需求状态写操作 |
| 员工详情复用 | 员工详情复用员工版重点关注、我的渠道、渠道拜访的展示样式，需求跟进并入渠道拜访区，不复制员工版写流程 |
| 员工详情数据隔离 | 团队长查看员工详情不消费员工消息，不改变员工 H5 消息展示，不计入员工行为数据和业务指标 |
| 本人业务 | 团队长通过角色切换返回员工版，按本人身份打卡和维护需求 |

### 10.3 核心场景验收路径

1. 团队看盘路径：从统一工作台进入团队长版 → 查看重点关注 → 查看团队总览 → 切换周期 → 打开完整排名 → 按员工/网点切换。
2. 上报需求路径：团队版重点关注 → 上报需求 → 查看全部 → 打开新上报需求 → 标记跟进 → 返回列表状态为跟进中 → 直接归档，不填写归档原因、不二次确认。
3. 超时提醒路径：团队版重点关注 → 超时关注 → 查看全部 → 筛选待提醒 → 勾选事项 → 一键提醒 → Toast“已发送提醒”→ 状态更新为已提醒，员工消息详情状态不变化。
4. 星级渠道路径：团队版星级渠道 → 切换周期 → 点击三星条目 → 进入星级渠道详情 → 筛选员工/星级 → 点击网点行展开渠道详情卡片 → 返回团队版。
5. 过程记录路径：团队版过程跟进 → 点击拜访次数 → 进入过程详情列表 → 筛选员工 → 点击记录进入只读详情。
6. 员工穿透路径：完整排名点击员工 → 员工详情 → 查看重点关注、我的渠道、渠道拜访及需求跟进只读信息 → 返回团队版。
7. 本人业务路径：团队版点击角色切换图标 → 返回员工版 → 点击我要拜访 → 以团队长本人身份进入拜访流程。

### 10.5 风险提示

| 风险 | 影响 | 应对 |
|------|------|------|
| 员工版和团队版数据口径不一致 | 团队长看到的聚合数据与员工侧明细对不上 | 指标口径、周期规则和计算源在接口层统一 |
| 团队长误操作员工数据 | 员工记录被错误修改 | 员工详情强只读，写操作仅在角色切换后的本人员工视角开放 |
| 上报需求状态边界不清 | 团队处理动作覆盖员工原始需求状态 | 团队长处理状态和员工需求状态分字段存储 |
| 超时提醒重复发送 | 打扰员工并降低提醒可信度 | 今日已提醒事项禁用，记录 lastRemindDate 和 remindCount |
| 敏感字段暴露 | 产生合规风险 | 手机号、生日、GPS、需求备注字段脱敏，埋点不上传原文 |
| 角色切换状态丢失 | 用户回到员工版后上下文丢失 | 进入团队版前记录员工版周期、网点筛选和滚动位置 |
