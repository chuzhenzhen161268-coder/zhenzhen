## 第 2 章：项目背景与目标

### 2.1 背景

为解决银行渠道精耕过程中，员工经营渠道相关数据和功能入口分散的问题，规划建设「零售员工端渠道经营视图」，作为年度零售渠道数字化经营建设的重点方向。经过多轮迭代，当前版本（HTML v8）已在首版 PRD 基础上扩展了多项核心能力，本文档作为现阶段实现状态的完整归档与迭代依据。

### 2.2 核心目标

- **聚合化**：实现渠道经营数据与过程数据的统一呈现，5 大模块单页直达，减少跨系统操作切换耗时 60% 以上。
- **标准化**：规范渠道拜访、需求采集与跟进的标准化作业流程（GPS 打卡 + 选择题表单），拜访记录完成率提升至 90%。
- **赋能化**：集成知识库（展业资料 + 优秀案例）与工具库，员工获取展业参考资料的平均时长压缩至 30 秒内。
- **闭环化**：异动提醒 → 拜访行动 → 需求跟进 → 上报协同，形成完整业务闭环，紧急需求当日响应率达 95%。

### 2.3 非目标（本版本不解决）

- 团队长汇总视图（团队维度数据汇总）
- 渠道星级自动评级算法（本版展示数仓同步结果）
- 知识库后台内容管理（后台 CMS 另立项）
- 离线模式（弱网兜底）

### 2.4 MVP 上线时间

2026-06-30（H5 移动端）

## 第 3 章：用户角色与使用场景

### 用户角色

| 角色 | 岗位/职责 | 核心诉求 | 使用频率 |
|------|-----------|----------|----------|
| 零售客户经理 | 负责维护多个银行网点渠道关系，日常外勤拜访为主 | 快速完成打卡记录、查看渠道异动、管理需求跟进 | 日常（每工作日） |
| 团队长 | 管理辖内多名客户经理，关注团队整体渠道指标 | 接收员工上报的紧急需求，查看汇总数据 | 周期性（后续版本） |

### 核心使用场景

**场景 1：外勤拜访打卡**  
**背景**：员工到达银行网点后需完成打卡并记录拜访内容。  
**操作路径**：首页「渠道拜访」模块 → 点击「我要拜访·立即打卡」→ 在打卡页**内联的网点选择区**（输入框 + 「附近网点」/「搜索结果」）点选网点，或输入未录入网点名称（点「立即打卡」后二次确认）→ 点击打卡并同步采集经纬度信息（采集失败不阻断）→ 选择「立即填写」或「稍后补充」→ 完成拜访表单提交。  
**期望结果**：拜访记录保存，记录打卡地点、打卡时间、经纬度采集结果和采集状态，日历打点更新，需求自动流入需求跟进表。

**场景 2：查看渠道异动**  
**背景**：员工上班首先查看当日有无需要重点关注的渠道异动。  
**操作路径**：首页「重点关注」模块 → 查看重点关注摘要 → 点击「查看全部」进入全部异动列表 → 点击网点降级/未拜访/生日提醒进入 H5 消息详情页，点击需求未满足进入 H5 需求详情页。  
**期望结果**：员工快速了解渠道风险点和待跟进需求；消息盒子下发类消息查看详情后从当前列表消失，需求未满足事项按需求状态持续展示或停止展示。

**场景 3：渠道建联信息管理**  
**背景**：员工需要查阅或更新某网点的关键人信息。  
**操作路径**：「我的渠道」→ 网点模糊搜索选择具体网点 → 查看建码卡片（关键人、生日、联系方式）→ 点击「编辑」→ Bottom Sheet 中增删改关键人信息（含生日）→ 保存。  
**期望结果**：建联信息实时更新，关键人生日提醒自动展示。

**场景 4：需求跟进与上报**  
**背景**：员工在拜访后收到紧急需求，需要录入并跟进。  
**操作路径**：拜访表单填写银行需求挖掘 → 需求是否满足选择“未满足”或“无法满足” → 按页面条件填写紧急程度与解决方案 → 提交 → 符合上报条件时系统自动推送企微消息至团队长 → 后续在「需求跟进表」中编辑解决方案并更新状态。
**期望结果**：紧急需求自动触达团队长，需求全生命周期可追踪。

**场景 5：知识库检索**  
**背景**：员工在拜访中遇到银行方的具体需求，需要快速匹配解决方案。  
**操作路径**：拜访表单“银行需求挖掘”模块点击「AI问案例」→ 输入关键词 → 匹配知识库案例/SOP → 引用到解决方案备注。
**期望结果**：快速获得可操作的解决方案参考，降低员工思考成本。

## 第 5 章：页面详细说明

### 5.1 主页面（首页）


#### 1. 页面定位
工作台核心承载页，汇聚5大功能模块于单一滚动视图，通过固定顶部 Tab 锚点导航实现快速定位。

#### 2. 页面入口
- 应用启动默认进入（唯一主入口）

#### 3. 页面目标
- 让员工在一个页面内完成日常经营所需的信息查阅与核心操作触达，无需跳出工作台框架。

#### 4. 页面模块说明

**4.1 顶部 Header**  
**模块作用**：展示工作台名称。  
**展示内容**：页面标题“零售银行渠道经营工作台”。员工版不展示员工头像、姓名及右侧角色切换按钮，不提供员工版/团队长版切换入口。  
**交互说明**：无。

**4.2 顶部 Tab 导航（qnav）**  
**模块作用**：5大模块的快捷锚点导航  
**展示内容**：重点关注 / 我的渠道 / 渠道拜访 / 知识库 / 工具库

**4.4 【我的渠道】模块**  
**模块作用**：渠道经营数字化看板  
**展示内容（由上至下）**：① 时间周期下拉（昨日/本周/自然月/本年/考核月）+ 默认值为“全部网点”的网点选择器；② 建码卡片（选中具体网点时显示“建码 YYYY-MM-DD · 已 N 天”）；③ 经营数据统计卡片（全部网点态 5 项，单网点态 4 项）；④ 一至五星渠道星级水平条形图，点击有数据的星级进入「渠道星级详情页」（§5.13），不展示额外汇总摘要数据。  
**页面级选择状态**：本模块顶部的「时间周期」与「网点选择器」为**页面级**选择状态，除驱动「我的渠道」自身各项外，同时驱动同页「过程跟进」模块四格（周期 + 网点双维联动，聚合键 `userId + 周期 + networkId`）。

**网点选择弹层**  
**模块作用**：在数百个、跨多家银行的网点中快速定位目标网点。弹层自底部弹出，高度 90%，头部（搜索框 + 银行大类 chips）固定，列表区内部滚动；弹层内为当前用户可见范围内的**全量网点**。

**展示内容与交互规则**：
1. **搜索框**：输入关键字对网点名称做跨银行模糊匹配；已选中某银行大类时，仅在所选大类内匹配。
2. **银行大类 chips**：即"银行品牌"（取自网点对象的 `bankBrand` 字段）。按固定优先级排序展示：国有大行 → 股份制 → 城商/农商；默认铺满 3 行，超出部分收进末尾「更多 ∨」标签，点击展开后 chips 区**内部滚动**展示全部大类，可再次收起。默认选中「全部」。
3. **最近选择（置顶区）**：展示本设备最近选中的 5 个网点；无历史记录时该区域不展示。数据存本机（localStorage），不跨设备同步。
4. **网点列表**：保持「全部网点」置顶；其后按当前搜索词与大类的过滤结果展示；点击任一网点即选中并回填筛选条件、关闭弹层。
5. **交集规则**：搜索词与银行大类为交集（AND）关系——结果为「所选大类内、名称匹配关键字的网点」。
6. **空态兜底**：交集为空时展示空态，并提供「清除大类，在全部大类中搜索」操作；点击后大类回到「全部」、保留搜索词重新匹配。
7. **回退规则**：点遮罩或关闭按钮关闭弹层，不改变已选网点值；重新打开弹层时，搜索词与大类均回到默认态（全部 + 空）。

> 本弹层为「我的渠道」网点选择、「需求跟进表」网点筛选共用的同一实现。
>
> **打卡页不使用本弹层**：员工端「我要拜访」打卡页的地点选择为**页内内联**（输入框 + 「附近网点」/「搜索结果」+ 未匹配兜底 + 已选态收起；无大类筛选、GPS 附近网点、归属标签、本人名下优先、不提供「全部网点」伪项）。其中"归属标签 / 本人名下优先 / 就近展示"的口径应用于打卡页内联区（见 §5.3 流程 1、§5.4 4.1/4.2）。**上列 1-7 条口径服务「我的渠道」「需求跟进表」两个入口。**

生日提醒徽章规则：

| 距离生日天数 | 徽章样式 | 颜色 |
|-------------|----------|------|
| 0天（今天） | 🎂 今天生日（闪烁动画） | 橙色 |
| 1-7天 | 🎂 N天后生日 | 橙色 |
| 8-30天 | 🎂 N天后 | 绿色 |
| >30天 | 🎂 M月D日 | 灰色 |
| 未填写 | 不显示 | — |

**数据统计卡片（stat-card）**：全部网点态展示 5 个固定指标（新增资产 / 新增有效户 / 新增开户数 / 名下渠道数 / 渠道经营积分），单网点态展示 4 项（隐藏「名下渠道数」）；每项包含标签、数值、单位和环比趋势（↑红/↓绿/—灰）。「名下渠道数」为员工级结构性指标，在网点维度下不成立，故单网点态不展示；清回「全部网点」恢复 5 项。  
**渠道星级分布**：一至五星横向条形图，条形宽度按占比渲染，各星级使用不同颜色；有数据的星级整行可点击，点击进入「渠道星级详情页」（§5.13）；无数据的星级不可点击。不再内联展开网点列表，不展示额外汇总摘要数据。

#### 5. 页面交互流程

**流程 1：切换网点查看建码卡片**  
点击网点选择框（默认“全部网点”）→ 网点选择弹层打开（默认「全部」大类 + 空搜索，展示全量网点列表）→ 输入关键字跨大类匹配，或点选「银行大类」chips 缩小范围（二者取交集；交集为空时出现空态与「清除大类，在全部大类中搜索」兜底）→ 点击具体网点选中、弹层关闭并回填 → 建码卡片出现 → 显示关键人信息和生日徽章；选中网点同步写入本机「最近选择」（下次打开弹层时置顶展示，最多 5 个）；编辑建码信息时不展示网点地址，关键人字段为职位、姓名、电话号码、生日、其它信息；点击“新增关键人”追加空白行，新增、删除、修改统一点击底部“保存”提交。

**流程 2：展开/收起重点关注**  
点击「展开全部」→ 列表展开（max-height 动画）→ 按钮变「收起」→ 再次点击收起

**流程 3：切换时间周期**  
点击时间周期下拉 → 选择昨日/本周/自然月/本年/考核月 → 数据统计卡片数值刷新；选「考核月」时弹层切换为「选择考核期次」列表（近 6 期含当期，默认当期并标注「进行中」），选定后控件回显「考核月」并旁标注所选期次区间与状态；同页「过程跟进」四格随同一周期同步刷新。

**流程 4：进入渠道星级详情页**  
点击渠道星级分布中有数据的星级条目 → 进入「渠道星级详情页」（§5.13）→ 展示该星级下的网点列表与星级变化图标，可切换周期与星级变化筛选；无数据的星级不响应点击。

### 5.2 【过程跟进】模块

#### 1. 页面定位

- 首页 Tab 导航「过程跟进」锚点
- 页面滚动自然到达

#### 3. 页面目标
- 让员工 5 秒内掌握当前所选周期的拜访与需求推进情况，快速定位需关注的滞后项。

### 5.3 【渠道拜访】模块（首页区域）


#### 1. 页面定位
渠道日常作业中枢，承载打卡入口、日历记录、需求跟进三大功能区，所有详细操作通过二级页面承载。

#### 2. 页面入口
- 首页 Tab 导航「渠道拜访」锚点
- 「过程跟进」模块拜访/活动数值点击跳转

#### 3. 页面目标
- 让员工在首页直接触达拜访打卡入口；快速浏览月度拜访日历；查看近期需求跟进状态。

#### 4. 页面模块说明

**4.1 打卡入口按钮**  
蓝底全宽按钮「我要拜访·立即打卡」，点击进入「我要拜访」二级页面（GPS 定位启动）。

**4.2 待补充记录横幅**  
触发条件：员工打卡后选择「稍后填写」。

**4.5 需求跟进区**

### 5.4 二级页面：我要拜访（MVP打卡 + 经纬度采集 + 拜访表单）



#### 1. 页面定位
外勤打卡与拜访记录的核心操作页，MVP 阶段保留现有前端交互和功能流程，点击打卡时尽量采集经纬度、定位精度和采集状态；定位失败不阻断员工继续选择拜访网点。

#### 2. 页面入口
- 首页「我要拜访·立即打卡」按钮
- 待补充横幅「去补充」按钮（直接跳至表单）

#### 3. 页面目标
- 让员工在2分钟内完成打卡+拜访记录全流程。
- MVP 阶段解决“可记录、可追溯、不中断”的问题：记录员工主动打卡时间、选择的拜访网点、可采集到的经纬度信息和采集状态；定位失败或授权失败不阻断打卡。

#### 4. 页面模块说明

**4.1 打卡位置区（MVP 方案）**

| 状态 | 触发时机 | 展示内容 | 用户操作 |
|------|----------|----------|----------|
| 默认态 | 进入我要拜访页 | 当前GPS定位卡片、网点选择区（输入框 + 「附近网点」按 GPS 距离升序取前 4，行带归属标签与 `≈xxm`） | 直接点选附近网点，或输入关键字搜索全部已录入网点 |
| 经纬度采集成功 | 浏览器/企微容器返回坐标 | 地图、经纬度、定位精度、采集时间、附近网点列表 | 可复制坐标，可继续打卡； |
| 经纬度采集失败 | 权限拒绝、容器限制、超时或环境不支持 | 展示「暂未获取GPS定位」和采集失败状态 | 选择拜访网点后继续打卡 |
| 网点搜索与未匹配 | 在网点选择区输入关键字 | 标题切为「搜索结果」：全部已录入网点、本人名下优先、行带归属标签（有距离数据时含距离）；**无命中时仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」**、不展示网点行 | 点选任一结果行即选中并收起；无命中时点「立即打卡」弹出「确认拜访该网点？」二次确认； |
| 已选网点 | 点选任一网点行 | 区域收起为「网点名 + 归属标签（未录入网点无） + 清除按钮」 | 点「立即打卡」：列表已选网点直接生成凭证；点已选区域可再展开改选；点「清除」回到未选态； |

**MVP 打卡判定**：员工选择拜访网点后，点击「立即打卡」即生成打卡记录。若可获取经纬度，则随记录提交；若无法获取，则记录 gpsStatus = failed / denied / unsupported / timeout，不阻断提交。

**打卡网点选择**：打卡地点在打卡页**页内选择、不使用弹层**——「选择拜访网点」处即为**输入框**，未输入时其下方直接按 GPS 距离升序列出「**附近网点**」（网点名 + 归属标签 + `≈xxm`）；输入关键字后列表标题切为「**搜索结果**」（命中全部已录入网点、**本人名下优先**、行带归属标签与距离）；关键字**未匹配到任何已录入网点**时结果区仅提示「**未匹配到系统已录入网点，将按所输名称作为未录入网点打卡**」。点选任一结果行 → 区域**收起为已选态**（网点名 + 归属标签 + 清除），点击已选区域可再次展开改选；点「清除」回到未选态。点「立即打卡」：**列表已选网点直接生成凭证**；**未录入网点（手输未匹配）弹出居中二次确认「确认拜访该网点？」**（含所输名称、「确认打卡／取消」；取消后关闭弹窗、停留打卡页并保留输入）；**未选且输入为空**时 Toast「请先选择拜访网点」，不生成凭证。**不再有"名称比对系统网点"式校验**，可拜访非本人名下网点（行内以灰色「非本人名下」标签标识）。

**4.2 打卡确认区**  
展示内容：地图、定位精度圆、当前经纬度、定位精度、采集时间和附近网点列表。员工在打卡页**内联网点选择区**点选网点（默认「附近网点」按距离升序、输入关键字切「搜索结果」，行带「本人名下 / 非本人名下」标签与距离，本人名下优先）；关键字无匹配时以所输名称作为未录入网点。  
交互：点选任一网点行后区域收起为已选态，点击「立即打卡」直接进入成功确认区；未录入网点（手输未匹配）点「立即打卡」时弹出居中二次确认「确认拜访该网点？」，点「确认打卡」后以所输名称（无归属标签）进入成功确认区；未选且输入为空时 Toast「请先选择拜访网点」，不得生成打卡凭证。

**4.3 打卡成功确认区**  
蓝色信息卡展示“打卡成功”、地点和完整时间，并列展示两个操作卡：  
“立即填写 / 趁热打铁，一次完成”→ 页面平滑滚动至拜访表单区域  
“稍后填写 / 生成待补充记录”→ 生成待补充记录，关闭二级页面，首页显示横幅。

**4.4 拜访表单（6个模块）**

| 题号 | 题目 | 题型 | 选项 |
|------|------|------|------|
| Q1 | 拜访对象 | 多选 / 手输 | 该打卡网点的**关键人多选**，选项呈现为「职位 + 姓名」（如「理财经理 王芳」）；已录入网点（不论本人名下 / 非本人名下）**只可勾选、不可在表单内新增关键人**；网点无关键人时展示空态提示（本人名下指向「我的渠道」维护 / 非本人名下仅提示）、**不展示「其他」按钮、直接展示拜访对象输入框**、该模块**为必填**（自由文本，为空则拦截提交并在该模块描红提示「必填未完成」）；当打卡网点为**未录入网点（手输未匹配）**时，改为展示空态说明 + **自由文本输入**（就地手输拜访对象，输入非空即满足必填），同样不展示任何补录入入口；已录入网点**在有关键人时**于关键人选项外附**「其他」按钮**（点选展开文本框输入拜访对象自由文本，仅记为本次记录、**不写入关键人档案**），**无关键人时不展示该按钮** |
| Q2 | 银行需求挖掘 | 两级分类多选 + 每标签选填描述 | 一级维度（职业需求 / 社会需求 / 个人需求）作为**外层表单卡片内的常驻分组块**（点大类标题进弹层，无「＋ 添加需求」按钮）；弹层只显示所点大类的二级指标（支持**类内搜索**、手工补充自定义项、勾选后即时填「描述（选填）」）；已选标签按大类归位展示、每个标签后跟各自选填描述；必填规则＝**仅至少选 1 项需求** + 「AI问案例」快捷入口； |
| Q3 | 达成合作内容 | 多选（选填） | 客户线索/资源互换/活动开展/晨夕会宣导/关键人开户/其他； |
| Q4 | 需求是否满足 | 单选+条件 | ✅ 已满足 / ⏳ 未满足 / 🚫 无法满足；必填 |
| Q5 | 需求是否紧急、解决方案 | 条件展示 | 已满足时隐藏且不参与校验；未满足/无法满足时展示，紧急程度与解决方案均必填； |
| Q6 | 其他拜访信息 | 选填 | 如有其他需要记录的拜访信息或潜客信息，请在此填写... |

自动触发规则：需求结果为未满足或无法满足时显示紧急程度和解决方案；满足条件的未满足需求提交后生成 Demand 记录并进入需求跟进，可在重点关注“需求未满足”中展示。隐藏字段不参与必填校验。

**Q1 拜访对象·关键人来源**：Q1 对象来源由静态角色枚举改为该打卡网点已录入的**关键人**（职位 + 姓名，多选）。**已录入网点（不论本人名下 / 非本人名下）一律不可在拜访表单内新增关键人**——Q1 只可勾选该网点已录关键人，关键人的增 / 改 / 删统一由「我的渠道 → 编辑建码信息」维护（仅本人名下网点开放，按「职位 + 姓名」去重）。**Q1「其他」按钮**：**该网点有关键人时**，已录入网点的 Q1 在关键人选项外附「其他」按钮，点选后展开文本框，员工可输入拜访对象信息（提示「请输入拜访对象信息（职位+姓名，多人可用顿号分隔）」）；该文本仅写入本次拜访记录快照、**不产生关键人档案新增 / 变更**，与勾选关键人并存时按顿号合并展示；**该网点无关键人时不展示该按钮、直接展示拜访对象输入框**；未录入（手输）网点不展示该按钮。**网点无关键人**时，Q1 展示空态提示「该网点暂无关键人，可前往『我的渠道』编辑建码信息补充」（非本人名下网点仅提示「该网点暂无关键人」），**不展示「其他」按钮、直接展示拜访对象输入框**（自由文本），因无可勾选项，该模块**为必填**（自由文本，为空则拦截提交并在该模块描红提示「必填未完成」）。提交时以**快照**固化本次拜访对象，关键人后续被删除 / 更名不影响已提交记录；存量历史记录保持原文本展示。**当打卡网点为未录入网点（手输未匹配、无关键人档案）时**：Q1 不展示关键人多选，改为展示空态说明「该网点未录入系统，请直接填写拜访对象」+ 自由文本输入框，输入非空即满足 Q1 必填。**标题提示文案统一**：Q1 标题「拜访对象」后的提示统一为**「（可拜访多个对象）」**，有关键人 / 无关键人 / 未录入手输三种状态一致；该文案同时适用于关键人多选与自由文本输入（文本态多人以顿号分隔）。

**Q2 银行需求挖掘·两级分类选择器**：「银行需求挖掘」由 10 项平铺 chip 改为**两级分类选择**——一级为需求维度（**职业需求 / 社会需求 / 个人需求**），**三个大类直接常驻平铺在表单卡片内作为分组容器**（非互斥；点击任一大类标题即拉起该类选择弹层，已选需求按所属大类归位展示在对应分组块下，**不设「＋ 添加需求」按钮**）；二级为该维度下的需求指标（源自《渠道信任经营 · 需求库速查（三维度）》46 项，按展示分组铺开、★常用项置前）。**选择器为半屏、只显示所点大类**：顶部搜索框在**当前大类内**匹配（不跨大类），底部为「已选摘要 + 确定（已选 N 项）」（空选置灰）；**勾选某项后该项下方即时出现「描述（选填）」输入框**；库中无对应项时走「**＋ 手工补充**」，自动挂靠当前大类、`grp` 记为"自定义"、打「自定义」标识（同大类重名或输入为空分别给 Toast）。表单卡片内，三个大类各为一块**浅灰底圆角分组卡片**（组头＝维度色圆点 + 大类名 + 「N 项」计数胶囊 + 右侧「＋ 添加」小按钮，未选时隐藏计数胶囊、按钮降级为灰色描边；组间留白分隔），已选需求按大类归入对应卡片（标签带维度色与「自定义」标识、可单个删除）；**每个标签下方的描述：有内容时直接显示带内容的描边输入框，为空时收起为浅色「＋ 描述（选填）」入口、点击展开为输入框**，可就地在卡片内填写 / 修改该需求的描述，与弹层内同项描述为同一份数据、双向同步。**维度三色规范**：职业需求 `#2B73FF`（蓝）/ 社会需求 `#8257E6`（浅紫）/ 个人需求 `#12A870`（浅绿）。**弹层内选项的选中态（边框 + 文字 + 底色）按当前大类取对应色**。**必填规则**：**仅要求至少选 1 项需求**；**「需求描述」为每个已选需求标签各自的选填描述**（校验未通过时模块卡片描红、聚焦并 Toast，选择需求后自动清除错误态）。修改态（拜访记录编辑）复用同一控件，已选需求及其描述按快照回显。存量历史记录保持原文本展示、不追溯改写，统计端归入「未分类」。

**4.5 编辑态：修改拜访记录**  
由「拜访详情」页点「修改」进入，复用同一套拜访表单：标题由「我要拜访」改为「**修改拜访记录**」；打卡凭证区（打卡网点 / 地点、打卡时间）**只读**展示、不可修改；6 个模块字段全部**预填原记录值**且可修改，条件必填与校验口径与新建一致，Q1 呈现复用同一套关键人多选规则（历史已固化的对象按快照回显）；底部操作由「放弃 / 提交完整记录」变为「**取消 / 保存修改**」；校验通过后覆盖原记录并返回详情页展示更新后内容，历史列表该行同步刷新。

#### 5. 页面交互流程

**流程 1：MVP 打卡并立即填写**  
进入页面 → 选择拜访网点 → H5 尝试采集定位结果 → 点击「立即打卡」→ 打卡成功 → 选择「立即填写」→ 完成6模块条件表单 → 点击「提交完整记录」→ Toast 反馈 → 关闭二级页面。

**流程 2：经纬度采集失败仍打卡**  
进入页面 → 经纬度采集失败或未授权 → 选择拜访网点 → 点击「立即打卡」→ 生成无GPS坐标打卡记录，记录 gpsStatus → 继续填写或稍后补充。

**流程 3：稍后补充**  
打卡成功 → 点击「稍后填写」→ 首页展示待补充横幅 → 点击「去补充」→ 恢复打卡记录并展示拜访表单。

**流程 4：修改拜访记录**

#### 10. 最终补充规则：全局待补充记录与提交校验

1. 打卡成功后仅生成“打卡凭证 / 待补充记录”，不生成正式拜访记录；该记录只表示员工已到访或已发起拜访动作，仍需补全表单。
2. 只有员工完成并提交完整拜访表单后，系统才生成正式拜访记录；正式拜访记录才进入历史拜访记录列表、日历记录、拜访详情页和后续统计。
3. 仅打卡但未填表单的记录不得出现在历史拜访记录列表中，也不得计入“已完成拜访记录”统计；只能出现在【渠道拜访】模块顶部的待补充队列中。
4. 待补充记录为全局队列，不按日历选中日期过滤；只要员工存在未补完整表单的打卡凭证，即在【渠道拜访】模块顶部展示。
5. 待补充记录按打卡日期时间倒序排列，最新一条默认展示在顶部；时间展示格式为 `YYYY/MM/DD` 与 `HH:mm:ss`。
6. 收起态只展示最新一条待补充记录；当存在 2 条及以上时，卡片底边中间展示向下小三角，点击后展开全部待补充记录。
7. 展开态展示全部待补充记录，每条记录样式一致：第一行 `YYYY/MM/DD 拜访记录待补充`，第二行 `银行名称 · HH:mm:ss`，右侧为 `去补充` 按钮。
8. 展开态底边中间展示向上小三角，点击后收起；小三角为浮层控件，不占用独立内容行。
9. 点击任一待补充记录的 `去补充`，进入该打卡凭证对应的拜访表单；提交完成后从全局待补充队列移除该条记录，并生成正式拜访记录。
10. 拜访记录表单包含 6 个模块：拜访对象、银行需求挖掘、达成合作内容、需求是否满足、需求是否紧急、其他拜访信息。拜访对象、银行需求挖掘、需求是否满足必填（其中「银行需求挖掘」需至少选 1 项需求、「需求描述」为每个已选需求标签各自的**选填**描述）；达成合作内容和其他拜访信息选填；需求是否紧急及解决方案按满足状态条件展示并在显示时必填。
11. 若任一当前可见的必填模块未完成，点击 `提交完整记录` 时阻止提交；未完成模块显示红色描边与“必填未完成”，同时 Toast `请完善相关信息`。隐藏字段不参与校验。
12. 若第 1、2、3 项选择 `其他`，对应备注输入框也必须填写，否则视为该必填项未完成。
13. 校验通过后才允许保存正式拜访记录、关闭表单，并同步刷新待补充记录队列和历史拜访记录列表。

### 5.8 二级页面：需求跟进表

#### 1. 页面定位
汇总员工名下所有网点的需求记录，是需求管理的全局视图，支持多维筛选和状态更新入口。

#### 2. 页面入口
- 首页「渠道拜访」需求区「全部 ›」入口
- 过程跟进模块「需求已满足/未满足」卡片点击

#### 3. 页面目标
- 提供需求全生命周期追踪视图，让员工随时掌握名下所有未跟进需求。

#### 4. 页面模块说明

**筛选区**：网点筛选 + 满足状态下拉（双筛选，组合过滤）。满足状态取值统一为三态「已满足 / 未满足 / 无法满足」。网点筛选采用与「我的渠道」一致的**网点选择弹层**（搜索框 + 银行大类 chips + 最近选择置顶 + 网点列表；详见 5.1「网点选择弹层」），支持按银行大类快速缩小范围。  
**统计行**：「共 N 条需求，M 条未满足」  
**需求列表**：每条显示网点名/描述摘要/紧急程度徽章/时间/满足状态；满足状态标签读取**共享状态值**（与同 `recordId` 的拜访记录双向同步、后写覆盖），保存或他处更新后列表行即刷新。  

#### 5. 页面交互流程

**流程 1：按网点筛选需求**  
点击网点筛选框 → 弹层打开（默认「全部」大类 + 空搜索）→ 搜索关键字或点选银行大类 chips（取交集，交集为空时展示空态与「清除大类，在全部大类中搜索」）→ 选中目标网点 → 弹层关闭并回填，列表按该网点过滤。

**流程 2：筛选未满足紧急需求**

### 5.9 二级页面：需求详情（编辑页）


#### 1. 页面定位
单条需求的详情查看 + 状态更新操作页，是需求跟进流程的终点。支持**连续阅读**：从筛选列表进入时，可在本条上直接切换上一条/下一条，无需往返列表。

#### 2. 页面入口
- 需求跟进表列表**（筛选列表）**点击 —— 进入后展示「上一条 / 下一条」连续阅读导航
- 首页渠道拜访需求摘要列表点击 —— **不展示**上一条/下一条（非筛选上下文）

#### 3. 页面目标
- 让员工快速更新需求解决方案和状态，无法满足需求支持一键上报。

#### 4. 页面模块说明

**基本信息区（只读）**：所属网点/记录时间/需求挖掘（标签纵向列表，每个标签后跟各自选填描述）/紧急程度/当前状态  
**需求状态（三态，统一为）**：✅ 已满足 / ⏳ 未满足 / 🚫 无法满足  
**解决方案区（可编辑）**：多行文本框 + 右上角「AI问案例 ›」快捷入口  
**状态更新区（三选一）**：✅ 已满足 / ⏳ 未满足 / 🚫 无法满足  
**底部操作栏**：「取消」+ 「保存更新」；**保存更新后停留当前页**（不自动返回列表），Toast 反馈成功并就地刷新当前页所展示的状态与内容。  
**连续阅读导航**：仅从筛选列表进入时，在页面底部（或顶部）展示「‹ 上一条 / 下一条 ›」。切换前若存在**未保存改动**，先弹二次确认，提供「**保存并继续**」与「**放弃改动**」两个选项（点「保存并继续」先提交再翻页、点「放弃改动」丢弃改动翻页；无改动直接翻页）；**冻结进入时快照**：进入本页时锁定当时的筛选结果与顺序作为导航序列，期间他处新增/变更不影响序列；到达**末条**时「下一条」置灰并 Toast「已到最后一条」、到达**首条**时「上一条」置灰并 Toast「已是第一条」；返回列表时**保留原筛选条件与滚动位置**。**（说明：团队长端两处需求详情页均为只读，无本二次确认分支。）**

**「无法满足」触发逻辑**：点击「无法满足」并保存 → 自动触发企微消息推送至团队长 → Toast「已上报团队长协同处理」

#### 5. 页面交互流程

**流程 1：标记已满足**  
进入需求详情 → 填写解决方案文本 → 点击「已满足」→ 点击「保存更新」→ Toast 反馈 → **停留当前页**并刷新所展示状态（不返回列表）→ 可用上一条/下一条继续阅读

**流程 2：上报无法满足**  
进入需求详情 → 点击「无法满足」→ 点击「保存更新」→ 触发企微推送 → Toast「已上报团队长」→ **停留当前页**

**流程 3：连续阅读**  
从筛选列表进入需求详情（进入时冻结筛选结果快照）→ 点「下一条」→ 若本条存在未保存改动先二次确认（「保存并继续」/「放弃改动」）→ 加载下一条 → 到末条时「下一条」置灰并 Toast「已到最后一条」（到首条时「上一条」置灰并 Toast「已是第一条」）→ 返回列表保留原筛选与滚动位置

#### 6. 页面状态说明

| 状态 | 触发条件 | 展示内容 |
|------|----------|----------|
| 默认态 | 进入页面 | 展示需求信息，状态默认当前值 |
| 已选无法满足 | 点击「无法满足」 | 保存按钮变为「保存并上报」 |
| 已保存态 | 点「保存更新」成功 | 停留当前页，Toast 成功并就地刷新状态； |
| 待切换确认态 | 存在未保存改动时点切换 | 二次确认弹窗，提供「保存并继续」/「放弃改动」； |
| 末条态 | 导航至快照序列首/末条 | 末条「下一条」置灰 + Toast「已到最后一条」、首条「上一条」置灰 + Toast「已是第一条」； |
| 加载态 | 提交保存中 | 保存按钮 loading 状态 |
| 异常态 | 保存失败 | Toast「保存失败，请重试」 |

#### 7. 数据字段建议

参见第7章 Demand 对象字段表。

#### 8. 首版范围说明

**首版必做（🔴 P0）**：三态状态更新（已满足 / 未满足 / 无法满足）；解决方案文本编辑；无法满足自动上报；保存后停留当前页；从筛选列表进入时支持上一条/下一条连续阅读（未保存改动二次确认、末条置灰+Toast、返回保留筛选与滚动位置）

**网点行点击**：展开该网点渠道详情卡片（复用「渠道详情卡片」规格）。

**周期口径（硬口径）**：本页周期**进入时继承**「我的渠道」当前所选周期（含所选考核期次，如考核月的某期）；**进入后页内独立切换**（仅影响本页）；**返回「我的渠道」时其周期保持进入前原状态**（本页内切换**不回写**「我的渠道」）；**再次进入重新继承**「我的渠道」当时的周期。因此本页与「我的渠道」**不是同一状态**（页内切换不回写、返回互不影响）。

### 5.14 二级页面：名下渠道排名



#### 1. 页面定位

#### 2. 页面入口
- 「我的渠道」**全部网点态**（网点选「全部网点」）下，**4 张经营结果卡片**（新增资产 / 新增有效户 / 新增开户数 / 渠道经营积分）可点击进入，并带入对应指标维度。

- 让员工在单一指标维度下查看本人名下网点的排名分布，并可直接查看网点渠道详情。

**指标切换区（页内）**：排名列表上方保留 **4 张指标卡**（新增资产 / 新增有效户 / 新增开户数 / 渠道经营积分），**4 选 1**、默认选中入口带入的指标，当前指标卡高亮；点击某张卡 → 排名列表与各行数值按该指标刷新（卡选中态同步切换）。

**排序切换**：列表支持排序切换——**默认按名次**，可切换为**按数值升序 / 降序**。

**排名列表**：按该指标排列本人名下网点，每行展示——排名序号 / 网点名 / 该指标数值 / （可选）占比或进度条。**网点行不展示所属员工副信息**（已限定为本人名下）。网点名**最多展示 2 行**，1～2 行完整可见，超过 2 行时第 2 行末尾以省略号收尾，并与右侧指标数值**顶部对齐**；超过 2 行的完整名称在该行展开的渠道详情卡片内完整展示（依据「渠道名称完整显示」规格）。

**网点行点击**：整行点击在该行下方原地展开 / 收起渠道详情卡片（同一列表同时仅展开一行；展开交互沿用「渠道详情卡片」规格）。

**渠道详情卡片（网点行展开）**：自上而下展示——①完整渠道名称（不发生省略号隐藏）；②**渠道建档信息**：建码日期 · 已建码天数、**关键人列表**（职位 + 姓名 + 生日，全部展示、不设条数上限）、网点星级 + 星级变化（网点星级**仅用星形图标展示**，不附「一星／二星」等文字档位）。卡片**不展示经营指标 4 项与过程指标 4 项**；卡片**只读**，不提供「编辑建码信息」入口；**仅星级变化**随页内「时间周期」切换刷新，建码日期 · 天数与关键人列表为静态档案、不随周期变化；无建档数据的网点展开后仍展示完整渠道名称，其余区域展示「暂无建档信息」占位。**关键人区排布**：关键人标签默认**每行两个**（各占半宽），当单个标签的「职位 + 姓名 + 生日」在半宽内放不下时，**标签内文字自然换行**，完整展示、不截断、不溢出；标签较多时逐行自然折行，不设条数上限。

## 第 6 章：通用能力说明

### 6.1 二级页面（Sub-Page）

**能力定位**：全屏覆盖的二级页面，承载不适合弹框承载的复杂内容，提供原生 App 级别的页面切换体验。

**适用页面**：全部异动、拜访历史、拜访详情、我要拜访、需求跟进表、需求详情、知识库、渠道星级详情页、名下渠道排名

**技术实现**：`position:fixed`，`z-index:100`；初始 `opacity:0; visibility:hidden`（不占位）；打开添加 `open` class → `opacity:1; visibility:visible`；入场动画：从右侧 `translateX(100%)` 滑入，300ms cubic-bezier(0.4,0,0.2,1)

**标题栏（sub-hd）**：深蓝色顶栏，左侧「← 返回」，中间页面标题，右侧操作（可选）

**交互规则**：点击返回按钮 → 关闭当前子页；不支持手势右滑关闭（首版）

**首版必做**：动画 + 所有子页面接入  
**首版可弱化**：手势右滑关闭（P1）

**状态同步要求**：子页面操作保存后（如需求状态更新），关闭时触发父页面列表数据刷新

### 6.2 Bottom Sheet（底部弹框）

**能力定位**：适用于表单编辑、选项选择等需要更多空间的操作场景，不触发全屏跳转。

**适用场景**：建联信息编辑、AI问案例

**技术实现**：挂载于 body 层（非 #app 内），避免 overflow:hidden 截断；`position:fixed; bottom:0; left:50%; transform:translateX(-50%) translateY(100%)`；打开添加 `open` class → `translateY(0)`，配合蒙层

**交互规则**：点击蒙层关闭；顶部有拖动把手（视觉提示，首版不支持手势拖动）；最大高度 88vh，内容超出时内部滚动

**状态同步要求**：Sheet 保存成功后，触发页面对应数据区域的刷新

### 6.3 Toast 通知

**能力定位**：操作结果的轻量级反馈，不阻塞用户操作。

**适用场景**：所有操作反馈（保存成功、复制成功、定位状态变化等）

**规格**：出现在底部距底 80px 处，深色圆角胶囊，2.5s 后自动消失，淡入淡出动画

**挂载层级**：body 级别，`z-index:10000`

### 6.4 筛选标签（Filter Tag）

**能力定位**：多处复用的横向滚动筛选组，单选。

**适用场景**：重点关注、历史拜访、需求跟进、知识库

**交互规则**：同一组内互斥单选，选中态蓝底白字；横向超出自动滚动，隐藏滚动条；默认选中「全部」

## 第 8 章：状态与规则说明

### 8.1 MVP 打卡与经纬度采集规则


- **打卡判定口径**：员工选择拜访网点后点击“立即打卡”，即可生成打卡记录；定位失败不阻断打卡。

- **采集失败处理**：因权限拒绝、企微/H5 容器限制、系统超时或设备能力不支持导致采集失败时，不阻断打卡；记录 gpsStatus，并允许员工继续选择拜访网点。
- **前端交互保持**：保留当前“我要拜访 · 立即打卡”“立即填写”“稍后填写”“待补充记录”等交互。

### 8.2 需求上报规则

- **自动上报条件**：拜访表单“需求是否紧急”=紧急 AND “需求是否满足”=未满足 → 保存时自动触发企微应用消息推送至员工所属团队长。
- **手动上报**：需求详情页选择「无法满足」→ 保存时触发上报，同时记录上报状态
- **推送内容**：包含需求描述、网点名称、紧急程度、员工姓名

### 8.3 生日提醒规则

- 计算：以当年对应月日计算距今天数，若当年日期已过则计算明年
- 今天生日（d=0）：闪烁橙色徽章「🎂 今天生日」
- 1-7天（d=1-7）：橙色徽章「🎂 N天后生日」
- 8-30天（d=8-30）：绿色徽章「🎂 N天后」
- >30天：灰色徽章「🎂 M月D日」
- 无生日数据：不显示徽章

### 8.4 待补充记录规则

支持多条待补充记录并存，新打卡不覆盖旧记录；完成一条仅移除对应记录。列表按打卡时间倒序。

- 员工打卡后选「稍后填写」→ 在 localStorage 写入 `_pendingRecord`（打卡地点 + 时间）
- 首页「渠道拜访」模块顶部显示黄色横幅提醒
- 点击「去补充」→ 恢复打卡状态并显示表单
- 完整提交后 → 横幅消失，`_pendingRecord` 清空
- 每次只能有一条待补充记录（新打卡会覆盖旧的）

### 8.5 数据权限规则

需求详情操作区依据当前角色与被查看员工 ID 渲染；团队长穿透员工时不得出现员工写操作。定位页可按设计展示并复制经纬度，埋点不得上传经纬度原值。

- 员工仅可见名下渠道数据（networkId 列表由登录态决定）
- 团队长可见辖内汇总数据（后续版本）
- 关键人电话字段脱敏展示（中间4位替换为 ****）

### 8.6 Tab 导航滚动联动规则

- 点击 Tab 平滑滚动至锚点，同时设置 `_tabScrollLock=true`，1.5 秒后解除
- 锁定期间禁止滚动事件触发 Tab 高亮变更
- 非锁定期间：模块顶部进入视口上方 120px 内即高亮对应 Tab
- 滚动到底部：强制高亮最后一个 Tab

### 8.7 重点关注事项链路规则


**消息盒子直达 H5 类（网点降级、未拜访提醒、生日提醒）**：
1. 上游规则命中；
2. 消息盒子生成消息并直接下发至 H5；
3. H5 在首页和全部异动页展示消息摘要；
4. 员工点击消息；
5. H5 打开消息详情页；
6. 消息详情页打开成功后，该消息从 H5 当前列表消失。

**H5 需求记录类（需求未满足）**：
1. 员工在拜访表单或需求跟进中提交未满足需求；
2. H5 生成或更新 Demand 记录；
3. 符合未满足展示条件的 Demand 进入重点关注；
4. 员工点击需求未满足事项；
5. H5 打开需求详情页；
6. 若需求仍未满足，返回后继续展示；若状态变为已满足、已关闭或已失效，则停止展示。

补充规则：
- H5 不负责生成前三类消息；
- 需求未满足不走消息盒子消费链路；
- 消息盒子类以 messageId 做去重和当前列表移除；
- 需求未满足以 demandId 和需求状态控制展示；
- 不再引入企微消息中心作为本模块链路说明。

### 9.1 命名规则

- 事件英文名格式：`模块_页面_事件类型`
- 系统前缀：`ls`（零售线 / lingshui）
- 三类基础事件类型：view（页面加载）/ click（用户点击）/ show（元素曝光）
- 命名规范：小写英文 + 下划线，全局不可重复，建议15字以内
- 历史已定义的事件名**不得修改**（避免数据断层）
- 重点关注新增埋点仅上传 messageId、messageType、sceneId、demandId、itemType、result 等非原文字段，不上传消息正文或需求描述。

逐项验证导航拖拽防误触、员工版无角色切换入口、建码保存、昨日/本周/自然月/本年/考核月周期、多待补充队列、地图/精度圆/附近网点、经纬度与采集时间展示及复制坐标、主动选点、六模块条件校验、历史筛选、AI 推荐动态 Tab、角色化需求操作以及统一文案；未涉及能力按 v1.3 原验收标准执行。

| 功能点 | 验收标准 | 优先级 |
|--------|----------|--------|
| MVP打卡 | 1. 员工在页内网点选择区点选网点（或输入未录入网点名称并二次确认）后可打卡 2. 能记录经纬度采集成功/失败状态 3. 经纬度采集失败不阻断打卡 4. 稍后填写可生成待补充记录 | P0 |
| 拜访表单提交 | 1. “需求是否紧急”选紧急且“需求是否满足”选未满足时，提交触发团队长推送 2. 提交后Toast显示「拜访记录已提交」3. 日历当日打点正确更新 | P0 |
| 建码卡片编辑 | 1. Bottom Sheet 正确从底部弹出 2. 不展示网点地址 3. 可增删关键人并维护职位、姓名、电话号码、生日、其它信息 4. 统一保存后卡片和生日徽章正确刷新 5. Toast 反馈正确； | P0 |
| 重点关注事项 | 1. 展示网点降级、未拜访、生日提醒、需求未满足 4 类事项 2. 查看全部进入二级页面 3. 消息盒子类点击进入消息详情后从列表消失 4. 需求未满足点击进入需求详情且按需求状态停止展示 | P0 |
| 需求状态更新 | 1. 「无法满足」触发上报 2. 状态保存后停留当前页并实时更新 3. 从筛选列表进入支持上一条/下一条 4. Toast 反馈正确 | P0 |
| Tab 导航联动 | 1. 点击 Tab 平滑滚动至对应模块 2. 1.5s锁定期间滚动不触发高亮变化 3. 滚动到底部最后 Tab 高亮 | P0 |
| 过程跟进四格 | 1. 正确展示当前所选周期数据（随「我的渠道」时间周期联动刷新） 2. 点击拜访/活动格滚动至对应模块 3. 点击需求格进入需求跟进表 | P0 |
| 知识库内容 | 1. 普通入口仅展示“展业 SOP/优秀案例”Tab 2. 4个SOP + 3个案例完整展示 3. 搜索默认、有结果、无结果状态正确 4. “AI问案例”进入时动态展示“AI 推荐” | P0 |

**核心场景验收路径**：

1. **完整拜访场景**：点击「我要拜访 · 立即打卡」→ 等待定位 → 在页内网点选择区点选「附近网点」/输入关键字选「搜索结果」→ 点击「立即打卡」→ 立即填写 → 完成6模块条件表单 → 提交 → Toast「拜访记录已提交」→ 返回首页 → 日历当日出现蓝点

2. **紧急需求上报场景**：“需求是否紧急”选「紧急」→“需求是否满足”选「未满足」→ 提交 → 确认团队长收到企微推送 → 在需求跟进表中查看到该需求状态为「未满足-紧急」。

3. **生日提醒场景**：关键人生日在提醒周期内 → 重点关注模块出现「生日提醒」 → 点击进入 H5 消息详情页 → 返回后该消息从当前列表消失

### 10.5 风险提示

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| GPS 定位在 iOS WKWebView 中需要 HTTPS | 影响打卡功能上线 | 确认 H5 部署环境为 HTTPS，提前验证 |
| 企微 API 推送依赖企业微信应用配置 | 影响紧急需求上报功能 | 提前申请企微应用权限，预留接入时间 |
| 数仓同步渠道数据延迟 | 影响数据准确性 | 明确数据同步频率 SLA（建议T+1），页面注明数据更新时间 |
| 关键人电话脱敏方案需合规审核 | 涉及客户信息展示 | **需合规审核，建议合规前置介入** |
| GPS 埋点坐标隐私合规 | 涉及用户位置数据 | 埋点仅上报定位结果状态和精度，不上报原始经纬度坐标 |
| 经纬度采集失败 | 员工设备、权限或企微容器限制导致无法采集坐标 | MVP 不阻断打卡，记录 gpsStatus 并允许选择拜访网点 |
