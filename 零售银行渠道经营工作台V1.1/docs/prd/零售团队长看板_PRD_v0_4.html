2. 项目背景与目标

2.1 背景

零售员工版渠道经营工作台已沉淀个人渠道经营能力，员工可以完成重点关注查看、渠道建码维护、拜访打卡、拜访记录补充、需求状态维护、知识库和工具库使用。团队长日常管理中需要从团队维度查看员工经营进展，识别无法闭环的上报需求、超过阈值仍未处理的超时关注，并通过提醒、跟进、归档动作推动团队经营闭环。

团队长本人也可能承担个人渠道经营任务。团队管理视角只看团队聚合数据和员工明细，不代员工编辑业务数据；团队长通过顶部角色切换图标回到本人员工视角，按本人身份完成打卡、建码、拜访和需求维护。

2.2 核心目标

  • 团队看盘：团队长可在一个 H5 页面查看团队重点关注、团队总览、星级渠道、过程跟进、拜访记录五类核心模块。
  • 事项闭环：团队长可处理员工上报需求，完成标记跟进、归档，并可对超时关注事项进行一键提醒。
  • 员工穿透：团队长可从排名、重点关注、过程记录、拜访记录进入员工详情，查看员工重点关注、渠道、拜访和需求上下文。
  • 边界清晰：团队长团队视角只读员工业务数据，不代员工打卡、编辑建码、提交拜访记录、保存需求状态；团队长本人的业务操作通过顶部角色切换图标回到员工版流程。
  • 数据安全：团队长查看员工敏感字段时按权限脱敏，埋点不上传手机号、GPS 原始经纬度、需求描述原文、拜访备注原文、解决方案原文。

2.3 非目标

  • 不重写员工版已评审通过的页面结构、字段口径和业务状态。
  • 不在团队长团队视角提供代员工打卡、代员工编辑建码、代员工提交拜访记录、代员工保存需求状态。
  • 不由团队长版判断员工重点关注消息是否完成，员工消息盒子生命周期由消息盒子后台负责。
  • 不提供 PC 端页面适配。

2.4 上线时间

PRD 确认后 2-3 周内完成 H5 开发、联调和试运行。上线范围包含团队看板、团队重点关注、上报需求处理、超时提醒、团队总览、完整排名、星级渠道、过程跟进、团队拜访记录、员工穿透和角色切换。

3.1 用户角色

3.2 核心使用场景

场景 1：团队长进入团队看板查看团队表现

背景：团队长需要快速掌握本周期团队经营结果和过程执行情况。 操作路径：团队长从统一工作台团队版入口进入 → 查看团队重点关注 → 查看团队总览 → 查看当前排名分析 → 打开完整排名。员工版不展示团队版切换入口。 期望结果：团队长可看到上报需求、超时关注、团队业务指标、员工/网点排名，并可从「按员工」排名穿透员工详情（「按网点」排名行就地展开渠道详情卡片）。

场景 2：团队长处理员工上报需求

背景：员工侧产生紧急且未满足、无法满足或主动上报的需求，需要团队长介入跟进。 操作路径：团队版重点关注 → 上报需求 → 查看全部 → 切换新上报/跟进中/已归档 → 打开需求详情 → 标记跟进或归档。 期望结果：团队长可查看需求上下文并完成团队侧处理动作；标记跟进和归档只更新团队侧处理状态，不反向修改员工拜访记录和员工需求原始内容。

场景 3：团队长提醒员工处理超时关注

背景：团队内出现生日当天、长期未拜访、需求未满足且未上报等需要团队长督促员工处理的事项。 操作路径：团队版重点关注 → 超时关注 → 查看全部 → 筛选待提醒 → 勾选事项 → 一键提醒 → Toast“已发送提醒”。 期望结果：系统按员工聚合发送管理提醒，列表刷新提醒状态；团队长不进入员工消息详情页、不消费员工消息；今日已提醒及冷却期内事项不可再次勾选提醒。

场景 4：团队长从排名穿透员工详情

背景：团队长发现某员工指标异常或排名靠后，需要查看员工经营明细。 操作路径：团队总览 → 完整排名 → 点击员工 → 员工详情 → 查看员工重点关注、我的渠道、渠道拜访及其中的需求跟进。 期望结果：团队长可查看员工经营上下文；员工详情页只读，不展示代员工写操作入口。

场景 5：团队长处理本人业务

背景：团队长本人也承担渠道经营任务，需要像普通员工一样完成拜访和需求维护。 操作路径：团队版 → 点击顶部角色切换图标 → 回到员工版 → 按本人身份完成员工版流程。 期望结果：团队长本人业务操作使用团队长本人的员工 ID，不携带被查看员工 ID，不影响团队内其他员工数据。

4. 功能架构

4.1 整体架构说明

团队长版采用“团队看板 + 二级列表/详情 + 员工穿透”的结构。团队看板为团队长默认管理视角，包含团队重点关注、团队总览、星级渠道、过程跟进、拜访记录五个模块；二级页面承载上报需求列表、上报需求详情、超时关注列表、完整排名、星级渠道详情、过程详情、拜访详情、员工详情；团队长通过顶部角色切换图标回到本人员工视角处理本人业务。

5. 页面详细说明

5.1 团队版主看板

1. 页面定位

团队长查看团队渠道经营表现和待处理事项的主页面。

2. 页面入口

  • 员工版不展示角色切换入口；团队长从统一工作台团队版入口进入。

3. 页面目标

  • 聚合展示团队重点关注、团队总览、星级渠道、过程跟进、拜访记录。
  • 支持团队长快速进入上报需求处理、超时提醒、完整排名、星级渠道详情、过程详情、员工详情。
  • 顶部右侧提供角色切换图标，用于返回本人员工视角。

4. 页面模块说明

顶部五项导航支持鼠标横向拖拽和移动端横向滑动，右侧显示渐隐遮罩，拖动结束不得误触导航项；超时关注页签显示团队侧未读红点，点击查看后消失，且不得消费员工侧消息。

5.5 团队过程跟进与拜访记录页

  • 支持按周期、员工、网点筛选过程记录，并通过顶部 Tab 切换记录类型。
  • 支持按周期、员工、类型检索团队拜访与活动记录。
  • 支持查看团队拜访和活动详情。

过程详情列表

模块作用：展示团队范围内的拜访、活动和需求过程明细。 展示内容：顶部tab筛选器，周期筛选器（昨日/本周/自然月/本年/考核月）、员工筛选器（支持按姓名搜索，规则见下）、网点筛选器，详情卡片。 交互说明：切换任一筛选条件后刷新列表；点击需求卡片进入需求详情；点击员工卡片进入员工详情；从详情页返回时保留筛选条件和滚动位置。渠道（网点）行名称最多 2 行、超出第 2 行省略号、与右侧元素顶部对齐，点击该行可在行下方展开渠道详情卡片（完整渠道名称 + 经营指标 4 项 新增资产/新增有效户/新增开户数/经营积分 + 过程指标 4 项 拜访次数/活动次数/需求总数/需求未满足，随页面周期刷新），同一列表同时仅展开一行。 备注：列表默认按记录时间倒序；筛选无结果时展示空态（页签为0）；筛选接口失败时保留上一次列表并提示“过程记录加载失败”；由“需求管理”列表进入的需求详情为只读页，内容区左下/右下角展示「上一条/下一条」悬浮按钮；已是首条/末条时对应按钮置灰、点击给 Toast（「已是第一条」/「已到最后一条」）；团队长端无二次确认、无未保存改动拦截（与员工端可编辑版不同）；返回列表保留周期/员工/网点与状态 chips 筛选及滚动位置；渠道详情卡片中某指标缺数据显示「—」。

网点筛选器 模块作用：在团队可见范围内数百个、跨多家银行的网点中快速定位目标网点（含"需求管理"Tab 的网点筛选）。 交互规格：点击网点筛选器 → 弹出网点选择弹层（高度 90%，头部固定、列表区内部滚动，内容为团队可见范围内的全量网点），与员工端「我的渠道」网点选择为同一实现： 1. 搜索框：对网点名称做跨银行模糊匹配；已选银行大类时仅在所选大类内匹配。 2. 银行大类 chips：即"银行品牌"（取自网点对象的 bankBrand）。按固定优先级排序：国有大行 → 股份制 → 城商/农商；默认铺 3 行，超出收进末尾「更多 ∨」，展开后 chips 区内部滚动；默认选中「全部」。 3. 最近选择（置顶区）：展示本设备最近选中的 5 个网点；无历史时不展示；数据存本机，不跨设备同步。 4. 网点列表：保持「全部网点」置顶；点击任一网点即选中、回填筛选条件并关闭弹层。 5. 交集规则：搜索词与银行大类为交集（AND）。 6. 空态兜底：交集为空时展示空态 + 「清除大类，在全部大类中搜索」；点击后回到「全部」、保留搜索词重新匹配。 7. 回退规则：点遮罩/关闭按钮关闭弹层不改变已选网点；重新打开回到默认态（全部 + 空搜索）。

员工筛选器 模块作用：在团队全部员工中快速定位目标员工；团队长端「星级渠道详情」「过程详情列表（含需求管理 Tab）」「拜访记录日历」及其日历详情二级页共 4 处共用同一实现。 交互规格：点击员工筛选器 → 弹出员工选择弹层（头部固定、列表区内部滚动）： 1. 搜索框：标题下方固定搜索框，对员工姓名做包含匹配、输入即时过滤（无需点击提交）；清空搜索词恢复全量列表。 2. 全部员工置顶：「全部员工」常驻列表首项、不参与姓名过滤；点击任一员工（含「全部员工」）即选中、回填筛选条件并关闭弹层。 3. 空态兜底：搜索无命中时列表区展示“没有找到匹配的员工”，搜索词保留以便修改。 4. 回退规则：点遮罩/关闭按钮关闭弹层不改变已选员工；重新打开弹层时清空搜索词、列表回到全量，当前已选员工保持高亮选中态。 5. 范围说明：仅按员工姓名匹配；列表项仅展示姓名，不展示工号/所属网点；不提供「最近选择」置顶。

拜访记录日历

模块作用：以月历方式查看团队拜访和活动分布。 展示内容：月份切换器、日历日期、拜访标记、活动标记、员工筛选器（支持按姓名搜索，规则见上）、选中日期、外展两条记录、「更多 ›」入口。 交互说明：切换月份后刷新当月标记；切换员工筛选后刷新日历标记；点击月历任一日期不跳页、仅在模块内筛选下方记录列表（默认展示今天，该日期无记录时展示空态）；点击「更多 ›」进入拜访记录二级列表页（该页顶部带统一周期筛选器与「员工筛选器」，与主页日历共用同一弹层实现，详见本页「员工筛选器」）；点击首页外展记录直接进入对应拜访或活动详情。 备注：拜访和活动使用不同颜色标记；同一天同时存在拜访和活动时展示两个标记；当日无记录时展示“当日暂无团队拜访或活动记录”。同员工版一致。拜访记录二级列表页按月分组展示，并接入含「考核月」的统一周期筛选（昨日/本周/自然月/本年/考核月，选「考核月」后再选期次）。

拜访记录二级列表

模块作用：集中查看团队范围内的拜访与活动记录，支持按周期、员工、类型检索。 展示内容：统一周期筛选器（昨日/本周/自然月/本年/考核月，选「考核月」后再选期次）、员工筛选器（支持按姓名搜索，规则见上）、类型标签（全部 / 拜访 / 活动，各标签叠加次数）、记录列表（按月分组）。 交互说明：页面不再展示日历，也无「X月X日记录」单日锚定标题，列表改按所选周期检索（不锚定单日）。切换周期（含考核月期次）或员工筛选后，列表与「全部 / 拜访 / 活动」次数同步按新条件重算；切换类型标签仅收窄列表、不改各标签上的次数。点击单条记录进入对应拜访或活动详情，返回时保留周期、员工、类型与滚动位置。 备注：各标签次数口径为「当前周期（叠加当前员工筛选）下该类型的记录条数」，与当前选中的类型标签无关；筛选无结果时列表展示空态。

拜访/活动详情

模块作用：展示团队成员单条拜访记录或活动记录的只读详情。 展示内容：记录类型、所属员工、所属网点、日期、开始时间、结束时间、拜访对象（统一展示为「职位+姓名」，多选并列、完整换行不截断）、需求挖掘内容（需求挖掘标签纵向列表，每个标签后跟各自选填描述；描述为空不展示描述行；维度三色与员工端一致）、达成合作内容、活动类型、参与人数、备注。 同员工版一致 交互说明：页面只读展示；点击返回回到来源列表并保留原筛选条件 备注：团队长不在此页代员工编辑、提交、删除记录；拜访对象为提交时的关键人快照、展示口径与员工端一致；需求状态（若有）读取与员工端共享的同一份值，含「需求状态」标签；备注内容按权限脱敏；记录不存在时提示“记录不存在或已删除”。

5.6 团队员工详情页

1. 页面定位

团队长从团队模块穿透查看员工经营上下文的只读页。该页复用员工版已评审通过的展示板块，不重写员工版业务流程，不提供代员工操作能力。

2. 页面入口

  • 完整排名点击员工。
  • 上报需求详情点击员工。
  • 过程记录点击员工。
  • 拜访详情点击员工。
  • 星级渠道详情经「员工」筛选定位（列表不展示员工姓名列；行点击为展开渠道详情卡片，不再穿透员工详情）。

3. 页面目标

  • 让团队长在一个页面内看清员工重点关注、渠道、拜访、需求四类上下文。
  • 与当前 demo 闭环：沿用员工版对应板块的展示形态，团队长视角统一只读。
  • 隔离员工侧行为数据：团队长浏览和点击不计入员工行为统计，不消费员工消息，不修改员工业务状态。

6. 通用能力说明

6.1 角色切换能力

能力定位

支持团队长在团队版和员工版之间切换，且保证团队视角与本人业务视角边界清晰。

适用页面

  • 员工版主工作台顶部。
  • 团队版主看板顶部。
  • 顶部角色切换能力。

能力说明

  • 员工版不展示角色切换入口。
  • 团队长版右侧展示角色切换按钮，可切换至员工版/团队长版。
  • 切换至员工版时使用团队长本人的员工身份。

交互规则

  • 从团队版回到员工版时恢复进入团队版前的员工版上下文。
  • 从员工穿透页返回团队页时恢复来源页筛选和滚动位置。
  • 返回本人员工视角时不得携带 viewedEmployeeId。

状态同步要求

员工版和团队长版共享登录态；员工版不展示角色切换入口。团队长版查看员工数据时必须携带 viewedEmployeeId；通过团队长版右侧按钮切换至本人员工视角时必须使用 currentUserId。

6.2 筛选与排序能力

能力定位

支持团队长在列表和排名场景中快速定位目标员工、网点、状态、指标和记录类型。

适用页面

  • 团队重点关注。
  • 上报需求列表。
  • 超时关注列表。
  • 团队总览与完整排名。
  • 星级渠道详情。
  • 过程详情列表。
  • 团队拜访记录。

能力说明

  • 周期筛选支持昨日、本周、自然月、本年、考核月五类，五个选项在同一控件内并列互斥单选；「考核月」为并列新增项，口径为考核账期（T-1 月 16 日 ~ T 月 15 日，含当日）。点选「考核月」后弹出「选择考核期次」列表：近 6 期（当期在最上、往期依次向下），每行左侧为日期区间、右侧为状态徽标（当期＝蓝色「进行中」、往期＝灰色「已结束」）、选中行显示勾选图标；首次进入默认高亮「当期（进行中）」。选定后控件回显「考核月」并在旁标注所选期次「区间 · 状态」（如 10/16–11/15 · 进行中），该标注仅呈现考核账期区间、不出现“数据截至 …”文案；切回自然历口径时标注消失。期次记忆：再次打开列表高亮上次所选期次，切走到其它周期再切回「考核月」仍保留所选期次。周期状态记忆范围：团队总览与团队总览详情（完整排名）共用、星级渠道与星级渠道详情共用、过程跟进与过程跟进详情各自独立、员工详情「我的渠道」与员工端「我的渠道」跨端共用；从上游页进入二级页时继承上游周期与所选期次（如团队总览→完整排名）。
  • 状态筛选支持上报需求状态和超时提醒状态。
  • 维度筛选支持按员工和按网点；网点筛选经"网点选择弹层"完成，支持在弹层内按银行大类（银行品牌）与关键字过滤（搜索 × 大类取交集）。
  • 过程详情使用周期、员工、网点筛选，并通过顶部 Tab 切换记录类型；星级渠道详情使用周期、员工和星级筛选。

交互规则

  • 筛选条件变化后刷新当前列表。
  • 从详情返回列表时保留筛选条件和滚动位置。
  • 排序支持记录日期升序、记录日期降序、超时天数升序、超时天数降序、指标值降序。

状态同步要求

筛选状态在当前页面内保持；切换主模块时不带入其他模块筛选条件。

6.3 Toast、弹层与底部面板能力

能力定位

统一团队长版管理动作反馈，降低误操作。

适用页面

  • 上报需求详情。
  • 超时关注列表。
  • 团队版主看板。
  • 员工详情页。

能力说明

  • Toast 用于保存成功、校验失败、提醒成功、加载失败四类轻量反馈。
  • 一键提醒不使用 Confirm 弹层，点击后直接发送。
  • 上报需求归档不使用归档原因弹层。
  • Loading 和骨架屏用于页面或列表加载。

  • 管理动作失败后保留当前页面状态并展示失败 Toast。
  • 归档和一键提醒均不二次确认。
  • 弹层关闭后返回触发前上下文。

状态同步要求

6.4 只读与权限控制能力

能力定位

确保团队长能查看团队员工数据，但不会代员工修改个人业务数据。

适用页面

  • 员工详情页。
  • 员工渠道只读详情。
  • 员工拜访只读详情。
  • 员工需求只读详情。

能力说明

  • 团队长可查看辖内员工聚合数据和明细数据。
  • 团队长员工详情页复用员工版重点关注、我的渠道、渠道拜访的展示能力，需求跟进并入渠道拜访区。
  • 团队长团队视角不可编辑员工建码信息、不可提交员工拜访记录、不可保存员工需求状态、不可消费员工消息。
  • 团队长本人业务操作仅在通过角色切换返回的员工视角中开放。

交互规则

  • 只读页不展示打卡、定位、编辑建码、新增关键人、删除关键人、提交拜访、编辑需求、保存需求状态按钮。
  • 管理动作如标记跟进、归档、一键提醒属于团队长权限，可在团队重点关注内操作。
  • 查看敏感字段需按权限脱敏。
  • 团队长查看员工详情产生的页面行为不计入员工行为数据，不更新员工侧页面统计和业务指标。

状态同步要求

权限状态由登录态、团队关系和被查看对象共同决定；团队视角始终只读员工数据，点击角色切换返回本人员工视角后才开放本人写操作。

8. 状态与规则说明

8.1 业务规则

上报需求按“新上报 → 跟进中 → 已归档”单向流转；新上报不可直接归档。超时关注与员工版重点关注统一为网点降级、未拜访、生日提醒、需求未满足四类。

  • 团队长团队视角只读员工业务数据，不代员工提交打卡、拜访记录、建码信息和需求状态。
  • 员工侧需求满足上报规则时进入团队长上报需求列表；上报规则由员工版 PRD 和后端规则引擎负责。
  • 团队长标记跟进和归档只更新团队长处理状态，不覆盖员工需求原始状态。
  • 超时关注由团队侧内部规则池 TeamTimeoutAttention 生成，团队长版只展示、筛选、提醒，不打开员工消息详情页。
  • 今日已提醒及冷却期内事项不可重复提醒。
  • 团队长本人业务通过角色切换图标进入员工版流程，使用团队长本人的员工 ID。
  • 团队长查看员工详情只产生管理视角访问，不计入被查看员工的行为数据、业务状态和过程指标。

8.2 用户权限规则

角色切换返回团队长本人员工视角；员工穿透页隐藏所有写入口。需求详情操作区必须同时校验当前角色与被查看员工 ID。

8.3 数据同步规则

  • 员工提交拜访记录后，团队版过程跟进和拜访记录需同步。
  • 员工需求满足上报规则后，团队版上报需求列表和团队重点关注入口需同步生成或更新。
  • 团队长标记上报需求跟进后，团队重点关注首页、上报需求列表和详情需同步。
  • 团队长归档上报需求后，默认首页和“全部”列表不展示该事项，已归档筛选中可查看。
  • 团队长完成一键提醒后，超时关注列表中对应事项变为已提醒，并记录提醒次数和最后提醒日期。
  • 员工消息盒子消息生命周期由消息盒子后台负责；团队长查看员工重点关注不消费员工消息。
  • 团队超时关注由 TeamTimeoutAttention 独立生成和流转；团队长一键提醒不改变员工消息盒子的已读、消失或详情访问状态。
  • 团队长查看员工详情不触发员工版数据同步；不更新员工消息已读、拜访次数、需求处理数、渠道维护记录。

9. 埋点设计

9.1 命名规则

  • event_name 统一使用通用事件类型：rc_view 表示页面浏览，rc_click 表示页面点击，rc_show 表示页面曝光或弹层曝光，rc_result 表示操作结果。
  • page_name 使用 rc_ + 角色 + 页面，例如 rc_staff_home、rc_team_home、rc_team_demand_detail、rc_team_timeout_attention_list。
  • module_name 使用 rc_ + 角色 + 模块，例如 rc_team_attention_module、rc_team_rank_module、rc_staff_visit_form_module。
  • element_name 使用业务对象 + 动作，例如 switch_team_click、demand_filter_click、timeout_remind_confirm_click、visit_submit_result。
  • 业务字段不通过埋点保存；拜访对象、需求挖掘、合作内容、备注、经纬度进入业务字段或业务表。
  • 埋点只记录页面浏览、点击、曝光、操作结果，不上传手机号、生日、备注、需求描述、解决方案、GPS 经纬度原值。

10.3 核心场景验收路径

  1. 团队看盘路径：从统一工作台进入团队长版 → 查看重点关注 → 查看团队总览 → 切换周期 → 打开完整排名 → 按员工/网点切换。
  2. 上报需求路径：团队版重点关注 → 上报需求 → 查看全部 → 打开新上报需求 → 标记跟进 → 返回列表状态为跟进中 → 直接归档，不填写归档原因、不二次确认。
  3. 超时提醒路径：团队版重点关注 → 超时关注 → 查看全部 → 筛选待提醒 → 勾选事项 → 一键提醒 → Toast“已发送提醒”→ 状态更新为已提醒，员工消息详情状态不变化。
  4. 星级渠道路径：团队版星级渠道 → 切换周期 → 点击三星条目 → 进入星级渠道详情 → 筛选员工/星级 → 点击网点行展开渠道详情卡片 → 返回团队版。
  5. 过程记录路径：团队版过程跟进 → 点击拜访次数 → 进入过程详情列表 → 筛选员工 → 点击记录进入只读详情。
  6. 员工穿透路径：完整排名点击员工 → 员工详情 → 查看重点关注、我的渠道、渠道拜访及需求跟进只读信息 → 返回团队版。
  7. 本人业务路径：团队版点击角色切换图标 → 返回员工版 → 点击我要拜访 → 以团队长本人身份进入拜访流程。
