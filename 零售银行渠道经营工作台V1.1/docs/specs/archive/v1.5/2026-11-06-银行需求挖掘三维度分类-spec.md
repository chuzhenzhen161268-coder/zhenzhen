**模式**：迭代 (iterate)

## 一、需求背景

**目标用户**：员工端＝客户经理（拜访时填写「银行需求挖掘」）；团队长端＝团队长（本轮只读展示）。

**要解决的问题**：拜访表单「银行需求挖掘」现状是 **10 项平铺 chip**（三方存管 / AUM·存款 / 信用卡 / 养老金 / 产品销售 / 贷款 / 其它对公需求 / 客户资源 / 渠道关键人赋能 / 其它），只能记录"这次谈了什么业务"，**表达不出需求的性质**。带来两个后果：① 员工自己看不出这次挖掘覆盖的是哪一类需求（是业绩型职业需求，还是家庭/社交类社会需求，还是个人兴趣与健康类个人需求）；② 团队长与统计端拿到的是一条条彼此平行的业务标签，**无法判断员工的能力结构**——谁擅长谈职业需求、谁在社会／个人需求上从未涉及，全靠人工翻记录猜。

**解决方式**：把「银行需求挖掘」改为**两级分类选择 + 大类外提 + 每标签独立描述**——第一级是需求维度（**职业需求 / 社会需求 / 个人需求**），**三个大类直接常驻平铺在表单卡片外层**作为分组容器，点击任一大类即拉起该类的选择弹层；第二级是该维度下的具体**需求指标**（源自《渠道信任经营 · 需求库速查（三维度）》46 项）；库中无对应项时**手工补充**，手工项自动挂靠当前大类、打「自定义」标识，不产生无归属的自由文本。已选需求按所属大类归位展示在外层；**每个已选需求标签可单独、选填地填写「需求描述」**，取消原模块级「需求描述（必填）」单条文本框，让描述与具体需求一一对应、有上下文可读。

**本轮迭代（2026-11-10，就地改写）**：在 11-06 版基础上做三处调整——① 需求大类由半屏内的 tab **上提为表单卡片外层常驻分组**，去掉「＋ 添加需求」按钮，点大类直接进入该类弹层；② 弹层**只显示所点大类**（去掉大类 tab 切换，保留类内搜索与手工补充）；③ 「需求描述」由**模块级单条必填**改为**每个已选需求标签的独立选填描述**（在弹层勾选后即填）。据此，11-06 版第四节"不做每个已选标签的独立需求描述"的边界**作废**。

**竞品差异 / 品类惯例**：本次未做外部调研（既有表单模块内的控件升级），不适用。

**AI 能力边界**：不适用（沿用既有「AI问案例」入口，本 Spec 不改其行为）。

## 二、逻辑补齐摘要

### 2.1 主成功路径

员工进入拜访表单 → 「银行需求挖掘」模块默认**空态**（职业 / 社会 / 个人三个大类分组常驻平铺，各组下提示"点击添加"）→ 点某个**大类分组**拉起**半屏选择器**（只展示该大类下的二级指标）→ 在二级指标中点选（可跨大类多次点选，每次从一个大类进入）→ 勾选某项后**可即时在选项下方填写该需求的「描述（选填）」** → 点「确定」关闭半屏 → 外层对应大类分组下展示已选标签（带维度色 + 各自描述）→ 提交 → 需求以「维度 + 分组 + 指标名 + 自定义标识 + 需求描述」结构随拜访记录落库。

### 2.2 关键分支

- **分支 1 · 大类外提常驻**：三个大类（职业需求 / 社会需求 / 个人需求）作为**分组容器常驻平铺**在表单卡片外层，**不再有「＋ 添加需求」按钮**；每个大类分组常驻显示（已选标签归到所属大类下，带该维度色圆点与「N 项」计数；暂无已选时显示"点击添加"提示）。点击某大类分组即拉起该大类的选择弹层。
- **分支 2 · 大类分组是容器不是互斥筛选**：三个大类可同时存在已选项；进入某大类弹层选择不影响其它大类已选项；先后进入不同大类，各自维护自己的选择。
- **分支 3 · 弹层只显示所点大类**：弹层内不再有大类 tab 切换，**只展示从外层点入的那个大类**的二级指标；二级指标按**展示分组**铺开（如"业绩 · 存款 / 账户与产品 / 客户经营 / 对公业务 / 综合管理 / 个人收获 / 合作保障"），分组标题与指标同一屏内顺序罗列，★ 常用项在分组内**置前**并标记。
- **分支 4 · 弹层内搜索**：选择器顶部搜索框在**当前大类范围内**匹配（匹配范围＝指标名 + 展示分组 + 大类名）；无命中时展示空态并提示可在下方「手工补充」录入。
- **分支 5 · 手工补充**：点「＋ 手工补充（无对应项时使用）」展开输入行 → 输入需求名称 → 添加后**自动挂靠当前大类**（grp 记为"自定义"）、打「自定义」小标；输入为空 → Toast「请输入需求名称」；同大类内重名 → Toast「该需求已选择」，不产生重复项。
- **分支 6 · 选择即生效、勾选即可填描述**：半屏内勾选／取消**即时写入**已选集合；**勾选某项后，该选项下方即时出现「描述（选填）」输入框**，可当场填写该需求的独立描述；外层卡片与半屏底部「已选摘要」同步刷新。「确定」按钮只负责**关闭半屏**并回吐已选（不承担"提交草稿"语义），文案为「确定（已选 N 项）」；点遮罩或右上「×」关闭时**保留已选与已填描述**、仅关闭面板。已选为空时「确定」**置灰不可点**。
- **分支 7 · 必填规则**：「银行需求挖掘」**至少选 1 项**；**每个需求标签的「需求描述」为选填**（无模块级描述、无描述必填校验）。提交时若一项需求都未选 → 模块卡片加红描边 + Toast「请至少选择一项银行需求」。
- **分支 8 · 修改态（拜访记录编辑）**：编辑态复用同一套控件；原记录已选需求按**快照回显**（含维度、所属分组、自定义标识、**每个标签各自的描述**），可继续增删与改描述；保存时按新结构覆盖写回（规则沿用《2026-11-03-拜访记录补充与需求状态同步-spec.md》）。
- **分支 9 · 存量记录**：已提交的历史记录保持原文本展示（如"需求：信用卡推广资源"），**不追溯改写、不做数据迁移**；统计端对无维度字段的存量数据归入「**未分类**」桶，不计入三个维度的覆盖率分子。

### 2.3 状态与异常

- **状态**：
  - 空态：职业 / 社会 / 个人三个大类分组常驻平铺，各组下提示"点击添加"。
  - 已选态：按大类分组展示标签（分组标题＝"维度名 · N 项"，前置该维度色圆点），标签带维度色与「自定义」标识，标签尾部「×」可单个删除；标签下方展示该需求自己的描述（无描述则仅显示标签）。
  - 错误态：未选任何需求时，提交校验未通过 → 模块卡片描红。
  - 搜索态：弹层内搜索结果在**当前大类范围内**按展示分组呈现。
  - 搜索空态：无匹配结果，提示可在「手工补充」中录入。
- **校验失败**：未选需求 → 卡片描红 + Toast「请至少选择一项银行需求」。（**描述为选填，不做描红校验。**）
- **异常**：手工补充输入为空 → Toast「请输入需求名称」；同大类重名 → Toast「该需求已选择」。其余提交失败提示沿用既有口径（Toast「提交失败，请稍后重试」），表单已填内容不丢失。
- **回退**：关闭选择器（遮罩／×）→ 仅关闭，已选与已填描述保留；表单「放弃／取消」→ 本次分类选择与各条描述均不落库。
- **已失效指标**：库中某指标下架／更名后，已提交记录不受影响（快照语义）。

### 2.4 跨页影响

- **主改页**：员工端拜访表单（新增态 + 修改态）「银行需求挖掘」模块——三大类上提为外层常驻分组、去掉「＋ 添加需求」按钮与模块级「需求描述（必填）」文本框、每标签可单独选填描述。
- **被动影响页**：
  - 员工端拜访详情页：「需求挖掘」展示改为**按维度分组的标签 + 每条标签后跟其自身描述**（沿用现有满足状态标签结构，名称部分改为带维度色的标签；无描述则仅展示标签）。
  - 员工端历史拜访记录列表行摘要、首页「渠道拜访」时间轴当日记录卡：需求摘要同步新口径。
  - 员工端「需求跟进」列表与需求详情：需求跟进与需求项为 1:1，其「需求描述」取对应需求项的**独立描述**（沿用既有 recordId 共享口径，不改同步规则）。
  - 员工端上报需求详情、团队长端拜访只读详情、员工详情·拜访只读详情：同步展示口径；团队长端维持只读，不新增写入口。
- **不涉及**：员工画像 / 团队长看板的需求维度能力结构分析（本轮明确不做，见第四节）；活动表单与活动详情；拜访表单其余 5 个模块；「AI问案例」入口与其检索逻辑；打卡、待补充队列、拜访次数统计。

### 2.5 仍未决项

无阻塞项。以下两项登记为后续范围：

1. **二级指标的展示分组口径**：本 Spec 采用《需求库速查·三维度》46 项原始库，但把原始库中 24 个零碎 `cat`（对私零售-存款／对私零售-账户／合作保障-客户保护…）**归并为 8 个展示分组**（见 §3.4 表）。这是**展示层归并**，不改变 46 项指标本身；后续如需按原始 `cat` 细分，需重新确认。
2. 一条拜访记录的需求项与 Demand 的拆分／合并（沿用既有 spec 的口径，本轮不变）。

## 五、验收标准

1. **大类外层常驻**：进入拜访表单即可看到职业 / 社会 / 个人三个大类分组常驻平铺（无已选时各组显示"点击添加"）；页面上**不存在「＋ 添加需求」按钮**。
2. **点类进弹层、分组为容器**：点击某大类分组拉起弹层，弹层**只展示该类需求**；三个大类可同时存在已选项、互不影响；无大类 tab 切换。
3. **弹层内搜索**：在弹层搜索框输入"信用卡""子女"等关键词，仅在该大类内匹配并返回；无命中时展示空态并引导手工补充。
4. **手工补充归类正确**：手工录入项自动挂靠当前大类、显示「自定义」标识；输入为空与同大类重名分别给出 Toast 提示且不产生重复项。
5. **每标签独立描述选填**：勾选某需求后该选项下方即时出现「描述（选填）」框；可不填；已填描述在外层标签下方逐条展示；描述为空不做任何拦截。
6. **必填生效**：未选任一需求时提交被拦截（卡片描红 + Toast「请至少选择一项银行需求」）；**描述无必填校验、无文本框描红**。
7. **删除可用**：外层标签与半屏底部已选摘要的「×」均可删除对应项，删除后分组计数同步刷新；全部删完后回到空态。
8. **口径一致**：员工端拜访详情、历史拜访记录列表、首页时间轴、需求跟进、上报需求详情、团队长端拜访只读详情，需求挖掘均按"维度分组标签 + 每条标签各自描述"展示，三个维度色与本文档 §3.4 一致。
9. **范围守界**：第四节列出的项均未变化（其余 5 个模块、AI问案例逻辑、需求状态同步规则、团队长端读写边界、存量记录文本）。

## 六、风险与依赖（可选）

- **依赖（数据源）**：《渠道信任经营 · 需求库速查（三维度）》46 项为需求指标的**唯一数据源**，原文件位于工作区根目录（`./银行渠道拜访需求库速查_三维度.html`）。上线时需由后端提供等价的指标字典接口（含 `dim`／`grp`／`name`／`star`），原型内为内置常量。
- **依赖（原型）**：分类选择器的三色、分组归并口径以本文档 §3.4 为**唯一视觉与交互基准**，原型内就地实现。
- **风险（分组口径）**：46 项原始库的 `cat` 有 24 个（过碎），本 Spec 归并为 8 个展示分组（见 §3.4）。若后续要求按原始 `cat` 展示，需重新确认并同步调整 `grp` 取值。
- **风险（存量数据）**：新增维度字段后，历史记录无维度值。按本 Spec 归入「未分类」桶，**不计入**三维度覆盖率分子；若产品要求补录历史维度，需另行评估迁移成本。
- **风险（描述选填）**：原「需求描述」为模块级必填单条，本次改为**每个标签的独立选填描述**——录入更灵活，但可能出现部分标签无描述；下游详情 / 需求跟进对无描述项仅展示标签本身，不做占位补全。
- **风险（编辑态快照）**：修改态的已选需求及其各自描述按快照回显，若指标库后续下架某指标，编辑态需仍能展示该历史项（快照语义），原型演示时需保留一条含自定义项与已填描述的样本。
