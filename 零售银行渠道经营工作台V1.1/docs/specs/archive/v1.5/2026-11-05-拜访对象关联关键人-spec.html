拜访对象关联网点关键人 — 需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-05 迭代版本号：零售员工工作台 v1.5 / 零售团队长看板 v0.4 流程设计要求：单版（打卡网点选择口径收敛 + 拜访表单 Q1 对象来源改造，属局部增量，无路径决策争议）

修订说明（2026-11-10 同版修订）：本 Spec 落地的「拜访表单 Q1『＋ 添加关键人』就地补录关键人」能力作废。即日起，已录入系统的网点（不论本人名下 / 非本人名下）一律不得在拜访表单内新增关键人——Q1 仅可从该网点已录入的关键人（职位 + 姓名）中多选，并新增「其他」按钮：点选后展开文本框，由员工输入拜访对象信息（自由文本，仅记为本次拜访对象快照、不写入该网点关键人档案），除此之外不再提供任何补录入入口；关键人的新增 / 修改 / 删除统一收敛到「我的渠道 → 编辑建码信息」（仅本人名下网点开放该入口）。已录入网点无关键人时，Q1 展示空态并提示前往「我的渠道」维护关键人信息（非本人名下网点不可维护、仅作提示），不展示「其他」按钮、直接展示拜访对象输入框（自由文本），该模块为必填（未填写即拦截提交并提示「必填未完成」，填写非空即通过）。（2026-11-11 修订：「其他」按钮仅在网点有关键人时展示。）未录入系统（手动输入）网点场景沿用《2026-11-09-拜访打卡网点选择改造》Spec 2026-11-10 修订口径：Q1 空态说明 + 自由文本手输拜访对象，输入非空即满足必填，同样不展示补录入入口。本 Spec 其余已落地口径（对象来源改为该网点关键人多选、按「职位 + 姓名」展示、提交时快照固化、存量记录不追溯改写）继续有效；原「打卡仅可选系统已录入网点 + 名称比对校验」口径已被《2026-11-09-拜访打卡网点选择改造》Spec 于 2026-11-10 推翻，详见该 Spec。

一、需求背景

目标用户：员工端＝客户经理（本人，外勤拜访时填写拜访记录）；团队长端＝只读查看团队成员的拜访记录。

要解决的问题：现有拜访表单 Q1「拜访对象」是与具体网点无关的静态角色多选（行长 / 经办 / 主任 / 理财经理 / 大堂经理 / 其它），只能记录"见了什么职位的人"，无法表达"今天拜访的是××理财经理"。而系统内关键人早已是按网点维护的实体（职位 / 姓名 / 电话 / 生日），却只服务于「我的渠道」的建码展示，与拜访记录完全割裂——同一个网点有多名理财经理时，员工既无法在拜访时点明对象，也在重复录入同一批人的信息。

解决方式：把 Q1「拜访对象」的对象来源从静态角色枚举切换为该网点已录入的关键人（职位 + 姓名，多选）。（2026-11-10 修订） Q1 额外提供「其他」按钮——点选后展开文本框，由员工输入拜访对象信息（自由文本，仅记录本次拜访对象、不写入该网点关键人档案），以覆盖"本次拜访对象不在该网点关键人列表中"的场景；网点无关键人时不再在拜访表单内就地补录，改为空态提示前往「我的渠道 → 编辑建码信息」维护，并直接展示拜访对象输入框（必填，2026-11-11 修订）；关键人档案的增 / 改 / 删统一在「我的渠道 → 编辑建码信息」内完成（仅本人名下网点开放）。原「收敛打卡地点为仅可选系统已录入网点」的口径已被《2026-11-09-拜访打卡网点选择改造》Spec 于 2026-11-10 修订推翻（改为允许手动输入未录入网点），见该 Spec。

竞品差异 / 品类惯例：不适用（本次为既有产品内的对象来源改造，未做外部调研）。

AI 能力边界：不适用。

二、逻辑补齐摘要

2.1 主成功路径

员工「我要拜访 · 立即打卡」→ 选择打卡网点（已录入网点，可以是他人名下；2026-11-10 起亦支持手动输入未录入网点）→ 打卡成功 → 进入拜访表单 → Q1「拜访对象」展示该网点的关键人列表（职位 + 姓名，多选）→ 勾选本次拜访的关键人；若本次拜访对象不在列表中，点选 「其他」按钮展开文本框输入（自由文本，仅记为本次拜访对象快照、不写入关键人档案）（2026-11-10 修订：若该网点无关键人，Q1 展示空态并提示前往「我的渠道」维护，并直接展示拜访对象输入框、该模块为必填（2026-11-11 修订：为空则拦截并提示「必填未完成」）；不再在表单内补录）→ 完成其余模块 → 提交 → 拜访记录以快照固化本次拜访对象（2026-11-10 修订：删除「同时补录的关键人写入该网点关键人档案」，表单内不再产生关键人写入）。

2.2 关键分支

  • 网点已录关键人 → Q1 直接展示该网点关键人（职位 + 姓名）多选，员工勾选。
  • 本次拜访对象不在关键人列表中（2026-11-10 新增；2026-11-11 修订） → 仅当该网点有关键人时，Q1 在关键人选项外附「其他」按钮 → 点选展开文本框，员工输入拜访对象信息（职位 + 姓名，自由文本）；该输入仅作为本次拜访对象快照写入拜访记录，不写入该网点关键人档案（不产生关键人新增 / 变更）；「其他」文本与勾选的关键人可并存。该网点无关键人时不展示「其他」按钮，直接展示拜访对象输入框（见下一条）。
  • 网点无关键人（2026-11-10 修订；2026-11-11 修订） → Q1 展示空态提示「该网点暂无关键人，可前往『我的渠道』编辑建码信息补充」（非本人名下网点改提示「该网点暂无关键人」），并直接展示拜访对象输入框（自由文本），员工可直接填写；不展示「其他」按钮与任何补录入入口，该模块为必填（为空则拦截提交并提示「必填未完成」，填写非空即通过）。
  • 已录入网点（不论本人名下 / 非本人名下）（2026-11-10 修订） → Q1 仅可勾选该网点已录关键人，一律不可在拜访表单内新增关键人。
  • 本人名下网点 → Q1 可勾选；关键人的增 / 改 / 删在「我的渠道 → 编辑建码信息」内完成（与 Q1 操作同一份数据，本处不提供表内补录）。
  • 非本人名下网点 → Q1 可勾选该网点已录关键人；不提供任何新增 / 改 / 删入口（既不可在拜访表单内补录，也不开放「编辑建码信息」）。
  • 重复补录（2026-11-10 起不适用） → 拜访表单内已无新增入口，去重逻辑仅保留在「我的渠道 → 编辑建码信息」侧。
  • 存量历史记录 → 已提交的老记录「拜访对象」保持原文本展示（如"副行长刘洋"），不追溯改写。

2.3 状态与异常

  • 状态：网点有关键人（可勾选 + 「其他」按钮）／网点无关键人（空态提示前往「我的渠道」维护 + 直接展示拜访对象输入框、模块为必填）／「其他」输入态（自由文本，仅入本次记录、不入关键人档案）／已录入网点（不论归属，一律不可表内补录）；Q1 选中态（多选）。（2026-11-10 修订，2026-11-11 修订）
  • 空态：该网点无关键人 → Q1 展示空态提示（本人名下指向「我的渠道」编辑建码信息 / 非本人名下仅提示），不展示「其他」按钮，直接展示拜访对象输入框（自由文本）供员工填写；无可勾选关键人时该输入框为必填（为空则拦截提交并提示「必填未完成」）。（2026-11-10 修订，2026-11-11 修订）
  • 校验失败：该网点存在关键人但 Q1 未选择任何一项、且未填写「其他」 → 按现有必填校验拦截提交；网点无关键人时该输入框同样按必填校验（为空拦截提交并提示「必填未完成」）。（2026-11-10 修订）
  • 「其他」文本口径（2026-11-10 新增）：「其他」文本非空即视为 Q1 已填写；与勾选的关键人并列，写入拜访记录时以「职位 + 姓名」快照形式与勾选项合并展示（顿号分隔）；该文本不回写关键人档案。
  • 异常：提交失败 → Toast「提交失败，请稍后重试」；关键人档案写入已收敛至「我的渠道 → 编辑建码信息」，其写入失败提示沿用该页口径，且保留其余模块已填内容。（2026-11-10 修订）
  • 回退：表单「取消 / 放弃」→ 本次勾选不落库（表单内不再产生关键人写入）。（2026-11-10 修订）
  • 已失效关键人：关键人被删除 / 更名后，已提交记录的拜访对象不受影响（快照语义）。

2.4 跨页影响

  • 主改页：拜访表单（新增态 + 修改态）——Q1「拜访对象」对象来源、展示口径与「其他」自由文本入口（2026-11-10 修订：不再含表内补录能力）。
  • 结果页：员工端拜访详情页——拜访对象展示口径改为「职位 + 姓名」。
  • 被动影响页：员工端首页当日拜访记录卡、历史拜访记录列表行摘要；员工端「我的渠道」建码卡片（关键人档案为同一份数据源，本页「编辑建码信息」维护后需体现）；团队长端拜访详情（只读，展示口径同步）。（2026-11-10 修订）
  • 不涉及：活动表单 / 活动详情（活动无拜访对象）；拜访表单其余 5 个模块；需求跟进与上报需求链路。

2.5 仍未决项

  • 无阻塞项。

五、验收标准

  1. 主路径可完成：员工打卡选点（已录入网点，可非本人名下；亦支持手输未录入网点）→ 拜访表单 Q1 展示该网点关键人（职位 + 姓名）→ 勾选 → 提交后拜访记录正确固化本次拜访对象。
  2. 无关键人空态（2026-11-10 修订，2026-11-11 修订）：网点无关键人时，Q1 展示空态提示（本人名下指向「我的渠道」维护 / 非本人名下仅提示），不展示「其他」按钮、直接展示拜访对象输入框（自由文本），该输入框为必填——为空则拦截提交并提示「必填未完成」。
  3. 已录入网点不可表内补录（2026-11-10 修订）：本人名下与非本人名下网点，Q1 均不出现「＋ 添加关键人」入口，仅可勾选该网点已录关键人；该网点有关键人时可点选「其他」按钮输入自由文本拜访对象。
  4. 档案单一来源（2026-11-10 修订）：关键人档案仅由「我的渠道 → 编辑建码信息」写入（本人名下网点可增 / 改 / 删、按「职位 + 姓名」去重），拜访表单 Q1 不回写；Q1 可选项与建码卡片保持一致。
  5. 快照语义：修改或删除某关键人后，已提交的历史拜访记录其拜访对象展示不变。
  6. 口径一致：员工端拜访详情、首页记录卡、历史拜访记录列表、团队长端拜访详情均展示「职位 + 姓名」口径，且多选对象完整换行不截断。
  7. 手输网点分支（2026-11-09 Spec 2026-11-10 修订）：打卡网点为手动输入（未录入系统）时，Q1 为空态说明 + 自由文本手输拜访对象（非空即满足必填），同样不展示补录入入口。
  8. 范围守界：第四节列出的页面与功能未发生变化。
  9. 「其他」按钮（2026-11-10 新增，2026-11-11 修订）：该网点有关键人时，已录入网点（不论本人名下 / 非本人名下）Q1 附「其他」按钮 → 点选展开文本框、可输入拜访对象信息；输入内容仅写入本次拜访记录快照，不新增 / 变更该网点关键人档案；与勾选关键人并存时按顿号合并展示；网点无关键人时不展示该按钮、直接展示拜访对象输入框；未录入（手输）网点亦不展示该按钮。

六、风险与依赖（可选）

  • 前置依赖（阻塞后续闭环，但不阻塞本轮交付）：「新增渠道 / 建码录入」是全新能力（现有产品仅有"编辑已有网点的建码信息"，无新增网点入口）。（2026-11-10 修订） 打卡已允许手动输入未录入网点（见《2026-11-09-拜访打卡网点选择改造》Spec），但手输网点无关键人档案、不参与网点维度统计；系统内网点仍以已有档案为准。
  • 数据模型（关键 · 2026-11-10 修订）：KeyPerson 仅由「我的渠道 → 编辑建码信息」写入（回退至单一写入来源），拜访表单 Q1 只读该网点关键人、不再回写；非本人名下网点不开放关键人维护入口。
  • 数据质量风险：关键人档案存在存量重复数据（原型演示数据 keyContacts 中曾出现两条完全相同的「理财经理 / 王芳」，本轮已清理），「我的渠道 → 编辑建码信息」新增时需依赖「职位 + 姓名」去重提示，否则脏数据会放大。
  • 敏感字段分层：关键人电话 / 生日为敏感字段，录入端明文可维护、展示端（尤其团队长端）按现有脱敏口径处理，需保持一致。
  • 体验风险（2026-11-10 修订）：已录入网点若长期无关键人档案，Q1 将无任何可勾选项，只能空态 + 通过自由文本输入框留痕（2026-11-11 修订：该输入框为必填）——仍建议在产品运营上引导员工尽快在「我的渠道」补建关键人，以提升「拜访对象」的结构化留痕价值。
  • 同步风险：关键人档案由「我的渠道」单一来源写入，需确认 Q1 可选项与建码卡片、团队长端只读视图在同一数据源上的一致性。
