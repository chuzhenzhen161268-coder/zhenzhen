# 过程跟进网点联动 — 需求规格（Spec）

**产品名称**：零售银行渠道经营工作台
**模式**：迭代 (iterate)
**平台类型**：移动端 Web（企微 H5）
**日期**：2026-11-02
**迭代版本号**：零售员工工作台 `v1.5` / 零售团队长看板 `v0.4`
**流程设计要求**：跳过（同一页内一个既有控件的联动范围扩展，不涉及页面流转、入口或分支决策的变化）

---

## 一、需求背景

**目标用户**：与现有用户一致。员工端＝客户经理（名下管辖一批网点）。

**要解决的问题**：员工端首页「过程跟进」四格当前只随「我的渠道」顶部的「时间周期」联动，**不随同一行的「网点选择器」联动**——员工把网点切到某个具体网点后，四格仍显示名下全量汇总，与「我的渠道」经营数据卡的口径不一致，无法回答"这个网点本周拜访了几次、还剩几条需求未满足"。改造后：过程跟进四格与「我的渠道」共用同一套「时间周期 + 网点」选择状态、整页联动；数据口径由 `userId + 周期` 扩为 `userId + 周期 + 网点`。

**竞品差异 / 品类惯例**：不适用。本产品为内部经营工作台，无对外竞品；"同页筛选控件驱动页内多模块"为通用做法，本次沿用。

**AI 能力边界**：不适用（本需求不涉及 AI 生成 / 判断 / 自动化）。

---

## 二、逻辑补齐摘要

### 2.1 主成功路径

员工端首页，「我的渠道」顶部网点选择器选中某具体网点 → 同页「过程跟进」四格数值按「该网点 + 当前所选周期」重算并即时刷新 → 四格点击行为与跳转目标不变（拜访/活动滚动至渠道拜访模块，需求格进入需求跟进表）。

### 2.2 关键分支

- 网点＝「全部网点」（员工维度）→ 四格展示员工名下全量汇总（与现状一致）
- 网点＝具体网点（网点维度）→ 四格展示该网点数据；清回「全部网点」恢复汇总
- 周期切换（昨日 / 本周 / 自然月 / 本年）→ 在「当前所选网点」范围内重算四格（周期与网点两个维度同时生效、可任意组合）
- 「需求未满足」的紧急副文本「N条紧急」→ 同口径随「网点 + 周期」重算
- 四格点击行为不变：拜访次数 / 活动次数 → 滚动至「渠道拜访」模块；需求已满足 / 需求未满足 → 进入「需求跟进表」
- 网点选择器自身行为不变（弹层、搜索、银行大类 chips、最近选择、建码卡片显隐均不动）

### 2.3 状态与异常

- 状态：全部网点态（员工汇总）／具体网点态（该网点数据），每种 × 四个周期
- 异常：沿用「过程跟进」既有的失败态（接口失败显示「--」+ 重试提示），本次不新增失败链路
- 回退：网点清回「全部网点」、周期切回原值，四格各自恢复为对应口径的数值

### 2.4 跨页影响

- 被动影响页：员工端首页「过程跟进」模块
- 数据口径：过程数据聚合键由 `userId + 周期` 扩为 `userId + 周期 + 网点`
- 不受影响：员工端「我的渠道」经营数据卡口径（上一轮已改造）、「渠道星级分布」（仍只随周期联动）、「需求跟进表」自身的网点筛选、团队长端全部模块

### 2.5 仍未决项

无阻塞项。

### 3.3 各受影响页的功能变化（特性级，按页）

#### 员工端首页「过程跟进」模块

- 四格数值改由「当前所选周期 + 当前所选网点」共同决定：网点＝「全部网点」时展示员工名下汇总（与现状一致），网点＝具体网点时展示该网点数据；两维度可任意组合、同时生效
- 「需求未满足」的紧急副文本「N条紧急」同口径随两维度刷新
- 四格点击行为与跳转目标不变（拜访 / 活动 → 滚动至「渠道拜访」模块；需求 → 进入「需求跟进表」）
- 空态口径不变：该网点该周期无数据显示「0」、不显示副文本

#### 员工端「我的渠道」模块

- 无功能变化：其顶部网点选择器的作用域由「仅本模块」扩展为「本模块 + 过程跟进模块」；选择器自身交互与「我的渠道」内各项展示均不变

## 四、不在本次范围内（明确边界）

- ❌ 不改员工端「我的渠道」经营数据卡的取值口径（上一轮已完成：选中具体网点时 5→4 项、数值切该网点），保持现状
- ❌ 不改员工端「渠道星级分布」——仍只随周期联动，不引入网点维度
- ❌ 不改「需求跟进表」自身的网点筛选与数据口径；本轮**不**让「过程跟进 → 需求跟进表」的跳转继承当前所选网点（维持需求跟进表独立筛选，见 §六 风险）
- ❌ 不改网点选择弹层实现本身（搜索、银行大类 chips、最近选择、空态兜底）
- ❌ 不改员工端其余模块（重点关注、建码卡片、渠道拜访、工具库、知识库等）
- ❌ 不改团队长端全部模块，含其「过程跟进 / 需求管理」的独立网点筛选器
- ❌ 两份 PRD 中与本次无关的章节本轮不变（相关章节已同步更新，见 §3.1）
- ❌ 埋点：本轮不新增、不修改任何埋点

## 五、验收标准

1. **主路径可完成**：员工端首页把网点切到某具体网点后，「过程跟进」四格与紧急副文本立即变为该网点对应数值；清回「全部网点」恢复员工汇总
2. **关键分支成立**：逐条对应 2.2 —— 周期与网点两维度可任意组合且同时生效；某网点某周期无数据显示「0」且无副文本；四格点击跳转不变
3. **状态与异常口径**：逐条对应 2.3 —— 接口失败仍显示「--」+ 重试提示；网点 / 周期回退后四格恢复对应口径数值
4. **范围守界**：第四节列出的模块、口径、埋点与版本号均未发生变化

## 六、风险与依赖（可选）

- **推翻既有裁定（文档一致性）**：本 Spec 推翻 2026-11-02 同日早些时候确认的「过程跟进只跟周期、不引入网点维度」口径，即 `product-manifest.json` 决策日志中的「过程跟进联动范围」条目。该条目已于本 Spec 批准后改写为「周期 + 网点双维度」。另经核定：`./docs/specs/2026-11-02-名下渠道数维度约束-spec.md` 中提及「不受影响」的两处（§二 2.4 与 §四）所指为员工端「需求跟进表」与团队长端「过程跟进 / 需求管理」的网点筛选，均不在本 Spec 改动范围内，无需修订。
- **风险（跳转口径不一致）**：「过程跟进」按网点展示的「需求未满足」数，与点击进入的「需求跟进表」独立网点筛选之间可能出现数量对不上（如四格显示 3 条、进去看到 8 条）。本轮默认**不继承**当前网点、保持「需求跟进表」现状；若评审认为需要继承，作为独立后续需求处理。
- **前置依赖（阻塞数据侧）**：过程数据统计接口需支持按 `userId + 周期 + networkId` 聚合。当前口径仅为 `userId + 周期`（员工 PRD §5.2 依赖说明）。数仓需确认可提供网点级过程数据（拜访记录表 / 需求记录表具备 `networkId` 归属）。**兜底口径**：若网点级过程数据不可得，四格在具体网点态下显示「--」并提示暂不支持，全部网点态不受影响。
- **依赖**：「过程跟进」与「我的渠道」共用同一套「周期 + 网点」选择状态，建议复用同一状态源，避免再次分叉。
- **风险（数据形态）**：网点级过程数据量级远小于员工级，可能出现大量 0 值网点；空数据展示沿用「0，不显示副文本」口径（文案已在页 PRD 细化）。
