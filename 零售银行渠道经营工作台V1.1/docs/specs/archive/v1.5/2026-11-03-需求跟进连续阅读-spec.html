需求跟进连续阅读 — 需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-03 迭代版本号：零售员工工作台 v1.5 / 零售团队长看板 v0.4 流程设计要求：单版（在既有「列表 → 需求详情 → 返回列表」链路上新增「详情 ↔ 上一条 / 下一条 ↔ 相邻详情」的同层级线性浏览分支，无路径争议、无需多版对比）

一、需求背景

目标用户：员工端＝客户经理（本人名下需求跟进）；团队长端＝团队长（需求管理 Tab 查看团队需求、处理员工上报需求）。 要解决的问题：需求条数较多时无法连续阅读——看完一条需求、返回列表时筛选状态丢失（需重做筛选），且逐条查看必须反复「返回列表 → 重新筛选 → 再点开」。解决后：从任一需求列表进入详情后，可原地用「下一条 / 上一条」前后浏览同批需求；返回列表时筛选与滚动位置保持不变，无需重做筛选。 竞品差异 / 品类惯例：本次未做外部调研（既有功能域的局部体验改造），不适用。品类参照：团队长端已定义「从详情页返回时保留状态页签、排序方式和滚动位置」规范（团队长端 PRD § 5.2 上报需求列表、§ 5.5 过程跟进·需求管理），本次员工端对齐该既有规范，团队长端复用同一规范。 AI 能力边界：不适用。

二、逻辑补齐摘要

2.1 主成功路径

员工端：在「需求跟进表」按网点 + 满足状态筛选出目标需求集合 → 点开一条进入需求详情 → 用右下角「下一条」/ 左下角「上一条」在该集合中前后浏览需求 → 返回列表，筛选与滚动位置保持。

团队长端（两处）：①过程跟进 →「需求管理」Tab，按周期/员工/网点 + 状态 chips 筛选 → 点开一条进入需求详情 → 用「下一条 / 上一条」逐条浏览；②团队重点关注 →「上报需求列表」，按状态页签 + 排序筛选 → 点开一条进入上报需求详情 → 用「下一条 / 上一条」逐条浏览。两处返回列表均保持筛选/页签/排序与滚动位置。

2.2 关键分支

  • 分支 1 · 未保存修改拦截（仅员工端）：员工端需求详情的「解决方案」与「状态」可编辑。点「下一条」或「上一条」时——本页存在未保存改动 → 弹二次确认，提供「保存并继续 / 放弃改动」；无改动 → 直接翻页。团队长端两处详情页均为只读（解决方案不可编辑，动作为「归档 / 标记跟进」即时生效），不适用本分支。
  • 分支 2 · 浏览序列冻结（快照口径，两端通用）：从列表进入详情时，冻结当时的筛选结果与排序为「浏览序列」；本次浏览期间因操作导致的状态变化（如标记/归档/改状态）不影响本次浏览序列，「下一条」仍按冻结序列推进。返回列表后，列表按最新筛选结果实时展示。
  • 分支 3 · 首末条边界（两端通用）：当前已是浏览序列最后一条时，「下一条」置灰；已是第一条时，「上一条」置灰。点击置灰按钮给 Toast（末条「已到最后一条」、首条「已是第一条」），页面不跳转。
  • 分支 4 · 入口差异（两端通用）：仅在从对应列表进入详情时展示「上一条 / 下一条」；从非列表入口进入详情时两者均不展示——
  • 员工端：首页「需求跟进区」摘要条进入；
  • 团队长端：团队重点关注首页「上报需求」预览卡片进入上报需求详情。
  • 分支 5 · 返回状态保持（两端通用）：返回列表时保留进入前的筛选与列表滚动位置。员工端＝网点筛选 + 满足状态 + 滚动位置；团队长端＝需求管理 Tab 的周期/员工/网点 + 状态 chips + 滚动位置、上报需求列表的状态页签 + 排序 + 滚动位置。
  • 分支 6 · 员工端「保存更新」口径：需求详情点「保存更新」只做保存与提示（Toast「需求状态已更新」），停留在当前详情页、不返回列表（与「标记跟进」一致的即时提示口径）。保存后：① 详情页「当前状态」标签展示为刚保存的状态；② 需求跟进表对应行的状态标签与「未满足」计数同步刷新；③ 该需求按新状态重新参与列表筛选；④ 本页基线状态重置为已保存值，此后翻页不再触发未保存拦截。「无法满足」上报团队长的既有口径不变。

2.3 状态与异常

  • 状态：
  • 有相邻条（正常态）：「上一条 / 下一条」按所在位置可点。
  • 第一条 / 最后一条：对应侧的按钮置灰不可点（保留按钮位置，避免布局跳动），点击给 Toast（首条「已是第一条」、末条「已到最后一条」）。
  • 无列表上下文（从首页摘要/预览卡片进入详情）：不展示「上一条 / 下一条」。
  • 返回列表：各端筛选、页签/排序、滚动位置均保持。
  • 异常：
  • 保存失败（仅员工端）：Toast「保存失败，请稍后重试」，停留当前详情，不翻页、已填内容不丢失（沿用现有保存口径）。
  • 浏览序列仅含当前一条（理论兜底）：该条既是首条也是末条，「上一条 / 下一条」均按边界处理。
  • 回退：详情页点「取消」／左滑返回（员工端）或左上返回（团队长端）→ 返回对应列表（保持筛选与滚动位置）；员工端未保存改动按现有「取消」口径丢弃。

2.4 跨页影响

  • 入口页：
  • 员工端「需求跟进表」、团队长端「过程跟进·需求管理」Tab、团队长端「上报需求列表」——返回时保持筛选与滚动位置。
  • 员工端首页「需求跟进区」摘要、团队长端团队重点关注「上报需求」预览卡片——入口不变、不新增「上一条 / 下一条」。
  • 结果页：员工端「需求详情」、团队长端「需求详情」（需求管理 Tab）、团队长端「上报需求详情」——均新增内容区左下角「上一条」与右下角「下一条」悬浮按钮及双向翻页能力；员工端「保存更新」后停留当前详情页并刷新展示。
  • 被动影响页：各需求列表行状态标签在操作后刷新；员工端「保存更新」后，详情页「当前状态」标签与需求跟进表对应行状态标签、计数同步刷新，并按新状态重新参与筛选；员工端首页需求跟进摘要状态标签按最新刷新；员工端「无法满足」上报团队长的既有口径不变。
  • 不涉及：各列表的筛选控件本身（员工端网点弹层/满足状态下拉、团队长端周期/员工/网点下拉与状态 chips、上报需求状态页签与排序按钮）逻辑不变；浏览序列的生成方式属实现层，Spec 只定口径。

2.5 仍未决项

  • 无阻塞项。

  • ❌ 不做「跳转到指定序号 / 首末条快捷跳转」（仅提供相邻的上一条 / 下一条）。
  • ❌ 不改需求详情的其他进入路径：员工端首页「需求跟进区」摘要、重点关注「需求未满足」H5、团队长端团队重点关注「上报需求」预览卡片——均不新增翻页能力（仅作为「不展示」判定来源）。
  • ❌ 不改筛选控件逻辑：员工端网点选择弹层（搜索/银行大类/最近选择）与满足状态下拉、团队长端周期/员工/网点下拉与状态 chips、上报需求状态页签与排序按钮的规则均不变。
  • ❌ 不改「超时关注」相关页面（团队长端超时关注列表/详情）——不属需求列表，不加「上一条 / 下一条」。
  • ❌ 不改团队长端「上报需求」的处理动作（标记跟进/归档）与其触发口径。
  • ❌ 不做批量处理或连续保存队列（每条独立保存/操作，不聚合提交）。
  • ❌ 不做浏览序列的服务端固化或跨会话记忆（仅本次会话内、进入详情时冻结）；本原型为内存态覆盖，刷新后回到基线数据。
  • ❌ 埋点：本轮不新增、不修改任何埋点

五、验收标准

  1. 主路径可完成：在员工端需求跟进表、团队长端需求管理 Tab、团队长端上报需求列表各自筛选后点开一条需求，均可点「下一条」/「上一条」在相邻需求详情间前后浏览。
  2. 返回状态保持：三个列表返回时均保持进入前的筛选（团队长端含页签/排序）与滚动位置。
  3. 未保存拦截成立（仅员工端）：员工端详情页有未保存改动时点「下一条」或「上一条」弹二次确认（保存并继续 / 放弃改动）；无改动时直接翻页；团队长端两处详情无此分支且不出现拦截。
  4. 快照口径正确：把当前条操作（员工端改状态、团队长端标记/归档）后，本次翻页仍按进入时的冻结序列推进；返回列表后列表按最新结果展示。
  5. 首末条边界正确：三处详情浏览到序列最后一条时「下一条」置灰、点击提示「已到最后一条」；浏览到第一条时「上一条」置灰、点击提示「已是第一条」。
  6. 入口区分正确：三处列表进入详情展示「上一条 / 下一条」；员工端首页摘要、团队长端上报需求预览卡片进入详情均不展示。
  7. 员工端保存口径正确：需求详情点「保存更新」后停留当前详情页并提示「需求状态已更新」；详情页「当前状态」标签与需求跟进表对应行状态标签、计数同步刷新，并按新状态重新参与筛选。
  8. 范围守界：第四节列出的页面、模块与功能均未发生变化。

六、风险与依赖（可选）

  • 依赖：员工端需求跟进表列表需按网点 + 满足状态真实返回数据（原型已补足可过滤的示例数据）。
  • 需确认（不阻塞）：真实产品「返回列表丢筛选状态」的成因（路由重渲染 / 组件状态未持久化），修复应落在该层；原型层面由 subStack 导航保留状态，本次需把「保持」明确为规范并补滚动位置保持。
