拜访打卡凭证增强 —需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-23 迭代版本号：不升版本号（沿用 零售员工工作台 v1.5 / 零售团队长看板 v0.4，仅页级追加本版增量） 流程设计要求：单版（打卡主链新增「拍照 → 照片必填校验 → 生成凭证」节点，并让凭证在同端拜访详情与团队长端只读详情展示；无页面流转重构）

本文件地位：本版增量规格，只承载本次变更，不复述 v1.5 / v0.4 基线能力（基线以规格文档 2026-11-11-渠道经营工作台员工端v1.5-团队长端v0.4规格文档-spec.md 与两份 PRD 正文为准）。基线中「打卡网点选择」（搜索 / 未录入二次确认 / 归属标签）保持有效，但本次调整其数据源与呈现：因网点距离数据不可得，取消原「附近网点（按距离升序取前 4）」，改为空态展示「本人名下网点」（不带距离）；输入关键字后按关键字匹配展示相关网点，无匹配则不展示；列表由页内内联平铺改为「点击网点输入框才弹出的下拉面板」。本次同时确立定位口径：打卡定位地址一律由 GPS 自动获取，页面不提供任何手动选择 / 编辑地址的能力（不可点选地图选点、不可手动改地址），地图仅作只读展示。

一、需求背景

目标用户：与现有一致。员工端＝零售线客户经理（外勤拜访、需打卡留痕）；团队长端＝零售线团队长（只读查看团队拜访记录，本次为被动展示方）。

要解决的问题：现有打卡凭证只有「网点名 + 打卡时间」两项，无法回答「人是否确实到过现场」——外勤场景存在代打卡、未到店打卡的可能，团队长也无从核验拜访真实性；同时拜访现场的照片、现场说明（如「负责人不在，已留名片」）没有沉淀位置。改造后：员工在打卡页可看到定位地图与结构化地址（地址由 GPS 自动获取、不支持手动选择）、拍摄带真实时间与地点水印的现场照片（必填）、填写现场打卡备注，形成可信打卡凭证；该凭证在员工端拜访详情与团队长端只读详情可查看。

竞品差异 / 品类惯例：参照企微「外出打卡」这一主流外勤考勤做法——其以「地图定位 + 打卡图片（水印照片）+ 打卡备注 + 打卡即留痕」构成可信外勤凭证。本次借鉴其位置可视化、水印照片凭证、现场备注三项能力；不引入其考勤模块属性（「上下班打卡 / 外出打卡」页签、底部「打卡 / 申请 / 统计 / 考勤机」导航），因本产品是渠道经营工作台、打卡属拜访业务凭证而非考勤。本次未另做外部调研。

AI 能力边界：不适用（本需求为确定性表单与凭证采集，不涉及 AI 生成、判断或自动化）。

二、逻辑补齐摘要

2.1 主成功路径

打卡页 → 查看定位地图与结构化地址（地址由 GPS 自动获取、不支持手动选择；地图只读，可「重新定位」）→ 选择拜访网点（点击输入框弹出下拉：空态为「本人名下网点」、输入关键字为匹配结果）→ 拍摄现场水印照片（1 张，必填，仅相机）→ 填写打卡备注（选填）→ 点「打卡」→ 生成含「网点 + 地址 + 照片 + 备注 + 时间」的打卡凭证 → 进入「是否立即填写拜访记录」→ 拜访表单（本次不改）。

2.2 关键分支

  • 分支 1（照片必填校验）：未拍摄照片时点「打卡」→ 拦截打卡、提示「请先拍摄打卡照片」、不生成凭证；补拍后即可打卡。
  • 分支 2（相机权限被拒 / 拍摄失败）：调起相机被拒或拍摄失败 → 提示「请在系统设置中开启相机权限」；其余区域（网点、备注）可继续填写，但不生成凭证（照片仍为必填）。
  • 分支 3（拍照与重拍）：点「打卡图片」区（左侧方形拍摄框 / 「拍摄水印照片」入口）→ 调起系统相机拍摄 → 生成叠加真实拍摄时间（取系统当前时间，格式 YYYY-MM-DD HH:mm）+ 真实地点（当前定位地址）水印的照片 → 以方形缩略图回显（含水印）；支持删除后重拍，照片固定 1 张（重拍覆盖原图）。
  • 分支 4（定位失败 / 无权限）：沿用现状失败态，不阻断网点选择与打卡；地图区显示「暂未获取 GPS 定位」占位；水印中的地点回退为所录网点名，无网点名时显示「定位失败」；照片仍必填。
  • 分支 5（定位获取口径）：打卡定位不提供手动选择地址的能力——不可点选地图进行选点、不可手动输入 / 编辑 / 搜索地址；地图卡为只读展示（设备当前定位点 + 结构化地址），「重新定位」仅将定位复位为设备当前位置。定位失败时按分支 4 处理（不阻断打卡链路）。
  • 分支 6（打卡校验顺序）：点「打卡」→ ①未选网点且输入为空 → 提示「请先选择拜访网点」；②已选/已填但未拍照 → 提示「请先拍摄打卡照片」；③通过上述校验后，已录入网点直接生成凭证、未录入网点弹二次确认「确认拜访该网点？」（沿用现状）；「取消」关闭弹窗并保留输入与照片。
  • 分支 7（打卡备注）：选填独立字段，作为打卡凭证的一部分；不回填拜访表单任何字段，留空不影响打卡。
  • 分支 8（存量记录）：历史打卡记录无照片 / 备注 → 两端详情页对应区域展示占位（「—」/「暂无」），不追溯、不迁移。
  • 分支 9（网点选择下拉）：网点输入框未点击时不展开列表；点击 / 聚焦输入框 → 从输入框下方弹出下拉面板，空态展示「本人名下网点」（因网点距离数据不可得，不展示距离、不按距离排序）；输入关键字 → 按关键字匹配展示相关网点（本人名下优先）；无匹配时不展示任何内容；点选某网点 → 收起为已选态并关闭下拉；清除已选网点 → 回到输入框态、下拉收起。

2.3 状态与异常

  • 状态：
  • 照片区——未拍摄（企微式左侧方形拍摄框 + 右侧「拍摄水印照片」入口）/ 已拍摄（方形缩略图 + 水印 + 右上「×」删除 + 「重拍」）；
  • 网点选择——未展开（仅输入框）/ 已展开·空态（下拉展示本人名下网点列表）/ 已展开·有匹配（关键字搜索结果）/ 已展开·无匹配（不展示任何内容）/ 已选（收起为已选网点行）；
  • 定位区——定位成功（地图 + 地址）/ 定位失败（占位，不阻断）；
  • 打卡——进行中 / 已完成（打卡成功确认区展示完整凭证）；
  • 编辑态——由拜访详情「修改」进入时，打卡凭证卡（照片 / 备注 / 地址）全部只读。
  • 异常：相机权限拒绝、拍照失败、定位失败（三项均不阻断网点选择；照片必填仍阻断打卡）/ 备注超长（页内限制输入长度）。
  • 回退：二次确认点「取消」→ 关闭弹窗、停留打卡页并保留输入与照片；清除已选网点 → 回到输入态（照片与备注保留）；重拍 → 覆盖原照片。

2.4 跨页影响

  • 主影响页：员工端「我要拜访」打卡页（新增只读定位地图区、打卡图片、打卡备注，打卡按钮改版，网点选择由内联平铺改为下拉）。
  • 被动展示页：
  • 员工端拜访详情页：新增只读「打卡凭证」展示（照片、打卡备注、定位地址 + 打卡时间）。
  • 员工端拜访记录编辑态：原「打卡凭证只读卡」扩展为含照片 / 备注 / 地址（仍只读、不可修改）。
  • 团队长端拜访只读详情页：新增只读「打卡凭证」展示（照片、打卡备注、定位地址）。
  • 不受影响：打卡网点的归属标签口径与未录入网点二次确认（未录入仍走二次确认）、搜索本人名下优先、已选收起 / 清除、拜访表单各模块（拜访对象、需求挖掘）、历史拜访记录列表行（不露出照片 / 备注）、我的渠道、需求跟进表、团队长端其余模块。
  • 呈现微调：①打卡网点下拉数据源与呈现调整——空态展示「本人名下网点」、输入关键字展示匹配结果、无匹配不展示，取消距离展示与距离排序（距离数据不可得），列表由页内内联平铺改为点击输入框弹出的下拉面板；②打卡定位区改为只读地图展示 + 重新定位，不提供手动选择地址能力。

2.5 仍未决项

  • 无阻塞项。本次已收敛为「定位地址仅由 GPS 自动获取、不提供手动选点」，不再存在「手动微调定位点削弱现场真实性」的风险。

3.3 各受影响页的功能变化（特性级，按页）

员工端「我要拜访」打卡页

  • 顶部定位区由「GPS 卡片（纯文本地址）」升级为「只读地图 + 结构化地址 + 重新定位」：地图展示设备当前定位点、不可交互（不支持点选 / 拖动选点）；定位地址仅由 GPS 自动获取，页面不提供任何手动选择或编辑地址的入口；「重新定位」按钮可将定位复位为设备当前位置；定位失败时该区展示占位、不阻断后续操作。
  • 拜访网点选择调整（数据源 + 呈现）：输入框默认不展开列表，点击 / 聚焦输入框才从下方弹出下拉面板——空态展示「本人名下网点」；输入关键字按关键字匹配展示相关网点（本人名下优先）；无匹配时不展示任何内容；点选后收起为已选态、下拉关闭，清除已选网点回到输入框态。因网点距离数据不可得，取消原「附近网点按距离升序取前 4」与距离数值展示；归属标签与未录入网点二次确认口径不变。
  • 新增「打卡图片」模块（企微式排版）：未拍态为左侧方形拍摄框 + 右侧「拍摄水印照片」文案；调起系统相机拍摄 1 张现场照片、自动叠加真实拍摄时间（系统当前时间）+ 真实地点（当前定位地址）水印，已拍态为方形缩略图（含水印）+ 右上「×」删除 + 「重拍」；该模块必填，未拍不可打卡；不支持从相册选取。
  • 新增「打卡备注」模块：选填独立字段，作为打卡凭证的一部分，不回填拜访表单。
  • 打卡按钮改为企微式圆形「打卡」按钮（含真实当前时间 HH:mm），替换原「立即打卡」；点击校验顺序为「网点 → 照片 → （未录入）二次确认」，全部通过后生成凭证。
  • 打卡成功后「打卡成功确认区」展示完整凭证（网点、地址、照片缩略图、备注、真实时间）；该凭证中的打卡时间取系统当前时间（YYYY-MM-DD HH:mm:ss），与照片水印时间一致。

员工端「拜访详情」+「拜访记录编辑态」

  • 拜访详情新增只读「打卡凭证」展示：现场照片、打卡备注、定位地址与打卡时间；存量无照片 / 备注记录展示占位。
  • 编辑态的「打卡凭证只读卡」由原「网点名 + 时间」扩展为含照片 / 备注 / 地址，全程只读、不可修改（沿用「打卡凭证不可修改」口径）。

团队长端「拜访记录只读详情」

五、验收标准

  1. 主路径可完成：员工在打卡页可看到只读定位地图与结构化地址（地址由 GPS 自动获取、无手选入口）→ 点击输入框在下拉（空态为「本人名下网点」/ 关键字匹配结果）中选定拜访网点 → 拍摄 1 张水印照片（必填，水印为真实时间 + 真实地点）→ 填写打卡备注（选填）→ 点「打卡」→ 生成含「网点 + 地址 + 照片 + 备注 + 时间」的凭证 → 进入「是否立即填写拜访记录」。
  2. 关键分支成立（逐条对应 2.2）：未拍照打卡被拦截并提示；相机权限被拒不生成凭证；未录入网点仍走二次确认；定位失败不阻断网点选择但照片仍必填；照片支持删除重拍且固定 1 张；定位地址仅由 GPS 自动获取、页面无任何手选 / 手改地址入口（地图只读，「重新定位」仅复位当前位置）；网点下拉仅在点击输入框时展开、空态展示本人名下网点、无匹配不展示、列表不带距离、选中后收起。
  3. 状态与异常口径（逐条对应 2.3）：定位失败 / 相机被拒均有明确提示且不影响其它区域填写；二次确认「取消」保留输入与照片；编辑态打卡凭证全程只读。
  4. 展示口径成立：员工端拜访详情与团队长端只读详情均展示打卡凭证（照片 / 备注 / 定位地址，照片水印含真实时间与地点）；历史拜访记录列表行不展示；存量无照片 / 备注记录展示占位。
  5. 范围守界：第四节列出的页面与功能未发生变化（尤其打卡网点归属标签口径与未录入网点二次确认、拜访表单）。

六、风险与依赖

  • 前置依赖：
  • 相机调用能力（企微 H5 容器内的相机唤起 / getUserMedia）与照片水印合成（时间 + 地点叠加）；
  • 逆地理编码（经纬度 → 结构化地址）与只读地图组件；
  • 网点距离数据（本次不可得）：网点选择因此不依赖距离（见第四节边界）；
  • 照片存储与上传（H5 端需压缩，避免流量与加载问题）。
  • 风险：
  • 定位无法人工纠偏：本次明确「定位地址仅由 GPS 自动获取、不支持手动选择」，室内 / 信号弱场景下可能出现地址偏差且无法人工纠正；缓解措施为「照片必填」+「重新定位」重试；若实测偏差影响面大，再评估是否放开受控的手动选点。（原「手动微调定位点削弱现场真实性」的风险随该能力取消而解除）
  • 企微容器相机 / 地图能力可用性：需研发先行确认容器内相机与地图组件的可用性与权限链路，未确认前按「能力缺失即降级为占位、不阻断打卡链路」兜底。
  • 与并行迭代的衔接：本次沿用 v1.5 / v0.4 版本、以页级追加修订落地；基线「打卡网点选择逻辑」口径不变（仅呈现方式改为下拉面板），与既有规格文档无冲突。
