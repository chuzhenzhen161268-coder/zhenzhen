## 一、需求背景

**目标用户**：与现有用户一致。员工端＝客户经理（名下管辖一批网点）；团队长端＝团队长（管辖团队覆盖的全部网点）。

**要解决的问题**：网点选择器目前是纯扁平列表；真实数据量级下可选网点达几百个、跨多家银行，用户只能逐个滚动查找，定位效率低。改造后用户可先按"银行大类（银行品牌）"缩小范围，或直接输入关键字跨大类命中，快速定位目标网点。

**竞品差异 / 品类惯例**：不适用。本产品为内部经营工作台，无对外竞品；网点选择属成熟交互模式，采用"搜索 + 分类筛选"通用范式即可，无差异化诉求。

**AI 能力边界**：不适用（本需求不涉及 AI 生成 / 判断 / 自动化）。

## 二、逻辑补齐摘要

### 2.1 主成功路径

用户在任一含网点筛选的页面点击网点筛选 → 打开网点选择弹层 → 通过搜索框输入关键字跨大类命中，或点选"银行大类"缩小范围 → 点选目标网点 → 弹层关闭，筛选条件回填为该网点。

### 2.2 关键分支

- **搜索命中**：输入关键字 → 跨全部大类模糊匹配网点名称 → 列出命中网点；若此时已选中某大类，则仅在所选大类内匹配
- **大类过滤**：点选某银行大类 chip → 列表只保留该大类的网点
- **二者交集**：已选大类 + 有搜索词 → 结果为「所选大类内匹配该关键字的网点」
- **交集为空**：显示空态 + 「清除大类，在全部大类中搜索」 → 点击后大类回到"全部"、保留搜索词重新匹配
- **大类超出显示行数**：点「更多」展开 → chips 区内部滚动显示全部大类；再次收起
- **最近选择**：本设备曾选过网点 → 置顶区展示最近 5 个；无记录 → 该区不展示

### 2.3 状态与异常

- **状态**：默认（大类 = 全部 + 搜索为空 = 展示可见范围内全部网点）；无结果（空态，含清除大类兜底）；已选大类（chip 选中态）；「更多」展开 / 收起；最近选择有 / 无
- **异常**：网点数据加载失败 → 列表区给出加载失败提示与重试入口；当前可见范围内无任何网点 → 空态
- **回退**：关闭弹层（点遮罩 / 关闭按钮）→ 不改变已选网点值；重新打开弹层 → 大类与搜索均回到默认态（全部 + 空）

### 2.4 跨页影响

- **入口页**：员工端「我的渠道」（网点选择）、员工端「需求跟进表」（网点筛选）、团队长端「过程跟进 · 需求管理」（网点筛选）
- **结果页**：无新增
- **被动影响页**：无（其他展示网点列表的页面本次不改造）

### 2.5 仍未决项

无阻塞项。

## 五、验收标准

1. **主路径可完成**：在 3 处任一入口点击网点筛选 → 弹层内可通过搜索或大类快速定位目标网点 → 选中后筛选条件正确回填为该网点
2. **关键分支成立**：逐条对应 2.2 —— 搜索可跨大类命中；选大类后列表只含该大类；搜索与大类同时存在时取交集；交集为空时出现空态与「清除大类」兜底且点击后恢复；大类超行时「更多」可展开收起；有历史时最近选择置顶展示最近 5 个
3. **状态与异常口径**：逐条对应 2.3 —— 默认态为"全部 + 空搜索"的全量列表；加载失败有重试入口；关闭弹层不改变已选值；重新打开回到默认态
4. **范围守界**：第四节列出的页面与功能未发生变化

## 六、风险与依赖（可选）

- **前置依赖（阻塞数据侧）**：网点主数据需新增独立字段「银行品牌／银行大类」（`bankBrand`；当前仅有 `networkId` / `networkName`），作为大类 chips 的唯一数据源，否则大类筛选无数据可筛；已明确不采用「按网点名称前缀解析」兜底。
- **依赖**：3 处网点选择器当前是三份互相独立的复制实现，本次须抽取为同一实现；否则后续仍会分叉。
- **风险**：真实数据下"全部网点"默认态需渲染几百条，需配合分页或虚拟滚动，否则首屏卡顿。
- **风险**：「最近选择」采用本地存储，换设备 / 清缓存即丢失，用户对"最近用过"的预期可能不一致。
- **风险**：大类"固定优先级"需与业务确认品牌清单与排序（国有大行 → 股份制 → 城商 / 农商）。
