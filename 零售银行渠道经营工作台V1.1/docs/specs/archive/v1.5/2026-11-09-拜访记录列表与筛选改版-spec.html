拜访记录列表与筛选改版 — 需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-09 迭代版本号：不升版本号（沿用 零售员工工作台 v1.5 / 零售团队长看板 v0.4，仅页级追加修订行） 流程设计要求：单版（团队长端新增「更多」入口、单条记录点击改跳详情、日历点击改为页内筛选，涉及入口与跳转关系变化，craft 画一版主流程）

一、需求背景

目标用户：团队长（团队长端）与零售客户经理（员工端），与现有用户一致，不新增画像。

要解决的问题： - 团队长端「拜访记录」模块把「查看记录」和「进入二级列表」混在一起——点单条记录会跳到二级列表页而不是详情，二级列表页又顶着一个月历。团队长按周/月/考核期盘点团队拜访与活动时，缺少周期维度，也看不到某周期内各类型的条数总览。 - 员工端「历史拜访记录」把类型筛选与时间筛选混在一行（全部/拜访/活动/自然月），且看不到某周期内各类型的记录条数。

竞品差异 / 品类惯例：不适用（本次为既有页面的入口与筛选调整，未做外部调研）。内部惯例对齐：周期筛选沿用全站统一的时间周期控件（昨日/本周/自然月/本年/考核月 + 考核期次），次数展示沿用同产品列表页「筛选标签 + 数量」的惯例。

AI 能力边界：不适用（纯筛选与计数，无 AI 参与）。

二、逻辑补齐摘要

2.1 主成功路径

  • 团队长（列表）：首页「拜访记录」模块 → 点「更多」→ 进入拜访记录二级列表页 → 切换周期/员工/类型筛选 → 列表与各类型次数同步刷新 → 点单条记录进入对应拜访/活动详情。
  • 团队长（页内直查）：首页「拜访记录」模块 → 点日历某一日期 → 模块下方列表直接展示该日期的拜访/活动记录（不跳页）→ 点单条记录进入详情。
  • 员工：首页「渠道拜访」模块「更多」→ 历史拜访记录页 → 切换周期与类型筛选 → 列表与各类型次数刷新 → 点记录进入详情。

2.2 关键分支

  • 团队长首页：点日历日期 → 不跳转，模块下方列表切换为该日期的记录；点单条记录 → 直接进拜访/活动详情；点「更多」→ 进二级列表页。
  • 团队长二级列表：切换周期（含考核月，选考核月后再选期次）→ 列表与「全部/拜访/活动」次数按新周期重算；切换员工筛选 → 同上；切换类型标签 → 仅收窄列表，不改各标签上的次数。
  • 员工端历史记录：切换周期 → 列表与次数重算；切换类型标签 → 仅收窄列表。
  • 类型标签次数口径：为「当前周期（叠加当前员工筛选）下该类型的记录条数」，与当前选中的类型标签无关（选中「拜访」时，「全部/活动」标签仍展示各自条数）。

2.3 状态与异常

  • 状态：正常；空态（当前周期 / 员工 / 类型组合下无记录 → 列表空态）；加载态（沿用各页现有列表加载态）。
  • 异常：列表加载失败沿用各页现有失败表现，本次不改。
  • 回退：从详情返回列表，保留进入时的周期 / 员工 / 类型筛选与滚动位置（沿用现有口径）。
  • 团队长首页：所选日期无记录 → 模块下方展示空态（沿用团队端「当日暂无团队拜访或活动记录」口径）。

2.4 跨页影响

  • 入口页：团队长首页「拜访记录」模块（新增「更多」入口、改记录点击行为、改日历点击行为）。
  • 结果页：团队长拜访记录二级列表页（删日历、加周期筛选、加次数）；员工端历史拜访记录页（标签加次数、「自然月」改周期筛选）。
  • 被动影响页：团队长 / 员工端拜访详情与活动详情页（作为跳转目标，内容不变）。

2.5 仍未决项

  • 无阻塞项。

3.3 各受影响页的功能变化（特性级，按页）

团队长端 · 首页「拜访记录」模块

  • 在拜访日历与下方记录列表之间、右对齐新增「更多」入口，点击进入拜访记录二级列表页。
  • 单条记录点击行为由「进二级列表页」改为「直接进对应拜访 / 活动详情页」。
  • 日历点击日期改为页内筛选：不再跳页，模块下方列表直接展示所选日期的记录；默认展示今天。

团队长端 · 拜访记录二级列表页

  • 删除页内日历展示，并移除原「X月X日记录」单日锚定标题。
  • 新增统一周期筛选器（昨日/本周/自然月/本年/考核月，考核月再选期次），列表改按所选周期检索、不再按单日锚定。
  • 保留员工筛选器。
  • 保留 全部/拜访/活动 类型标签，并在各标签上叠加显示「当前周期（叠加员工筛选）下该类型的记录条数」。
  • 记录列表按 员工 + 周期 + 类型 检索；点记录进详情。

员工端 · 历史拜访记录页

  • 类型标签 全部 / 拜访 / 活动 各叠加显示「当前周期下该类型的记录条数」。
  • 原「自然月」标签替换为统一周期筛选器（昨日/本周/自然月/本年/考核月）；按月份分组在所选周期范围内保留。

五、验收标准

  1. 主路径可完成：团队长首页点「更多」进二级列表、点单条记录进详情；员工端由「更多」进历史拜访记录并可筛选查看。
  2. 关键分支成立：团队长首页点日历日期仅刷新页内列表、不跳页；类型标签次数为当前周期 + 员工筛选下各类型条数，不随选中标签变化；切换周期 / 员工后次数与列表同步重算（逐条对应 2.2）。
  3. 状态与异常口径：无记录时展示空态；从详情返回保留筛选与滚动位置（逐条对应 2.3）。
  4. 口径一致：两端周期筛选均为含考核月的 5 项统一控件；两端类型标签的次数展示形态一致。
  5. 范围守界：第四节列出的页面 / 模块 / 字段未发生变化。

六、风险与依赖

  • 推翻既有决策：团队长二级列表与员工端历史拜访记录接入「含考核月的统一周期控件」，推翻 2026-11-05「历史拜访记录页不接入考核月」的旧口径（该旧口径出自《2026-11-04-考核月周期维度-spec.md》，已于 2026-11-09 在该 Spec 顶部追加修订说明并在 §2.4 / §3.2 第⑦项 / §四首条 / §五第 8 条逐条标注废除），需同步更新两份 PRD 的相关备注与 manifest 决策记录。
  • 首页日历点击行为变更：由「跳二级列表并锚定单日」改为「页内筛选」，属既有交互的行为反转，需在 PRD 明确写清，避免原型与文档不一致。
  • 次数口径依赖：各类型次数需「按周期 + 员工 + 类型」对既有记录集合计数，不新增数据字段；数据量大时需关注计数性能（正式实现层面，建议在 PRD 依赖说明中提示）。
