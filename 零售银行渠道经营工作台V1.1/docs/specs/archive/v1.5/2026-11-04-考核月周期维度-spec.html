考核月周期维度 — 需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-04 迭代版本号：零售员工工作台 v1.5 / 零售团队长看板 v0.4 流程设计要求：跳过（在同一既有控件上增加一个并列选项 + 一个选期弹层，不涉及页面流转、入口或分支决策的变化）

2026-11-05 修订（口径变更）：员工端「渠道星级详情」的周期由「与『我的渠道』共用同一状态、双向联动」改为独立周期状态 sdPeriod——进入时继承「我的渠道」当前周期（含所选考核期次），进入后页内独立切换、仅影响本页，返回「我的渠道」时其周期保持原状态（页内切换不回写）。同步更新：§2.4、§3.2、类别一 / 三 / 四 / 五 / 八、§3.3 员工端表格，以及《2026-11-02-渠道星级变化可视化-spec.md》。

2026-11-09 修订（口径变更，本条推翻本 Spec 原边界）：废除本 Spec 中「历史拜访记录页不接入考核月」的口径。自 2026-11-09 起，员工端「历史拜访记录」页与团队长端拜访记录（含拜访记录二级列表页）均接入含「考核月」的统一周期控件（昨日/本周/自然月/本年/考核月 + 考核期次），原「全部/拜访/活动/自然月」中的「自然月」标签被该统一周期筛选器取代。同步更新：§2.4、§3.2（第⑦项）、§四（首条）、§五（第 8 条）；另 §2.4 中「10 处控件 / 7 个周期状态变量」的计数亦随之增加（新增员工端「历史拜访记录」与团队长端「拜访记录二级列表」两处控件）。驱动文档：《2026-11-09-拜访记录列表与筛选改版-spec.md》。

一、需求背景

目标用户：员工端＝客户经理；团队长端＝团队长 / 网点负责人。

要解决的问题：现有「时间周期」仅提供 昨日 / 本周 / 自然月 / 本年 四个自然历口径。实际渠道经营考核以「考核月」为管理节奏——考核账期为 T-1 月 16 日 ~ T 月 15 日（含当日）。当前页面无法按考核账期查看经营结果，员工与团队长无法回答"本考核月进度如何""上一个考核月做得怎样"。

解决方式：在「时间周期」控件中并列新增「考核月」选项（与 昨日 / 本周 / 自然月 / 本年 同级）；点选「考核月」后弹出考核期次列表，可选近 6 期考核账期；页面全部指标按所选考核账期同轴刷新。

竞品差异 / 品类惯例：不适用（本产品为内部经营工作台，无对外竞品；"同一控件并列新增口径 + 选期弹层"为通用做法）。

AI 能力边界：不适用。

二、逻辑补齐摘要

2.1 主成功路径

任一含「时间周期」控件的页面 → 点开周期下拉（现有底部弹层，标题「选择时间范围」）→ 选择「考核月」→ 弹层内容切换为「选择考核期次」列表（近 6 期，默认高亮当期）→ 选定某一期 → 弹层关闭，控件回显「考核月」并在控件旁标注所选期次区间与状态（如 10/16–11/15 · 进行中）→ 页面全部受周期驱动的指标按该考核账期即时刷新。

2.2 关键分支

  • 期次默认：首次选「考核月」时默认高亮当期考核月（进行中）。
  • 期次列表内容：近 6 期（含当期）；当期在最上、往期依次向下；每行展示"日期区间 + 状态标记"。
  • 期次状态：当期＝蓝色「进行中」；往期＝灰色「已结束」。
  • 期次记忆：选定后再次打开列表，高亮上次所选期次；切走（改为 昨日/本周/自然月/本年）后再切回「考核月」，仍保留上次所选期次。
  • 周期互切：五个选项（昨日 / 本周 / 自然月 / 本年 / 考核月）在同一控件内并列互斥；选自然历口径时按原口径刷新，回到「考核月」恢复所选期次。
  • 二级页继承：从上游页进入二级页时（如「我的渠道」→「名下渠道排名」），若上游周期为「考核月」，二级页继承该周期与所选期次。
  • 共用状态：员工端首页「过程跟进」四格与「我的渠道」共用同一周期状态——「我的渠道」切到考核月时，四格同步刷新。

2.3 状态与异常

  • 状态：进行中（当期）／已结束（往期）；控件展开态／收起态；期次选中态（6 选 1）。
  • 空数据：某期某指标无数据 → 按各页既有口径显示 0 或占位符（不新增特殊空态）。
  • 回退：切回自然历周期（昨日/本周/自然月/本年），各页恢复对应口径数值；考核月的期次记忆保留、不丢失。

2.4 跨页影响

  • 主动影响：全部 10 处「时间周期」控件（清单见 §3.3），覆盖 7 个周期状态变量。（2026-11-09 修订：其后新增员工端「历史拜访记录」与团队长端「拜访记录二级列表」两处控件，当前控件总数大于此数）
  • 被动影响：员工端首页「过程跟进」四格（跟随「我的渠道」周期，无独立控件）。
  • 不涉及：网点 / 员工 / 星级 / 状态筛选；其余与周期无关的模块。（原「历史拜访记录页不接入考核月」一条已于 2026-11-09 修订废除——该页改为接入含「考核月」的统一周期控件，见本文首修订说明）

2.5 仍未决项

  • 无阻塞项。

上 4 期 06/16–07/15 已结束（灰）

控件回显规格

  • 控件内文案：考核月（与 昨日/本周/自然月/本年 同级显示）

  • 标注仅表达考核账期区间，不出现「数据截至 …」类数据切点文案，避免与账期口径混淆

趋势 / 变化标识

  • 各页既有趋势 / 变化标识（如星级变化、指标涨跌）随所选期次联动，取该期次对应的口径值

五、验收标准

  1. 并列选项成立：10 处周期控件下拉均为 5 项（昨日 / 本周 / 自然月 / 本年 / 考核月），互斥单选。

  6. 数据联动：切换期次 / 切换周期，页面受周期驱动的指标同轴刷新；员工端首页「过程跟进」四格跟随「我的渠道」同步刷新。

六、风险与依赖（可选）

  • 前置依赖（数据侧）：需各页指标支持按「考核账期」聚合（period = 考核月 + 期次）。当前演示为静态派生数据；研发阶段需明确后端按考核账期出数口径，以及"进行中账期"的数据切点（默认截至 T-1 日）。兜底：数据未到位时原型按演示数据派生。
  • 口径边界：本 Spec 明确"考核账期窗口（固定右端 M 月 15 日，含当日）"与"数据切点（进行中账期数据截至 T-1 日）"为两个概念，页面标注只呈现前者，不混用。
  • 推翻既有裁定（文档一致性）：本 Spec 取代此前（2026-11-04 早些时候）"在时间周期下增设 自然月/考核月/上个考核月 二级子切换"的方案，该方案已被完整回退（Spec 删除、原型还原、product-manifest.json 移除对应 decision）。本轮以"并列一级选项 + 期次列表"重新落地。
  • 风险（记忆态与共用状态）：员工端 3 处控件共用 period 状态，团队长端各为独立状态。共用状态下的期次记忆需保证跨页一致（同一状态变量天然一致）；独立状态间互不影响，符合预期。
