团队长端员工筛选搜索 — 需求规格（Spec）

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-09 迭代版本号：不升版本号（沿用 零售员工工作台 v1.5 / 零售团队长看板 v0.4，仅页级追加修订行） 流程设计要求：跳过（纯页内弹层交互增强，无入口 / 路径 / 分支变化，无需流程图）

一、需求背景

目标用户：团队长（与现有团队长端用户一致，不新增用户画像）。

要解决的问题：团队长端有 4 处「按员工筛选」入口（渠道星级详情页、过程跟进详情页、主页拜访记录日历、拜访记录日历详情二级页），其员工选择弹层目前是一张无搜索、无分组的固定长度平铺列表，只能逐条滚动查找。实际团队员工数量多时，滚动查找效率低、容易漏选。增加姓名搜索后，团队长可输入姓名关键字即时定位目标员工并选中。

竞品差异 / 品类惯例：不适用（本次为既有弹层加搜索框的局部增强，未做外部调研）。内部惯例对齐：同产品的「网点选择弹层」已实现"固定头部搜索框 + 列表内部滚动 + 空态兜底"的成熟模式，员工搜索沿用同一交互骨架。

AI 能力边界：不适用（纯字符串包含匹配，无 AI 参与）。

二、逻辑补齐摘要

2.1 主成功路径

团队长在 4 处页面点击「员工筛选」→ 弹出员工选择弹层 → 在搜索框输入姓名关键字 → 列表实时过滤出姓名包含关键字的员工 → 点击目标员工 → 筛选条件回填并关闭弹层 → 页面列表按该员工刷新。

2.2 关键分支

  • 未输入关键字 → 列表展示全部员工（= 现状口径）。
  • 输入关键字且有命中 → 列表仅展示姓名包含关键字的员工；「全部员工」常驻置顶、不参与过滤（与网点选择器「全部网点」置顶同理）。
  • 输入关键字无命中 → 列表区展示空态「没有找到匹配的员工」。
  • 清空关键字 → 立即恢复全量员工列表。
  • 点击某员工 / 「全部员工」 → 回填筛选条件、关闭弹层、刷新对应页面列表（沿用现状行为）。

2.3 状态与异常

  • 状态：正常（全量列表）／ 过滤态（按搜索词收窄）／ 空态（无匹配）。
  • 空态：无匹配时列表区展示「没有找到匹配的员工」，搜索框保留输入内容以便用户修改。
  • 异常：无（本地过滤，不涉及请求失败链路）。员工数据本身加载失败的口径沿用各页现有列表加载失败表现，本次不改。
  • 回退：点遮罩 / 关闭按钮关闭弹层，不清空已选员工；重新打开弹层时搜索词清空、列表回到全量，当前已选员工保持高亮选中态。

2.4 跨页影响

  • 主改页（4 处入口 → 3 个弹层）：
  • 团队长端「渠道星级详情页」与「拜访记录日历详情二级页」→ 共用 csEmp 员工弹层（一处改动两页生效）。
  • 团队长端「过程跟进详情页」→ pdEmp 员工弹层。
  • 团队长端「主页拜访记录」日历模块 → vrEmp 员工弹层。
  • 被动影响页：无。各页列表刷新、筛选联动、返回保留筛选与滚动位置等既有口径均不变。

2.5 仍未决项

  • 无阻塞项。

四、不在本次范围内（明确边界）

  • ❌ 不新增员工数据字段（姓名拼音 / 工号）；搜索仅按姓名做包含匹配。
  • ❌ 不做「最近选择」员工置顶（与网点选择器的"最近选择"不对齐）。
  • ❌ 不给员工列表项增加副信息（工号 / 所属网点）；列表项维持仅展示姓名。
  • ❌ 不改网点选择弹层（pdNet / 网点选择器）及其搜索、大类 chips、最近选择逻辑。
  • ❌ 不改员工端任何页面；./docs/prd/零售员工工作台_PRD_v1_5.md 不动（员工端无同类员工筛选场景）。
  • ❌ 不改各弹层的高度、头部标题、关闭按钮、选中态样式等既有结构，仅追加搜索区与过滤逻辑。
  • ❌ 不改各页列表刷新、筛选联动、返回保留筛选与滚动位置等既有口径。
  • ❌ 不做跨页「员工搜索词/最近选择」状态共享；各弹层搜索状态相互独立。
  • ❌ 埋点：本轮不新增、不修改任何埋点。

五、验收标准

  1. 主路径可完成：4 处入口的员工弹层均可输入姓名、列表即时过滤，并能选中目标员工回填、关闭弹层、刷新页面列表。
  2. 关键分支成立：未输入=全量；有命中=仅展示命中员工（「全部员工」常驻置顶）；无命中=空态；清空输入=立即恢复全量（逐条对应 2.2）。
  3. 状态与异常口径：无匹配时展示「没有找到匹配的员工」；重新打开弹层时搜索词已清空、列表回全量、已选员工仍高亮（逐条对应 2.3）。
  4. 口径一致：4 处入口的弹层行为、文案一致（其中渠道星级详情页与拜访记录日历详情二级页共用同一弹层，须同时生效）。
  5. 范围守界：第四节列出的文件、弹层与功能未发生变化。

六、风险与依赖（可选）

  • 前置依赖：无（姓名包含匹配不依赖任何新增数据字段）。
  • 数据量风险：团队员工数量很大时，若采用全量本地过滤，列表长度与客户端渲染需关注；正式实现可考虑服务端过滤 / 分页（本次原型不涉及，建议在 PRD 依赖说明中提示）。
  • 同名风险：仅按姓名匹配且列表项仅显示姓名，同名员工无法区分，存在选错可能；为已知限制、用户已确认接受（后续如需可再引入工号副信息）。
  • 一致性风险：csEmp 弹层被「渠道星级详情页」与「拜访记录日历详情二级页」共用，改动须同时覆盖两页，避免只改一处导致行为不一致。
