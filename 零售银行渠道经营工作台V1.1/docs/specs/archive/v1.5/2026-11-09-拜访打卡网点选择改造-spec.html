拜访打卡网点选择改造 — 需求规格（Spec）

修订说明（同版迭代）
- 2026-11-10：① 于打卡网点选择处回加手工输入能力；② 解除「打卡只能选择系统已录入网点」的限制，允许以纯自由文本落库（不恢复"名称比对系统网点"校验）。对应地，拜访表单 Q1「拜访对象」在未录入网点场景下改为空态说明 + 就地手输。
- 2026-11-11：取消打卡页的「底部弹层」形态，改为页内内联——原「选择拜访网点」触发器位置直接改为输入框；未输入时其下方直接按 GPS 距离升序列出「附近网点」（网点名 + 归属标签 + ≈xxm）；输入关键字后切换为「搜索结果」（全部已录入网点，本人名下优先，含归属标签与距离）；关键字未匹配到任何已录入网点时仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」。点选列表网点后区域收起为已选态（网点名 + 归属标签 + 清除）；点「立即打卡」时——列表已选网点直接生成凭证，未录入（手输未匹配）则弹出二次确认「确认拜访该网点？」。原打卡专用弹层变体、弹层内的手动输入输入态作废；「我的渠道」「需求跟进表」的网点选择弹层保持现状。

产品名称：零售银行渠道经营工作台 模式：迭代 (iterate) 平台类型：移动端 Web（企微 H5） 日期：2026-11-09（2026-11-10、2026-11-11 修订） 迭代版本号：不升版本号（沿用 零售员工工作台 v1.5 / 零售团队长看板 v0.4，仅页级追加修订行） 流程设计要求：跳过（同一页内地点选择控件的形态调整，不涉及页面流转、入口归属或分支决策的变化）

一、需求背景

目标用户：与现有用户一致。员工端＝客户经理（名下管辖一批网点）。

要解决的问题（2026-11-09 主体）：员工端「我要拜访」打卡页原用两个并列入口选打卡地点——上方「从我的渠道中选择网点」（搜索框为静态占位，实际只能点本人名下网点列表）、下方「手动输入地点」自由文本。而「手动输入地点」自 2026-11-05 起已被约束为「必须命中系统已录入网点」，本质上退化成一个隐式的全量网点检索框，与上方搜索框职能重叠、数据源却不同（上框仅本人名下、下框覆盖全部已录入网点）。员工必须先自判"这个网点是不是我名下的"，再决定用哪个入口，认知负担重且易走错路径。改造后：合并为单一「选择拜访网点」入口，在结果行标注归属，按 GPS 就近推荐，并让本人名下网点优先排序。

追加要解决的问题（2026-11-10）：单一入口且"仅可选系统已录入网点"在实操中形成硬约束——外勤常遇到系统尚未录入的拜访对象（他行新开网点、临时合作点位、支行下设未建档门店等），搜不到也选不了，导致无法打卡。故解除"仅已录入网点"限制：允许以纯自由文本作为打卡地点落库，不做是否命中系统网点的比对。因未录入网点无系统关键人档案，拜访表单 Q1「拜访对象」在该场景下同步提供空态 + 就地手输。

追加要解决的问题（2026-11-11）：11-09／11-10 的打卡地点选择被放进底部弹层——员工要点开弹层才能看见网点，弹层内还要再切"列表态／输入态"两层，操作层级偏深；且弹层内的输入态与页内搜索框语义割裂。故取消弹层、改为页内内联：触发器位置直接是输入框，下方直接铺开「附近网点」，输入即切「搜索结果」，选完即收起为已选态，并把"未录入网点"收敛为搜索结果为空时的自然兜底（不再需要单独的"手动输入"入口与输入态）。

竞品差异 / 品类惯例：不适用。本产品为内部经营工作台，无对外竞品；"内联搜索框 + 就近推荐 + 归属标识 + 无结果即按所输名称兜底"为打卡 / 签到类应用的通用做法，本次沿用。

AI 能力边界：不适用（本需求不涉及 AI 生成 / 判断 / 自动化）。

二、逻辑补齐摘要

2.1 主成功路径

  • 路径 A（列表点选 · 已录入网点）：打卡页 → 「选择拜访网点」区显示输入框，其下方直接是「附近网点」（GPS 距离升序）→（可输入关键字切为「搜索结果」）→ 点选任一网点行 → 区域收起为已选态（网点名 + 归属标签）→ 点「立即打卡」→ 直接生成打卡凭证、进入成功确认区。
  • 路径 B（未录入网点 · 2026-11-11）：打卡页 → 在输入框输入网点名称 → 下方无匹配结果、仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」→ 点「立即打卡」→ 弹出二次确认「确认拜访该网点？」（含所输名称）→ 点「确认打卡」→ 生成打卡凭证（地点＝所输名称）。

路径 B 与路径 A 共用同一条「立即打卡」的后续链路，不新增任何确认页或独立页面；差异仅在"是否弹二次确认"。

2.2 关键分支

  • 形态（2026-11-11 修订）：打卡页地点选择页内内联、不使用弹层；「我的渠道」「需求跟进表」的网点选择弹层保持现状（大类 chips、最近选择、搜索×大类交集）不受影响
  • 默认态：输入框为空 → 显示「附近网点」分组，按 GPS 距离升序取前 4，行内显示 ≈xxm；无距离数据时该分组不展示
  • 搜索态：输入关键字 → 显示「搜索结果」分组，命中全部已录入网点（不受归属限制，支持跨银行关键字模糊匹配）；行内带归属标签（有距离数据时一并显示距离）
  • 排序：搜索结果本人名下优先在前、非本人名下在后，同组内保持原顺序；附近网点单按距离升序、不掺入归属排序
  • 归属标签：网点属当前员工名下 → 蓝色「本人名下」；否则灰色「非本人名下」；未录入网点无归属关系 → 不展示归属标签
  • 未匹配兜底（2026-11-11 修订）：关键字未匹配到任何已录入网点时，结果区仅展示提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」，不展示任何网点行；所输文本即视为未录入网点（无需额外点选、无独立"手动输入"入口与输入态）
  • 已选态（2026-11-11）：点选任一结果行 → 该区域收起为「网点名 + 归属标签 + 清除」；点击已选区域可再次展开（回到输入框 + 附近网点）改选
  • 清除：已选态右侧「×」清除已选网点，区域回到输入框 + 附近网点
  • 打卡校验与确认（2026-11-11 修订）：
  • 列表已选网点：点「立即打卡」→ 直接生成凭证，不弹确认
  • 未录入（手输未匹配）：点「立即打卡」→ 弹出居中二次确认「确认拜访该网点？」（正文含所输名称、"确认打卡／取消"）；「取消」关闭弹窗、停留打卡页并保留输入
  • 两者皆无（未选且输入为空）：点「立即打卡」→ Toast「请先选择拜访网点」，不生成凭证
  • 拜访对象（Q1）联动（2026-11-10）：打卡网点为未录入网点时，拜访表单 Q1「拜访对象」无关键人档案 → 展示空态说明 + 自由文本输入（就地手输）；该输入非空即视为满足 Q1 必填，且不展示任何补录关键人入口。已录入网点保持「关键人多选」口径（2026-11-10 修订：已录入网点不论本人名下 / 非本人名下，一律不可在拜访表单内新增关键人，原「＋ 添加关键人」入口作废、改为「其他」按钮（自由文本写拜访对象、不入关键人档案）、无关键人走空态且模块不阻塞，详见《2026-11-05-拜访对象关联关键人》Spec 2026-11-10 / 2026-11-11 修订）

2.3 状态与异常

  • 区域状态（2026-11-11）：
  • 输入态：输入框 + （输入为空→「附近网点」／输入有匹配→「搜索结果」／输入无匹配→「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」提示）
  • 已选态：收起为「网点名 + 归属标签（未录入网点无） + 清除按钮」
  • 无附近网点：无 GPS 距离数据时不显示该分组
  • 异常：经纬度采集失败（权限拒绝 / 容器限制 / 超时 / 不支持）沿用现有失败态，不阻断网点选择与打卡
  • 回退：已在输入态改选但未点选 → 保持原选择不变；点选后收起 → 点已选区域可再展开改选；二次确认点「取消」→ 关闭弹窗、保留输入与页面状态；清除 → 回到未选态

2.4 跨页影响

  • 主影响页：员工端「我要拜访」打卡页（地点选择区）
  • 联动页：员工端拜访表单 Q1「拜访对象」（未录入网点场景走空态 + 自由文本手输；已录入网点无关键人场景同样走空态，见《2026-11-05-拜访对象关联关键人》Spec 2026-11-10 修订）
  • 共享组件：打卡页不再使用网点选择弹层；「我的渠道」「需求跟进表」的弹层行为与数据源不变
  • 网点主数据新增两个字段用途：GPS 距离（供附近网点排序展示）、员工归属标识（供归属标签与排序）
  • 未录入网点无 networkId 与归属关系：打卡记录仅以名称落库，不参与网点维度经营统计
  • 不受影响：打卡成功确认区、拜访表单其余 5 个模块、我的渠道、需求跟进表、团队长端全部模块

2.5 仍未决项

无阻塞项。非本人名下拜访是否需要留痕/统计、未录入网点的统计归集，见 §六 风险（本轮不作为范围）。

五、验收标准

  1. 形态正确（2026-11-11）：打卡页地点选择为页内内联、无底部弹层；「选择拜访网点」处即为输入框，其下方直接展示「附近网点」列表
  2. 附近网点：默认态按 GPS 距离升序展示前 4 个网点，行内显示 ≈xxm 与归属标签（本人名下蓝 / 非本人名下灰）
  3. 搜索与排序：输入关键字后标题切为「搜索结果」，命中全部已录入网点（含非本人名下）且本人名下网点排在前
  4. 未匹配兜底：输入任意未录入网点名称 → 结果区仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」、无网点行；点「立即打卡」→ 弹出二次确认「确认拜访该网点？」→ 点「确认打卡」成功生成凭证（地点＝所输名称）；点「取消」→ 关闭弹窗并停留打卡页（输入保留）；全程不出现任何"未录入 / 不可打卡"拦截
  5. 已选态与直接打卡：点选任一列表网点 → 区域收起为「网点名 + 归属标签 + 清除」；点「立即打卡」直接生成凭证、不弹确认；点「清除」→ 回到输入框 + 附近网点；点已选区域可再次展开改选
  6. 未选拦截：未选且输入为空点「立即打卡」→ Toast「请先选择拜访网点」
  7. 拜访对象联动：未录入网点进入拜访表单 Q1 → 展示空态说明 + 自由文本输入；输入非空通过必填、输入为空按"必填未完成"拦截；已录入网点 Q1 行为与 2026-11-05 口径一致（2026-11-10 / 11-11 修订：不展示「＋ 添加关键人」；有关键人时以「其他」按钮自由文本输入、无关键人时直接展示拜访对象输入框且为必填（为空则拦截提交并在该模块描红提示「必填未完成」，回归 v1.4 无条件必填口径））
  8. 范围守界：「我的渠道」「需求跟进表」弹层、团队长端全部模块、打卡成功确认区、其余表单模块与埋点均未发生变化

六、风险与依赖（可选）

  • 推翻既有裁定（文档一致性）：本 Spec（2026-11-09）曾推翻 PRD v1.5 §5.4 于 2026-11-05 的「保留『手动输入地点』自由文本输入」口径；2026-11-10 又回加手工输入并允许纯自由文本（不恢复名称比对校验）；2026-11-11 进一步把打卡地点选择从弹层改为页内内联，并作废 2026-11-09 的"打卡弹层变体"与 2026-11-10 的"弹层内手动输入入口 / 输入态"。相关口径已在本文档与 PRD、product-manifest.json 决策日志中同步。
  • 前置依赖（GPS 距离数据）：附近网点排序与 ≈xxm 展示依赖定位服务/网点主数据提供"当前坐标到网点"的距离。原型内为演示用静态距离值；正式落地需数仓/地图服务按实时坐标计算距离并返回排序。兜底口径：无距离数据时不展示「附近网点」分组（仍可输入关键字搜索）。
  • 前置依赖（归属标识数据）：本人名下判定依赖"员工 ↔ 网点"归属关系数据（与「名下渠道数」等既有员工维度指标同源），需保证归属口径一致。
  • 风险（归属优先与就近推荐的取舍）：附近网点按距离排序、搜索结果按归属优先，两者口径不同。若评审认为附近分组也应归属优先，需另议（当前维持"距离优先"）。
  • 风险（非名下拜访治理）：仍允许打卡非本人名下网点。是否需要在打卡记录上留痕"非名下拜访"、是否纳入团队长端查看与统计，本轮未定，作为后续独立需求登记。
  • 风险（未录入网点无 networkId · 2026-11-10）：未录入网点不在网点主数据内、无 networkId 与归属关系，打卡记录仅以名称落库。由此带来：① 归属标签不展示；② 拜访对象无关键人档案（走手输）；③ 该记录不参与"名下渠道 / 网点维度"经营统计。如后续需要归集统计或团队长端可见性，需单独立项（本轮不做）。
  • 风险（主数据治理 · 2026-11-10）：允许自由文本后，可能出现同网点多名（"建行建国路支行" / "建设银行建国路支行"）的脏数据。本轮不引入去重 / 归一化，亦不回写主数据；如需治理，作为后续独立需求。
