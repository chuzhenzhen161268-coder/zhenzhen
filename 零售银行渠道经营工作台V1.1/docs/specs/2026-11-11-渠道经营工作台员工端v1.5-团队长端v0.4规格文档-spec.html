一、需求背景

目标用户： - 员工端＝零售线客户经理（管辖一批网点，负责建码、拜访、需求挖掘与跟进）； - 团队长端＝零售线团队长（管辖团队覆盖的全部网点与员工，负责盘点、跟进与需求上报处理）。

本版不新增用户画像，与 v1.5 / v0.4 基线一致。

要解决的问题：本版是 v1.5 / v0.4 的口径收敛与体验补齐批次，解决四类问题： 1. 数据口径不可信：同一指标在不同页/不同维度取值不一致（过程跟进只随周期不随网点、星级看不到升降、需求状态在拜访记录与需求跟进两处各存一份互不相通）； 2. 筛选与定位低效：网点选择器无搜索/无大类/无最近选择、团队长端员工筛选器无搜索、拜访记录把「看记录」与「进二级列表」混在一起； 3. 信息表达不清：渠道长名称被省略号隐藏且无查看全称的出口、渠道行下的卡片信息过载或与行内重复、需求挖掘平铺 chip 表达不出需求性质； 4. 闭环缺失：拜访记录提交后不可修改、未录入网点无法打卡、需求详情无法连续阅读。

改造后用户能做的不一样的事：员工可在任一处看到同一份可信数据、在长列表里快速定位、就地修改错填的拜访记录、连续读完一批需求；团队长可在同一周期维度下盘点团队、按员工/网点维度穿透、识别正在掉星的渠道。

竞品差异 / 品类惯例：不适用。本次为既有产品内部口径收敛与增量改造，未触发外部调研；同类零售银行外拓/过程管理工具的主流做法（周期维度统一、列表→详情连续阅读、长名称 2 行 + 详情卡片出口）作为背景参照已体现在各条口径中。

AI 能力边界：不适用。本版全部口径为确定性规则与统计展示，不涉及 AI 生成、判断或自动化。

二、逻辑补齐摘要

2.1 主成功路径

员工端（一条主闭环）：首页看到本人周期内的过程跟进四格与渠道拜访记录 → 进「我的渠道」按银行大类/关键字定位网点并选中 → 查看该网点经营数据与星级变化 → 点经营结果卡进「名下渠道排名」看名下网点贡献 → 点网点行展开渠道详情卡片看建档信息 → 进「我要拜访」按 GPS 附近网点或搜索选定拜访网点（未录入网点亦可）完成打卡 → 填写拜访表单（拜访对象、银行需求挖掘三维度分类等）提交（或稍后补填）→ 在「历史拜访记录」按周期与类型筛选查看记录 → 打开记录详情，如需修正直接进编辑态保存覆盖 → 打开「需求跟进表」按网点与满足状态筛选 → 进需求详情连续浏览并用「上一条/下一条」翻页，改动需求状态后保存更新。

团队长端（一条主闭环）：首页「团队总览」按员工/网点维度看团队业务指标与排名 → 点某网点行展开渠道详情卡片看建档信息 → 进「星级渠道」按周期看各星级数量 → 点星级进「星级渠道详情页」按员工/周期/星级变化筛选定位掉星渠道 → 进「过程跟进」按员工/网点/周期看过程明细与需求管理 Tab → 进「拜访记录」点日历日期页内查看当日记录，或点「更多 ›」进拜访记录二级列表按周期/员工/类型盘点 → 打开记录详情只读查看 → 在「团队重点关注」处理上报需求（标记跟进/归档）→ 进「员工详情」看单员工全貌。

2.2 关键分支

A. 周期维度（本版全局统一） - 分支 A1：任一含周期控件的页面选「考核月」→ 追加弹层「选择考核期次」（近 6 期，含当期）→ 选中后控件回显「考核月」并在旁标注所选期次「区间 + 状态」。 - 分支 A2：从带周期的列表页进入其二级页 → 二级页继承上游当前周期（含考核月期次）；二级页内可独立切换周期；返回上游不回写、上游保持原状态。 - 分支 A3：切走再切回同一页 → 保留上次选中的考核月期次（记忆态）。

B. 网点维度与指标可用性 - 分支 B1：员工端「我的渠道」网点＝全部网点 → 经营数据卡 5 项（含「名下渠道数」）、四张结果卡可点击进「名下渠道排名」。 - 分支 B2：员工端选中具体网点 → 经营数据卡 4 项（隐藏「名下渠道数」）、四张结果卡不可点击、「名下渠道数」卡始终无入口；清回全部网点即恢复。 - 分支 B3：团队长端「团队总览」/「完整排名详情」维度＝按网点 → 「团队业务指标」区恒展示 5 项但「名下渠道数」卡整卡置灰不可选（不隐藏）；排名指标选择器退出「渠道数」，仅 4 个可选。 - 分支 B4：团队长端当前已选「渠道数」时切到「按网点」→ 排名指标一次性回落到默认「新增资产」，标题与列表按「新增资产 · 按网点」刷新，不给打断式提示；切回「按员工」不自动恢复「渠道数」。 - 分支 B5：员工端「渠道星级详情页」不提供网点筛选（展示该星级全部渠道，不受「我的渠道」所选网点影响）。

C. 网点选择器（两套形态） - 分支 C1：员工端「我的渠道」「需求跟进表」与团队长端「过程跟进 · 需求管理」三处 → 使用网点选择弹层：搜索框 + 银行大类 chips（默认铺 3 行、超出收进「更多 ∨」）+「最近选择」置顶区（本设备最近 5 个，无记录不展示）+ 列表（「全部网点」置顶）；搜索与大类取交集；交集为空给空态 +「清除大类，在全部大类中搜索」。 - 分支 C2：员工端打卡页 → 使用页内内联形态（不使用弹层）：输入框为空时下方直接铺「附近网点」（GPS 距离升序取前 4，行内 ≈xxm + 归属标签）；输入关键字切「搜索结果」（命中全部已录入网点、跨银行匹配、本人名下优先在前、非本人名下在后）；点选后区域收起为已选态；已录入网点点「立即打卡」直接生成凭证、不弹确认。 - 分支 C3：打卡页输入的名称未命中任何已录入网点 → 仅提示「未匹配到系统已录入网点，将按所输名称作为未录入网点打卡」、不展示网点行；点「立即打卡」弹二次确认「确认拜访该网点？」（正文含所输名称）→「确认打卡」生成凭证（地点＝所输名称）、「取消」关闭弹窗并保留输入。 - 分支 C4：打卡页未选网点且输入为空点「立即打卡」→ Toast「请先选择拜访网点」、不生成凭证。 - 分支 C5：打卡页清除已选（右侧「×」）→ 回到输入框 + 附近网点态；点击已选区域可再次展开改选。

D. 拜访对象（Q1） - 分支 D1：已录入网点（不论本人/非本人名下）且有关键人 → 展示该网点关键人（职位 + 姓名）多选，另附「其他」按钮；点「其他」展开文本框录入拜访对象自由文本（仅作本次拜访快照、不写入网点关键人档案），可与勾选项并存。 - 分支 D2：已录入网点但无关键人 → 展示空态提示（本人名下：「该网点暂无关键人，可前往『我的渠道』编辑建码信息补充」；非本人名下：「该网点暂无关键人」），直接展示拜访对象自由文本输入框，不展示「其他」按钮；该模块必填。 - 分支 D3：未录入网点（打卡手输未匹配）→ 同 D2 的空态 + 自由文本输入框，必填；不展示任何补录关键人入口。 - 分支 D4：三态下「拜访对象」标题后的提示文案统一为「（可拜访多个对象）」。 - 分支 D5：全场景均不提供「＋ 添加关键人」入口（原入口作废）；关键人增改删统一由「我的渠道 → 编辑建码信息」完成，且仅本人名下网点开放该入口。

E. 银行需求挖掘（Q2） - 分支 E1：控件默认空态，三大类分组块常驻平铺在外层（无全局「＋ 添加需求」按钮、无模块级全局「需求描述」框）；各组标题＝维度色圆点 + 大类名 + 「N 项」胶囊 + 「＋ 添加」按钮；未选时隐藏计数胶囊、按钮降级为灰色描边、组内显示「点击添加」。 - 分支 E2：点某大类 → 拉起半屏选择器，仅展示该大类选项（不提供跨大类 tab 切换）；支持类内搜索（匹配需求名称与分组名称）；勾选后即时在该项下方展开「描述（选填）」输入框；底部按钮「确定（已选 N 项）」，空选置灰。 - 分支 E3：手工补充 → 点「＋ 手工补充（无对应项时使用）」录入自定义项，自动挂靠当前大类、分组记「自定义」、打「自定义」标识；空输入 Toast「请输入需求名称」；同大类重名 Toast「该需求已选择」。 - 分支 E4：大类是分组容器不是互斥筛选，支持跨大类多选。 - 分支 E5：提交校验至少选 1 项（未选 → 卡片红描边 + Toast「请至少选择一项银行需求」）；需求描述选填、无校验。 - 分支 E6：修改态按快照回显（含自定义项与每条标签的独立描述）；存量记录保持原文本、不追溯改写，统计归入「未分类」桶。

F. 渠道名称与渠道详情卡片 - 分支 F1：列表行名称最多展示 2 行，≤2 行完整展示不出现省略号，>2 行在第 2 行末尾以省略号收尾且不再换行；名称与同排右侧元素（状态标签 / 星级变化图标 / 数值）顶部对齐；字号、行高、与下方副信息间距沿用现状（统一术语为「省略号隐藏」，不用「截断」）。 - 分支 F2：团队长端「团队总览 · 完整排名详情」仅「按网点」维度适用名称 2 行规则；「按员工」维度取员工姓名（短），保持现状。 - 分支 F3：渠道星级详情页（员工端 / 团队长端）的渠道行整行点击 → 展开/收起「渠道详情卡片」，卡片内容＝完整渠道名称 + 经营指标 4 项 + 过程指标 4 项（沿用 11-03 原口径，本版未改）。 - 分支 F4：员工端「名下渠道排名」与团队长端「团队总览 · 按网点」（首页 Top4 + 完整排名页）的渠道行整行点击 → 展开/收起「渠道详情卡片」，卡片内容＝完整渠道名称 + 渠道建档信息（①建码日期 · 已建码天数；②关键人列表（职位 + 姓名 + 生日）；③网点星级 + 星级变化），不再展示经营指标 4 项与过程指标 4 项；卡片全程只读、无「编辑建码信息」入口。 - 分支 F5：同一列表同时仅展开一行；再次点击该行收起；团队长端展开态下切换排名维度 → 卡片收起。 - 分支 F6：团队长端「团队总览 · 按员工」维度无卡片，整行点击进入员工详情（现状不变）。 - 分支 F7：卡片周期口径＝仅「星级变化」随页面当前时间周期刷新；建码日期 · 已建码天数与关键人列表为静态档案，不随周期变化。 - 分支 F8：关键人区默认每行两个（各占半宽），单个标签内容在半宽内放不下时标签内文字自然换行、完整展示、不截断不溢出；关键人展示条数不设上限。 - 分支 F9：网点无建档数据 → 卡片仍保留完整渠道名称，其余区域展示「暂无建档信息」；建码日期缺失时该行以「—」占位。

G. 星级变化 - 分支 G1：枚举统一为「升星 / 降星 / 无变化」，图标色固定为升星 ↑ 红、降星 ↓ 绿、无变化灰「—」；上期无评级（新网点）不显示图标。 - 分支 G2：星级变化筛选档位＝全部 / 升星 / 降星 / 无变化，默认「全部」；pills 数量显示当前变化筛选下的条数；无匹配时给带「清除筛选 / 看全部」入口的空态，与「该星级当期本就无渠道」空态文案区分。 - 分支 G3：变化图标只出现在两端详情页网点行与员工端「我的渠道」网点信息卡片；列表层星级条目行不加图标；图标不可点。 - 分支 G4：三处入口进入详情页时预置筛选：员工端「我的渠道」预置所点星级 + 星级变化「全部」+ 周期继承当前；团队长端「星级渠道」预置所点星级；团队长端「员工详情」预置该员工筛选。 - 分支 G5：数量为 0 的星级条目不可点。

H. 需求状态与需求跟进 - 分支 H1：状态枚举统一为 已满足 / 未满足 / 无法满足（原「无法解决」更名为「无法满足」）。 - 分支 H2：拜访记录与需求跟进为可选关联、非一一对应；存在关联时以 recordId 绑定、共享同一份状态与内容、双向同步；未关联的需求跟进不参与同步。本版落地范围限定为 1:1 映射，一条拜访记录关联多条需求的 1:N 场景不纳入本版。 - 分支 H3：写入规则为后写覆盖——两端都可写入，以最后一次保存为准直接覆盖，不做终态保护、不做冲突提示；不再沿用「仅在需求未满足时跟随、终态不覆盖」的旧规则。 - 分支 H4：内容类联动——改「需求挖掘」内容 / 紧急程度 / 解决方案 → 同步更新该记录已生成的对应需求内容与紧急程度展示（需求跟进列表与需求详情不再只读静态基线值）。 - 分支 H5：条目增删——新增需求项与新建口径一致；移除需求项时其对应需求一并失效（本版收敛，不再保留「已是终态不受影响」的例外）；需求状态取值中不再出现「已关闭 / 已失效」。 - 分支 H6：需求跟进仅由拜访记录中判定为「未满足」的需求项生成；「无法满足」按既有口径走上报链路，本版不额外生成需求跟进。

I. 拜访记录可修改性 - 分支 I1：所有「拜访」记录一律可修改，详情页导航栏右上恒展示「修改」入口；不再依据关联需求状态判定（不再读取关联需求状态），不再展示「关联需求已全部满足，不可修改」说明条，不再有只读态与超期说明条。 - 分支 I2：「活动」记录详情不提供「修改」入口，也不展示说明条，全程只读。 - 分支 I3：编辑态复用现有拜访表单，标题由「我要拜访」改为「修改拜访记录」，原记录字段全部预填；打卡凭证（打卡网点／地点、打卡时间）保持只读不可修改；底部操作按钮由「放弃 / 提交完整记录」替换为「取消 / 保存修改」。 - 分支 I4：保存后覆盖原记录，返回详情页展示更新后内容并仍展示「修改」入口；外部历史拜访记录列表对应行的摘要与状态标签被动刷新，未编辑过的记录保持基线数据不变。

J. 需求详情连续阅读 - 分支 J1：仅从对应筛选列表进入详情时展示「上一条 / 下一条」（内容区左下「上一条」、右下「下一条」）；非列表入口进入不展示——员工端首页「需求跟进区」摘要条、团队长端团队重点关注首页「上报需求」预览卡片。 - 分支 J2：浏览序列冻结——进入详情瞬间冻结当时的筛选结果与排序为本次浏览序列，本次浏览期间因操作产生的状态变化不影响该序列；返回列表后按最新筛选结果实时展示。 - 分支 J3：首末条边界——最后一条时「下一条」置灰、第一条时「上一条」置灰（保留按钮位置避免跳动），点击置灰按钮给 Toast（末条「已到最后一条」、首条「已是第一条」），页面不跳转。 - 分支 J4：员工端详情可编辑，点翻页时若存在未保存修改 → 弹二次确认，提供「保存并继续」与「放弃改动」；无改动直接翻页。 - 分支 J5：团队长端两处需求详情（过程跟进 · 需求管理 Tab、团队重点关注上报需求列表进入的详情）均为只读，点「下一条」无需二次确认。

2.3 状态与异常

五、验收标准

  1. 主路径可完成：员工端能从首页 → 我的渠道（定位并选中网点）→ 名下渠道排名 → 渠道详情卡片 → 打卡（含未录入网点）→ 拜访表单提交 → 历史拜访记录 → 拜访详情编辑保存 → 需求跟进 → 需求详情连续阅读完成整条闭环；团队长端能从团队总览 → 星级渠道 → 星级渠道详情 → 过程跟进 → 拜访记录 → 上报需求处理 → 员工详情完成整条闭环。
  2. 周期口径成立：所有含周期控件的页面均为 5 项并列；考核月可弹期次列表、回显区间与状态、记忆所选期次；二级页继承上游周期、页内独立切换、返回不回写（逐条对应 2.2 A1–A3）。
  3. 维度口径成立：「名下渠道数」在员工端具体网点态隐藏、在团队长端按网点维度置灰不可选但不隐藏；「渠道数」退出网点维度排名指标并一次性回落默认指标（逐条对应 2.2 B1–B4）。
  4. 网点选择口径成立：三处弹层具备搜索 + 大类 + 最近选择且交集为空有兜底；打卡页为页内内联、附近网点按距离升序、搜索结果本人名下优先、未匹配走未录入网点二次确认、未选拦截（逐条对应 2.2 C1–C5）。
  5. 拜访对象口径成立：有关键人多选 +「其他」、无关键人空态 + 自由文本必填、未录入网点同口径、三态标题均为「（可拜访多个对象）」、全场景无「＋ 添加关键人」（逐条对应 2.2 D1–D5）。
  6. 需求挖掘口径成立：三大类外层常驻、点类进半屏且无跨大类 tab、类内搜索、手工补充自动归类并打「自定义」、每标签独立选填描述、至少选 1 项、三色取自 §3.4（逐条对应 2.2 E1–E6）。
  7. 名称与卡片口径成立：6 处列表名称最多 2 行且与右侧元素顶部对齐；两套卡片的适用范围与内容正确，A 套保留经营 4 项 + 过程 4 项、B 套为建档信息且只读、仅星级变化随周期刷新、关键人每行两个；同时仅展开一行（逐条对应 2.2 F1–F9）。
  8. 星级变化口径成立：枚举「升星 / 降星 / 无变化」与三色一致；筛选档位与 pills 数量联动；三处入口预置筛选正确；无数据星级不可点（逐条对应 2.2 G1–G5）。
  9. 需求状态同步成立：三态枚举统一；以 recordId 绑定、后写覆盖、无终态保护；移除需求项时对应需求一并失效；未关联的需求跟进不参与同步（逐条对应 2.2 H1–H6）。
  10. 拜访记录修改成立：所有「拜访」记录展示「修改」入口且无说明条；编辑态字段预填、打卡凭证只读、按钮为「取消 / 保存修改」；保存后详情与外部列表同步刷新；「活动」记录不提供入口（逐条对应 2.2 I1–I4）。
  11. 连续阅读成立：翻页按钮仅在列表入口展示；浏览序列冻结；首末条置灰 + Toast；员工端未保存拦截弹「保存并继续 / 放弃改动」、团队长端只读不弹；「保存更新」停留当前页 + Toast「需求状态已更新」（逐条对应 2.2 J1–J5）。
  12. 状态与异常口径：空态、加载失败、校验失败、保存失败、取消与返回均按 2.3 表现，可通过对应回退方式恢复。
  13. 范围守界：第四节列出的文件、页面、模块、口径与埋点均未发生变化。
