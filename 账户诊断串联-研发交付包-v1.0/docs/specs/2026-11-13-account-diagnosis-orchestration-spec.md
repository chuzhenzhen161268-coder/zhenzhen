# 账户诊断串联 — 需求规格（Spec）

**产品名称**：账户诊断串联  
**模式**：新需求（greenfield）  
**平台类型**：Web 网页（GWork 入口及浏览器承接）  
**日期**：2026-11-13  
**迭代版本号**：v1.0  
**流程设计要求**：单版。覆盖从 GWork 触发到账户诊断结果页打开的完整流程及权限失败、依赖失败等异常。

## 一、需求背景

**目标用户**：已登录 GWork、需要为客户查看账户诊断结果的客户经理或投顾。

**要解决的问题**：员工需要通过账户诊断能力查看客户账户诊断结果，但资金账号属于客户敏感信息，不应通过 GWork 对话传递。串联流程需让员工在浏览器安全录入账号，并在获取诊断及打开结果页前完成必要的基础服务关系校验。

**竞品差异 / 品类惯例**：不适用。本需求为内部 GWork 到既有账户诊断能力的场景串联，不涉及面向外部用户的同类产品比较。

**AI 能力边界**：Skill 仅负责识别“账户诊断”请求并编排流程，不负责生成、解释或修改诊断结果；诊断结果由四部提供，十部直接调用。账号、权限校验结果和诊断结果不得由模型推断或补造。

## 二、逻辑补齐摘要

### 2.1 主成功路径

员工在 GWork 输入“账户诊断”，GWork 校验员工登录状态并触发账户诊断串联 Skill；浏览器复用理财产品投前服务清单的资金账号录入与基础服务关系校验页面，员工录入账号并通过校验后，十部直接调用四部获取账户诊断结果；员工回到 GWork 后打开浏览器，由四部再次校验员工与客户基础服务关系并授权展示诊断结果。

### 2.2 关键分支

- **未登录或登录失效**：GWork 不启动账户诊断流程，提示员工完成登录后重试。
- **基础服务关系不成立**：复用的投前服务清单页面按既有逻辑拒绝进入下一步，不获取诊断结果。
- **关系校验通过**：允许十部直接调用四部获取账户诊断结果，并向 GWork 返回后续打开诊断结果所需的流程状态。
- **结果页打开前关系校验不通过**：四部拒绝授权，账户诊断结果页不打开。
- **诊断服务或打开过程失败**：向员工反馈失败状态，允许按既有入口重新发起完整流程；不得绕过任一权限校验继续打开结果。

### 2.3 状态与异常

- 登录校验中、浏览器录入中、关系校验中、诊断获取中、等待打开结果、成功打开、无权限、诊断暂不可用、打开失败。
- 录入页取消或关闭时，结束当前流程并返回 GWork；重新发起时重新执行登录与权限校验。
- 首次关系校验失败或异常时，不调用四部获取诊断结果。
- 四部再次校验失败或异常时，不打开结果页。
- 诊断获取失败、结果打开失败时提示员工重新发起；不得展示未授权或其他客户的结果。

### 2.4 跨页影响

- **GWork**：新增“账户诊断”意图识别与串联 Skill 触发，承接浏览器打开动作及流程状态反馈。
- **理财产品投前服务清单资金账号录入与校验页面**：复用既有页面和基础服务关系校验逻辑，承接账户诊断场景的资金账号录入；原投前服务清单行为不在本次改变范围内。
- **账户诊断结果页**：由四部提供诊断结果，十部直接调用；结果页打开前由四部再次校验基础服务关系。本需求不定义结果页内容与呈现规则。

### 2.5 仍未决项

无阻塞性产品决策。接口契约、字段、凭证传递与有效期、调用协议、失败码及技术安全实现均交由技术评审确定，不作为本 Spec 的产品定义。

### 3.3 各受影响能力的功能变化

#### GWork 账户诊断入口与串联 Skill

- 新增对员工“账户诊断”输入的识别与串联 Skill 触发。
- 在登录有效时发起浏览器录入流程；登录无效时提示重新登录。
- 承接诊断流程状态并在结果可打开时触发浏览器打开，不接收资金账号或诊断结果内容。

#### 理财产品投前服务清单资金账号录入与校验页面

- 复用既有资金账号录入页面及员工与客户基础服务关系校验逻辑，供账户诊断流程使用。
- 关系校验通过后进入账户诊断获取流程；校验不通过时沿用既有拒绝规则并终止本次账户诊断。
- 不改变该页面在理财产品投前服务清单原有场景中的行为。

#### 账户诊断结果打开流程

- 由十部直接调用四部获取账户诊断结果。
- 打开结果页前由四部再次校验员工与客户的基础服务关系；校验未通过时拒绝打开。
- 本需求只定义结果获取与受控打开关系，不定义诊断结果内容、页面布局或技术字段。

## 四、不在本次范围内

- 不设计或改造理财产品投前服务清单既有资金账号录入页面，不改变其原场景行为；账户诊断仅复用该页面与既有校验逻辑。
- 不设计账户诊断结果页的指标、内容、分析规则、布局或交互。
- 不新增独立资金账号录入页面。
- 不在 GWork 对话、Skill 或其可见日志中传递资金账号、诊断结果链接或诊断内容。
- 不定义接口路径、请求/响应字段、凭证结构与有效期、传输协议、错误码、存储方式或技术架构，均交由技术评审确定。
- 不绕过首次基础服务关系校验或结果打开前四部的再次校验。

## 五、验收标准

1. 员工登录 GWork 后输入“账户诊断”，系统可触发账户诊断串联 Skill 并进入浏览器录入流程；未登录时不进入后续流程。
2. 资金账号录入实际复用理财产品投前服务清单既有页面，首次基础服务关系校验复用其既有逻辑。
3. 非基础服务关系员工无法进入诊断获取步骤；首次校验失败或异常时，十部不调用四部获取诊断结果。
4. 基础服务关系校验通过后，由十部直接调用四部获取账户诊断结果。
5. 打开账户诊断结果页前，四部再次校验员工与客户基础服务关系；校验不通过或异常时，结果页不打开。
6. 成功时员工可从 GWork 返回的打开动作进入浏览器账户诊断结果页；失败时得到明确状态并可重新发起完整流程。
7. 资金账号不经 GWork 对话或 Skill 传递；诊断结果内容与页面设计不属于本需求范围。

## 六、风险与依赖

- 依赖理财产品投前服务清单既有资金账号录入页面及基础服务关系校验能力可被账户诊断流程复用。
- 依赖十部具备直接调用四部获取账户诊断结果的业务链路。
- 依赖四部在账户诊断结果页打开前执行独立的基础服务关系再次校验。
- 具体接口、字段、凭证传递与安全机制由技术评审确认；若现有能力无法满足上述业务约束，需由技术评审提出实现方案，不由本 PRD 预设。
