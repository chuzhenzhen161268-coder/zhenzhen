投后理财账户服务报告 — 需求规格（Spec）

产品名称：投后理财账户服务报告 模式：新需求（greenfield） 平台类型：Web 网页 / GWork（WorkBuddy）串联内部服务清单 日期：2026-10-30 迭代版本号：v1.0 流程设计要求：单版；覆盖触发、圈客、客户画像、报告生成、话术生成、合规审查和服务清单展示的完整链路

一、需求背景

目标用户：负责名下客户经营的客户经理或投顾。

要解决的问题：周报、月报及诊断与优化报告生成后，员工缺少统一查看、理解和触达客户的服务入口。本场景将周期任务、WorkBuddy 查询、客户画像、报告 Skill、对应话术和服务清单连接成闭环。

竞品差异 / 品类惯例：不适用。本需求基于现有 GWork、内部数据服务和服务清单工作流，不引入外部产品形态。

AI 能力边界：大模型负责识别查询意图、解析圈客条件，并分别基于已完成的周报、月报、诊断与优化报告生成对应话术和进行合规审查。模型不得脱离对应报告编造客户收益、持仓或观点，不得将缺失数据当作事实，不得承诺收益或直接作出投资决策。

二、逻辑补齐摘要

2.1 主成功路径

周期任务或员工在 GWork 发起查询后，系统圈选客户并获取客户画像；报告不存在最新可用版本时，在 GWork 内现场调用开发三部对应报告 Skill，优先复用已有报告；每份成功报告各自触发对应话术生成与合规审查，最后一次性进入服务清单。

2.2 关键分支

  • 自动任务分支：每周推送名下客户周报；每月第一个交易日推送月报；每月第二个交易日推送诊断与优化报告。
  • 批量主动查询分支：员工先明确客户范围，批量查询使用自由圈客模式，根据资产、画像、排序和排除条件生成服务清单。
  • 单客主动查询分支：员工指定单个客户时，先进入内部安全中转页，校验资金账号和员工权限，生成不含敏感信息的一次性任务码，再由 WorkBuddy 获取授权客户信息。
  • 报告类型分支：员工未指定报告类型时默认生成周报、月报、诊断与优化报告三类；明确指定时只生成指定类型。
  • 报告读取/生成分支：有最新报告时优先读取；缺失时在 GWork 内现场调用开发三部报告 Skill 生成。
  • 部分失败分支：三类报告独立处理。单类报告失败不阻塞其他已完成报告及其对应话术进入服务清单；失败报告对应 Tab 保留异常状态或空状态。
  • 任务元数据分支：服务清单顶部展示本次生成来源和生成时间；来源为员工消息时展示动态消息名称，周期任务、批量查询、单客查询按实际来源标识展示。

2.3 状态与异常

  • 报告生成过程在 GWork 内执行，报告和话术完成后才进入服务清单，不展示中间生成态。
  • 单类报告生成失败：对应报告 Tab 展示异常状态、失败原因和重试能力；其他成功报告继续处理。
  • 周报、月报、诊断与优化报告各自生成一份对应话术；某类报告失败时不生成该类话术，不影响其他报告与话术。
  • 每份话术独立进行合规审核，审核失败时最多重新生成 3 次。
  • 某份话术 3 次仍未通过：客户仍进入服务清单，该报告对应话术展示“AI生成话术未通过合规审核，请自行编辑话术”；该话术未人工编辑前禁止一键复制、企微单聊和企微群发，其他已通过审核的话术及其触达能力不受影响。
  • 员工自行编辑任一未通过审核的话术后：该话术立即恢复复制和企微触达能力，无需再次合规审核。
  • 单客任务码无效、过期或无权限：中转页阻止传递并提示重新输入或联系权限管理员；敏感信息不得传给 WorkBuddy。
  • 无命中客户：展示圈客条件和无数据状态，不生成空客户详情。
  • 画像字段缺失：展示不可用标识，话术不得补造缺失信息。
  • 标准方案素材：作为当前客户维度的公共模块，位于客户概况之后、报告 Tab 之前，随详情区域滚动；不归属诊断与优化报告正文。外层仅展示小 C、大 C 两张方案卡片，点击后从右侧抽屉展示对应详情；小 C、大 C 各 5 档，五档名称统一为“低波动方案、中低波动方案、中波动方案、中高波动方案、高波动方案”。持有公募产品展示小 C 五档，持有私募产品展示大 C 五档，同时持有两类产品展示两组共 10 档。不按单个客户资产金额或画像再次筛选档位。
  • 标准方案素材在抽屉中按档位支持预览、下载和勾选“加入群发素材”，默认均不勾选；仅员工主动勾选的方案进入群发确认。素材不参与报告或话术生成，不因客户画像改写。方案选择按客户隔离保存，群发时随该客户自身的报告/话术发送，不得跨客户复用。
  • 报告预览为长图只读预览，预览层不提供企微发送或“发送给客户”操作；报告卡提供下载图片。
  • AI 话术支持在页面内直接编辑，失焦保存非空内容；人工编辑话术不标记“合规通过”。

2.4 跨页影响

  • GWork 负责主动查询、圈客编排、报告 Skill 调用、话术生成与合规编排。
  • 新增/完善内部安全任务码中转页，仅用于本场景单客查询。
  • 内部服务清单展示客户列表、客户画像、三类报告 Tab、各报告的异常/空状态及对应话术。
  • 复用报告预览/下载、客户视图和企微群发能力；本服务清单页面不提供报告卡或话术卡上的单客企微发送按钮。
  • 服务结果回写场景 ID、客户 ID、报告类型、报告状态、话术审核状态、触达方式和服务结果。

2.5 仍未决项

  • 无阻塞项。报告 Skill 的具体输入输出、报告版本判定和任务码接口由技术方案阶段确认，不改变本 Spec 的业务时序。

3.3 各受影响页的功能变化

./docs/prd/pages/02-客户投后理财账户服务报告.md

  • 支持周期任务、批量自由圈客和单客任务码查询结果进入同一服务清单。
  • 客户列表按整体持仓金额排序，支持搜索和企微群发。
  • 详情区展示风险等级、整体持仓金额、理财持仓金额、客户视图入口以及周报、月报、诊断与优化报告三个独立状态。
  • 三类报告支持成功、异常和空状态；成功报告支持预览/下载，异常报告支持重试。
  • 周报、月报、诊断与优化报告分别展示对应话术；每份话术仅使用其对应报告作为输入。合规失败三次后，该话术进入人工编辑态并仅限制该话术的复制和企微触达权限。
  • 顶部展示生成来源/生成时间；群发从左侧客户列表搜索框下方发起，确认时按客户逐份展示可发送报告长图、对应话术、不可发送原因及该客户已选方案素材。

./docs/prd/pages/03-客户服务任务码中转.md

  • 校验员工输入的客户资金账号和查看权限。
  • 校验通过后生成一次性、不含敏感信息、限定场景和有效期的任务码，并自动对接 WorkBuddy。
  • 校验失败、任务码生成失败或对接失败时提供明确错误状态和重试路径。

四、不在本次范围内

  • 不把两个理财场景做成页面互相跳转。
  • 任务码中转 V1.0 只用于投后理财账户服务报告，不用于理财投后异动服务报告。
  • 不把客户姓名、资金账号等敏感信息直接上传至 WorkBuddy。
  • 不新增报告内容编辑器、投资决策、自动调仓、产品推荐或收益承诺能力。
  • 不在 Spec 阶段定义报告 Skill、话术 Skill、合规 Skill 的接口字段、数据库结构和部署方式。

五、验收标准

  1. 员工可从周期任务、批量自由圈客或单客安全中转完成“触发 → 圈客 → 画像 → 报告 → 对应话术 → 合规 → 服务清单”闭环。
  2. 未指定报告类型时生成三类报告，指定类型时只生成指定类型。
  3. 有最新报告时可复用；缺失时在 GWork 内现场调用开发三部 Skill，报告完成前不进入服务清单。
  4. 三类报告独立处理，单类失败不阻塞其他已完成报告和对应话术；异常 Tab 可识别并支持重试。
  5. 一个客户按周报、月报、诊断与优化报告分别生成对应话术；每份话术只使用其对应的成功报告，不读取其他报告内容。
  6. 当前客户公共素材区中，公募客户展示小 C 五档标准方案，私募客户展示大 C 五档标准方案，同时持有两类产品展示两组；主页面只展示两张方案卡片，五档详情在右侧抽屉中查看。每档支持预览、下载和勾选加入群发素材，默认不勾选，且按客户隔离保存。
  7. 每份话术审核失败最多重生成 3 次；三次失败后客户仍展示，但仅该话术在人工编辑前不可复制和触达，人工编辑后立即恢复。
  8. 单客查询必须经过内部任务码中转，任务码不含客户敏感信息且无权限/过期时不能继续查询。
  9. 群发按客户、报告类型、话术审核状态和成功回执计算可发送内容；异常报告、待人工编辑话术、已触达报告不发送，确认操作固定在弹窗底部。
  10. 完整报告以长图只读预览；AI 话术可页内编辑并失焦保存，人工编辑后不展示“合规通过”标签。

六、风险与依赖

  • 依赖数仓提供员工客户关系、持仓和画像数据。
  • 依赖开发三部周报、月报、诊断与优化报告 Skill，支持读取最新报告和按需现场生成。
  • 依赖话术生成 Skill、统一合规审查 Skill 和企微触达能力。
  • 依赖内部任务码服务提供权限校验、一次性凭证、有效期和 WorkBuddy 安全对接。
